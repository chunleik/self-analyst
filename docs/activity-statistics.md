# 活动统计与凌晨四点分界

## 如何读时间轴

统计日以本地时间04:00开始，次日04:00结束，用开始日期标识。例如9月15日03:00看到的“今天”，
是9月14日04:00至当前时刻；“昨天”是9月13日04:00至9月14日04:00。
上午为统计日的04:00–12:00，后半天为12:00–次日04:00；Wiki小时仍按整点生成。
周和月按统计日日期判断，分别从周一和月首04:00开始；看板最近两周是滚动十四天，Wiki双周仍按两个ISO周组织。
遇到夏令时按本地日历分界和实际经过时长计数。

## 使用时长

窗口事件先与查询范围取交集，再扣除AFK区间。完全非活跃的窗口不会贡献应用耗时；
跨统计日的事件分段归属，每个区间只计一次，重叠AFK不重复扣除。

- 应用已知、标题未知：保留应用耗时，省略未知标题。
- 应用未知：单独展示“未识别应用活动”，不据此宣称主要使用了某个应用。
- AFK缺失、失败或部分覆盖：保留可用事实，标明未完全扣除非活跃时间的估计。
- 只有非活跃、没有事件、数据查询失败：分别展示对应状态。
- 活跃总量包含未识别活动；AFK总量来自请求范围内的非活跃区间，并不保证与窗口覆盖相加等于整个请求长度。

## 升级与历史摘要

升级会使旧统计口径的桌面快照失效，首次刷新使用新本地事实，后续继续复用兼容快照。
Wiki数据库迁移至schema 4，记录统计与日历版本；旧摘要保留，默认查询、父级摘要和语义检索隔离旧口径结果。
同一小时可以保留不同统计版本的摘要。永久原始事件不修改。

迁移既有Wiki数据库前，在同目录生成 `llm-wiki.db.before-statistics-v4.bak`。
迁移失败时事务回滚并关闭连接，Wiki降级，桌面仍可使用本地事实。备份是升级前数据，不能代表后续新生成的摘要。

启用既有Wiki历史补算时，近期周期优先发现，较早历史按后台批次逐步发现，并保存发现进度。
重算遵守现有LLM预算和重试设置；未配置模型或预算暂停时保留待处理状态。
关闭Wiki或关闭历史补算的设置仍被尊重；没有完成的新版本Wiki时，看板使用本地统计。

如需回退，先正常退出应用并另行备份当前派生数据库，再将升级前备份恢复为 `llm-wiki.db`，
使用与该数据格式匹配的程序。不要让旧程序打开新schema数据库，也不要修改永久原始事件。
