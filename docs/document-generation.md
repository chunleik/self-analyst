# 生成和保存文档

在“会话”中直接说明要整理的内容和文件格式，例如：

- “把今天的原始采集记录导出为 Excel，保留时间、时长和数据字段。”
- “根据本周活动整理一份 Word 工作报告，说明数据缺失情况。”
- “把这份分析制作成 PPT 工作汇报。”
- “给刚才的 PPT 增加一页总结，保留旧版本。”

生成的文件以卡片形式显示在对应助手回复下方，包含文件名、格式、大小和版本；生成中的文件会显示状态。桌面版点击“另存为”，在系统对话框中选择电脑上的其他目录；Web 版点击“下载”，由浏览器管理保存位置。保存失败或取消不会删除应用内成果，可以再次保存。

会话顶部的“全部会话文档”默认收起，展开后可浏览成果并继续加载较早文件。右侧上下文区不再单独放置文档列表。

## 支持的格式

| 格式 | 支持的内容 |
| --- | --- |
| CSV | 单张明细表，包含表头；使用 UTF-8 编码 |
| JSON | 保留值类型及嵌套数据；直接导出包含 metadata 和 records |
| Excel（XLSX） | 明细、多工作表及来源说明；长数字可按文字保存以避免精度丢失 |
| Word（DOCX） | 可编辑的标题、段落、列表和表格，长内容自动分页 |
| PDF | 固定排版的报告与表格，嵌入中文字体 |
| Markdown | 标题、段落、列表和表格，适合轻量笔记 |
| PPT（PPTX） | 16:9 演示文稿，包含可编辑标题、正文、分节和表格；长内容自动拆页 |

当前使用内置版式，不支持导入已有 Office 文件、自定义模板、宏、动画、外部图片或图表编辑器。格式无法完整表达内容时会提示调整，不会以成功状态交付静默截断的文件。

## 数据范围

直接导出由后端查询和写入，原始记录不会经模型逐条转写。需要指定明确时间范围；事件数据还需要指定事件桶。可选择字段和 Wiki 层级。

- **原始事件**：逐条已保存的采集记录，按接收时间 receivedAt 筛选，只在嵌入式事件服务模式可用。
- **事件投影**：经过 heartbeat 合并等处理的派生记录，按事件 timestamp 筛选。
- **文件元数据**：文件名、路径、大小及时间等，按 lastModified 筛选，不读取被监控文件正文。
- **Wiki**：与指定范围相交的摘要时间块，包含摘要状态；未完成摘要不会被当成已完成报告。

时间范围开始包含、结束不包含。来源、时间、时区、记录数与覆盖情况保存在成果元数据中；适合的格式也会附带说明。CSV 保持普通表头和数据行，其来源说明不插入数据行。缺少或损坏的原始分区会使导出失败，系统不会把不完整数据标为完整导出。

CSV 会对可能被电子表格当成公式的文字添加安全前缀；需要完全忠实的原始值时使用 JSON。Excel 将这类内容作为字符串处理。

## 版本与保存

同一轮请求因断线重试时，成功文件会被复用。明确修改内容或在新轮次重新生成会产生新成果；修改时可关联上一版本。用户已经另存到其他目录的副本不会随后续聊天被覆盖。

刷新或重启应用后可以继续保存已生成的文件。即使后续模型回答失败，已经成功生成的文件仍然保留。较早消息被裁剪后，其文件仍保存在会话文档列表；删除会话会清理应用管理的文档和生成源，但不会删除用户另存的副本。

只有受管桌面会话或已认证的 Web 版会话能够访问文档。不接受任意文件路径作为下载来源。另存为不能覆盖应用自身的数据或程序资源；选择已存在的普通目标文件时，系统会要求确认覆盖。

## 当前资源限制

生成源最多 1 MiB；直接导出最多 100,000 条记录，单份文件最多 50 MiB；Word/PDF 最多 200 个生成页，PPT 最多 100 页。应用管理的文档与临时数据共用 1 GiB 预算。单次生成最多 120 秒，并服从聊天取消或更早的超时。

时间范围遵循原始查询的配置上限，默认 31 天。Word/PDF 表格最多 10 列，PPT 表格最多 8 列；宽表可改用 Excel，或选择更少字段。达到限制时需要缩小范围或调整格式，不会自动删除旧文档。

文档生成随应用 JAR 与桌面运行时提供。生成过程不需要安装 Office、Python 或 Node；查看和编辑下载文件可使用用户选择的兼容软件。
