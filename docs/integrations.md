# 连接与工具

在设置中打开“连接与工具”。默认仍进入“模型设置”。新增功能仅允许带桌面认证的本机 UI 使用；旧的无 token 本机访问模式不能管理连接、凭据或批准操作。

## 配置与启用

连接配置保存在当前数据根的 `config/integrations.json`，格式版本为 1。`mcpServers`、`mailAccounts` 和工具批准记录采用独立 JSON，不向平面 TOML 塞入数组对象。普通 `config.toml` 保存不会覆盖它。

1. 添加连接或邮箱，保存公共元数据。默认禁用。
2. 外部 MCP 的 Bearer 默认仅本次进程有效，可显式选择系统库保存；邮箱授权码通过“加密保存并启用邮箱”确认操作存入系统安全存储。提交后输入框清空。
3. 点击测试或发现工具。测试不代表启用，也不自动批准工具；邮箱测试不读取正文。
4. 外部 MCP 对照远端工具描述和参数结构逐项批准，再显式启用；邮箱则在专用操作中核对读取范围、正文、模型目标及留存后确认。连接变更在下一轮聊天发布工具；撤权立即影响未执行的旧轮次调用。

保存本身不联网。运行启动和下一轮聊天为已启用连接安排异步发现，不等待全部远端服务器后才启动应用。离线、认证不足或发现失败的连接会显示状态，不阻断本地工具。修改无关设置不清空仍有效的目录。重启会重新建立已启用连接，但仅会话凭据需要重新输入。

保存使用 revision 乐观并发控制。冲突时先刷新，不能用迟到响应覆盖新编辑。写入使用同目录临时文件、强制刷新和原子替换；失败保留原配置。`.integrations.lock` 协调写入，`integrations.json.bak` 是前一版公共元数据，不含秘密。

## 删除连接与查看接口

选择连接后可点击“删除连接”。未保存的新连接只移除这一条内存草稿；已保存连接会先显示保存的名称、目标和影响，确认后按版本单独删除连接、关联工具批准并尝试清理本地凭据。其它连接及其未保存编辑保留，不需要为了删除空草稿先保存整页。取消不改变数据；版本冲突保留草稿。请求结果不明时暂时锁定写入，请确认放弃草稿并重新读取保存状态，不要连续重试。

“断开”仍只停用并清理凭据，保留条目；“删除连接”才移除条目。操作系统拒绝清理凭据时会显示待清理，不代表秘密已删除；必要时只处理能明确对应的 Windows 凭据管理器项目。删除不删除聊天或远端数据，不会在服务商处作废令牌。“放弃更改”丢弃整个连接页的未保存修改，不删除已保存连接。兼容联网搜索仍由高级配置管理，不能在这里删除。

MCP 的“查看 MCP 接口”打开只读弹窗，显示该连接已发现的 **tools** 名称、描述、输入参数 JSON Schema 和定义批准状态，并不枚举 MCP resources 或 prompts。打开不会联网；用户点击“发现工具/刷新工具列表”才通过现有发现接口读取目录。未保存元数据时先保存或放弃更改再发现；旧目标的目录不冒充新目标能力。尚未发现与已发现但无工具会分别说明，缓存目录不是远端实时保证。

查看、发现不自动批准、启用或执行工具。批准仍在连接设置中逐项进行，业务调用仍需单次确认。弹窗支持 Escape、关闭后焦点返回和窄屏滚动，第三方内容仅作为文本展示。

## 远端 MCP

第一期支持 Streamable HTTP，匿名或 Bearer。仅允许 HTTPS 公网目标，不接受 URL 内账号、查询参数、片段、内网、回环、链路本地、元数据地址或非全球单播地址。每次交换重新检查全部 DNS 地址并连接已检查的地址，TLS 按原始主机名验证，不跟随重定向，也不使用进程代理。

实现复用 MCP SDK 的初始化、工具发现和调用，使用受限 HTTPS transport。响应可以是 JSON 或有限 SSE 事件流；无限后台 GET 订阅、断线续传、旧 SSE、stdio、OAuth 和任意命令导入不在本期范围内。需要这些能力的服务器可能显示不兼容。初始化、每次请求、响应体、工具数量、结构大小均有上限；不确定是否执行的调用不会自动重试。

远端工具使用本地命名空间，不能覆盖原生工具。工具描述和参数 schema 的摘要变化后，原批准不再有效。即使远端标记为只读，每次调用仍需要聊天中的真实确认卡。确认绑定会话、轮次、目标、配置版本、工具定义和精确参数；拒绝、超时、关闭、参数变化或撤权后不会执行。来自邮件、网页或模型文字的“同意”不能代替确认卡。

旧 `websearch.*` 仍仅由 TOML/既有模型外设置负责；`legacy-websearch` 只是管理器中的保留入口，不复制旧 URL 或密钥。旧设置仍需按既有提示重启。它现在也需要工具批准和逐次确认，且不能连接明文或内网地址；不兼容值保留以便用户修正，不静默绕过限制。

## 凭据

外部 MCP 默认 `session` 只放在内存，用户显式选择持久保存时使用 Windows 当前用户的 Credential Manager。邮箱新凭据不再提供存储勾选项：在明确确认“加密保存并启用邮箱”后，强制使用该系统安全存储并回读核验；其它平台或系统库不可用时明确失败，不回退为仅会话或明文文件。目录发现可使用本次临时授权码，但不持久保存或启用；邮箱不提供旧会话凭据迁移。凭据绑定连接 ID 及精确目标；邮箱还绑定服务商与完整地址。改目标会清除旧引用和批准，不能把旧 Bearer 发给新服务器。

元数据保存、凭据替换和删除分开处理。替换先创建新引用，再提交配置，成功后删除旧项；提交失败尝试清理新项并保留旧项。退出清理会话凭据，持久凭据保留供下次使用。断开使本地连接不可用并尝试删除本地凭据；操作系统拒绝清理时会显示待清理提示，并在后续凭据操作或退出时重试。进程退出/崩溃后若保险库仍有孤立项，需要在 Windows 凭据管理器手工清理；不承诺系统拒绝删除时已擦除。远端授权码必须到服务商网站手工作废。

邮箱启用提交报错时，先核对持久配置，只有确认未提交才清理新凭据；若确认已提交则按真实成功结果返回。响应丢失、格式异常或无法核对时显示结果不确定并保留可能有效的凭据，不自动重试；使用“刷新状态”取得完整当前状态后再操作，关闭重开设置不跳过核对。保留可能有效的凭据不等于确认存在可删除的孤立项。

操作系统保险库不是同一登录用户下恶意进程的隔离边界。授权码可能具有比 SelfAnalyst 更大的权限，软件只读不表示服务商签发了只读授权码。日志不记录授权码、Bearer、邮箱正文或远端原始错误；MCP SDK 会输出原始内容的日志被关闭，仅显示本地分类状态。

## 邮箱与模型授权

内置邮箱连接器仅供 SelfAnalyst 进程使用，没有外部 MCP 端口或独立可执行文件。目前支持普通 QQ 与 163 的 IMAPS；详情见 [邮箱指南](mail-integration.md)。

新添加邮箱默认选择“全部文件夹”，覆盖服务商 IMAP 暴露的当前及以后新增的可读目录，包括嵌套目录。配置后自动加载目录，可搜索并勾选指定范围，支持嵌套完整路径及最多 256 个目录。该默认不启用账户、不授予正文读取或模型处理，也不触发后台同步。指定模式仍按完整目录名精确匹配，不将 `*` 或空列表视为全部。

邮箱表单移除了处理授权、后续轮次启用、系统库保存三个勾选项，保留正文选择、范围选择和“断开”。普通保存不能启用账户；显式启用操作展示账户、范围、正文、当前模型目标及聊天保留说明，取消不提交，配置版本或展示目标过期时失败。改动服务商、地址、范围或正文权限后会先停用并要求重新确认；单独改显示名不影响启用。已有匹配的持久凭据可复用，启用成功不等于连接测试成功。

首次让某个会话中的邮箱数据进入模型前，会显示模型接收目标及聊天保留说明。更换接收地址后必须重新确认，原来的目标授权不能替代新目标授权；同一目标的密钥轮换不产生新接收方。聊天、压缩、列表摘要和修复会话的模型路径都检查实际租约目标；HTTP 重定向不会把数据转交其它目标。

邮箱来源标记由服务端在结果暴露前持久保存，不能通过模型参数或前端会话编辑清除。该会话停止自动长期记忆提炼，禁止会把邮件衍生查询发给 embedding 的语义搜索；只允许明确列出的本地只读工具，设置/记忆写入必须单次确认，其它原生工具默认拒绝。

## 导入、备份与回退

`GET /desktop/integrations/export` 仅导出公共元数据。导入清除所有机器凭据引用、启用状态、工具批准和邮箱披露确认；不会启动子进程，未知传输/字段被拒绝。备份 JSON 不会备份保险库秘密。新机器恢复后，配置存在不代表已认证。

邮箱范围通过 `folderScope` 的 `all` / `selected` 明确表达，`allowedFolders` 仅在指定模式下决定精确白名单。邮箱必须有明确范围，缺少字段会报错而不猜测或迁移；非法配置不会被静默覆盖。新配置保存和导出会写出该字段，导入保留范围含义但不会继承启用和披露授权。旧版本的严格解析器不支持新字段，会拒绝读取；降级前保留备份，不应删除范围字段来模拟安全降级。

数据根准入在建立连接/凭据前检查格式。新增邮箱来源表使用独立版本标记，旧会话数据继续兼容；恢复后来源标记与目标授权随会话数据库保留。降级前保留完整停机备份，旧版本没有本期权限和来源保护，不能将降级视为安全兼容路径；不要手工删除标记或降低格式版本。

删除会话与断开账户不同：会话历史、AgentState 和来源记录按现有删除协调清理，备份、用户另存文件、远端邮箱及模型已收数据不会因此撤回。不存在“正文零落盘”保证。

## 验证范围

自动化使用合成凭据、MCP 响应、IMAP/TLS 服务器和 MIME 消息。Windows 凭据真实读写测试只在 Windows 执行；Linux 中明确跳过。无真实 QQ/163 登录验收。分发包、Windows 原生环境和必需 Windows CI 的实际结果应与本地 Java/Node 测试分开记录。
