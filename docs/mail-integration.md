# 内置邮箱连接

关联 OpenSpec change：`add-mcp-and-readonly-mail`、`default-all-mail-folders`、`add-mcp-tool-management`。
已发布的 beta.19 仅支持应用内只读；本文的本机 MCP、草稿和发信章节对应正在验证的开发变更，不代表已发版。

## 支持范围

邮箱默认在 SelfAnalyst 进程内按需读取，包括列出账户、列出已授权文件夹、搜索邮件和按引用读取单封邮件。
可独立选择向本机 MCP 客户端开放某个邮箱，以及允许该邮箱申请保存远端草稿或发信；这些新增能力均默认关闭。

- 普通 QQ 邮箱：完整的 `@qq.com` 地址，固定连接 `imap.qq.com:993`。
- 普通 163 邮箱：完整的 `@163.com` 地址，固定连接 `imap.163.com:993`。
- 本变更新增普通 126 和使用应用专用密码的个人 Gmail 固定预设；自动化使用合成数据，未经真实账户互操作验证。126 使用完整 `@126.com` 地址、网易客户端授权码和固定 `imap.126.com:993` / `smtp.126.com:465`。个人 Gmail 使用 `@gmail.com` 地址、Google 生成的 16 字符应用专用密码和固定 `imap.gmail.com:993` / `smtp.gmail.com:465`。无法创建应用专用密码的账户不适用，不能使用网页登录密码；Gmail OAuth 与 Google Workspace 自定义域不在此范围内。
- 读取和可选草稿使用 IMAPS 993；可选发信使用各服务商固定 SMTPS 465（QQ 为 `smtp.qq.com`，163 为 `smtp.163.com`）。均验证证书链和服务器名称，仅接受 TLS 1.2/1.3；证书失败不回退明文。
- 本次不支持 Microsoft Exchange Online/Outlook、自定义服务器或其它企业/VIP 邮箱，后续需要 OAuth 或单独的连接信任审查；也不支持 QQ 的其它域名别名、标记已读、移动、删除、附件发送/下载或后台全量同步。

例如 `synthetic@qq.com` 和 `synthetic@163.com` 仅为本文及测试使用的合成地址，不对应可用测试账户。自动化验收不使用真实邮箱或授权码。

## 获取授权码

1. 在服务商官方网页登录自己的邮箱，找到 POP3/IMAP/SMTP 或客户端服务设置。
2. QQ、163、126 按服务商要求开启 IMAP、完成验证并获取客户端授权码。个人 Gmail 在符合条件的 Google 账户中创建应用专用密码。不要填写网页登录密码。
3. 在顶部 **MCP** 页面（beta.19 为设置中的“连接与工具”）选择适用的服务商预设，填写完整邮箱地址，按需选择独立正文权限，先点击“保存更改”保存未启用的账户配置。文件夹范围固定全部，包含以后新增目录。
4. 输入授权码，点击“加密保存并启用邮箱”，核对弹出的邮箱、读取范围、正文许可、模型接收目标、系统加密保存及聊天留存说明后确认。取消不会提交授权码或启用请求。表单不再需要额外勾选处理授权、后续轮次启用或持久保存三个选项。
5. 授权码由 Windows 当前用户 Credential Manager 加密保护并保留至之后启动；应用会回读核验，不写入 TOML、连接 JSON 或普通导出。当前非 Windows 平台没有已实现的安全持久化后端，会明确报不可用，不偷偷改为仅会话或明文保存。
6. 配置页不自动加载文件夹。可主动执行“测试连接”核对服务商连接，测试不会读取正文。会话首次使用邮箱内容时仍需确认实际模型目标，目标改变后重新确认。

**软件的默认只读行为不等于授权码本身只读。** QQ/163 客户端授权码可能允许其它客户端执行更大的操作范围。SelfAnalyst 的限制来自程序的协议路径及逐次批准。请为本应用使用可独立作废的授权码；本地断开不能替代在服务商处作废授权码。

## 加密保存与断开

系统安全存储由 Windows 负责加密及访问保护，SelfAnalyst 不自制加密文件，也不把解密密钥与配置放在一起。它不能隔离同一登录用户下的恶意程序或管理员。新凭据写入及回读核验成功后，才提交新的引用和启用状态；确认尚未提交的失败会尝试删除新项并保留原有效状态，清理失败会提示待清理，不能把失败说成已经安全保存。

若配置替换可能已完成但后续操作报错，会先读取持久状态核对。已确认提交的凭据不会被误删；响应丢失、内容异常或无法确认结果时，界面保留原完整配置并显示“状态待确认”，不自动重试，也不声称账户一定未启用。请点击“刷新状态”核对后再操作，不能仅凭报错重新提交授权码。核对前暂停邮箱新增、编辑、启用与断开；刷新失败或返回不完整状态不会解除限制，关闭再打开设置也不会跳过核对。

已有匹配的系统库凭据可以在不再次输入授权码时确认启用。目录发现时输入的临时授权码只用于本次连接，不持久保存、不供 Agent 使用。邮箱统一采用明确范围和系统安全存储，不提供旧邮箱配置或会话凭据迁移；非法配置报错且保留原文件，不猜测更宽权限。外部 MCP 的会话凭据行为不变。

改动邮箱服务商、地址或正文许可并保存后，账户先停用，需重新确认启用；修改显示名等无关信息不改变既有启用状态。“断开”先停止后续访问，再尝试清理连接使用的本机凭据。它不删除聊天或远端邮件，不能撤回已发送给模型的数据。普通保存不会自动启用，也不会取消模型发送保护。

## 全部文件夹

邮箱设置固定读取全部 IMAP 可读文件夹，包含以后新增和嵌套目录。不需要输入 `*`，也没有范围、搜索、加载或勾选目录控件。打开、保存和启用设置不会自动列举目录。

“保存更改”仅保存连接元数据；“加密保存并启用邮箱”确认中明确披露动态全部范围、正文许可、模型目标和留存。正文默认关闭，仍须独立选择。新界面不迁移或转换旧指定范围配置，不支持的范围会明确报错，不会静默扩权。

全部范围不等于已读取全部邮件。Agent 仍按需列举、分批搜索和读取；不后台同步、不自动下载附件。服务商仍决定可见目录和历史邮件范围，现有数量、名称及请求预算不变，超限明确报错。断开账户停止后续读取，已发送内容和聊天记录不被撤回。

## 连接测试和网易邮箱身份声明

测试依次验证固定目标的 TLS、认证、协议能力、文件夹列举以及只读打开 INBOX。163 和新增的 126 预设在打开文件夹之前发送 IMAP ID，真实声明 `name=SelfAnalyst`、应用构建版本和 `vendor=SelfAnalyst`。开发类路径没有构建元数据时版本标为 `development`，不会冒充其他客户端或虚构支持邮箱。

缺少 ID 能力或出现 `Unsafe Login` 会报告服务商限制。请核对官方 IMAP 开通状态、客户端授权码和服务商限制，不通过更换伪造身份或关闭 TLS 校验绕过。

连接测试成功只代表本次最小流程成功，不证明所有历史邮件可见，也不自动授予正文、模型发送或工具权限。

## 搜索、覆盖范围与引用

每次调用重新核对账户启用状态、会话授权、文件夹和正文权限；返回结果前再次核对，防止等待期间撤权后继续提供结果。多个可用账户而请求未指定账户时，要求明确选择，不自动跨账户读取。

支持文件夹、时间、发件人、主题、未读条件。默认每页 20 条，最多 50 条。每次只搜索最多 500 个 UID 组成的窗口，并限制实际信封数和传输字节。单个文件夹超过 100,000 封邮件时返回预算限制，避免协议库为巨大序号缓存分配无界内存。结果只含有界主题、发件人、收件人、日期、未读状态、UID、Message-ID 与大小，不自动拉取正文生成预览。

- `coverage` 记录请求时间、实际检查邮件数、最低检查 UID 和是否截断。
- `providerVisibleRange=unknown` 表示不能判断服务商向 IMAP 客户端开放了多少历史邮件。
- 游标继续向更早的 UID 窗口搜索。UID 可能不连续，因此某页可以没有命中但仍有下一游标。
- 服务器不支持中文所需字符集时返回能力受限错误，不回退为下载整箱正文的本地搜索。
- 没有结果不证明旧邮件不存在。请在官方设置中核对客户端收取范围，SelfAnalyst 不自动修改该设置。

引用与游标为有界内存中的随机不透明标识，有效期 15 分钟，重启后失效。它们绑定账户、原始文件夹、UIDVALIDITY、UID/继续位置、查询条件、权限版本和会话。权限变化、邮件移动、UIDVALIDITY 改变、过期、换会话或修改查询后旧游标不会被解释为另一封邮件；需要重新搜索。Message-ID 仅作辅助显示，不承诺跨文件夹线程一致性。

## 正文和附件预算

正文仅按需读取，默认最多返回 20,000 个 Unicode code point。单次操作还分别限制：

- 解码文本总量：256,000 字节。
- 明文 IMAP 协议输入总量：2,000,000 字节，包含编码后 MIME 数据及服务器元数据；不含 TLS 封装开销。
- MIME part 数：64；嵌套深度：12。
- 总执行时间：30 秒；网络连接及单次读写另有有限超时。

先读取 MIME 元数据，优先选择纯文本。HTML 只做本地文本提取，移除脚本、样式和嵌入内容，不执行脚本、不请求远程图片或链接。附件（包括嵌入邮件和有文件名的 inline part）仅返回有界文件名、类型、大小和 inline 标记，不打开附件流，不解码附件。过大的文本 part 不下载；超出字符、解码体积、嵌套或 part 预算时明确返回 `truncated` 和限制原因，协议输入超限则安全失败。

邮件正文、标题、地址和附件名称都属于不可信数据，不能作为批准工具调用、改变模型目标、发送信息或修改设置的依据。

## 协议只读与取消

使用 Angus/Jakarta Mail 执行协议，不自行构造 IMAP 命令。所有文件夹以 `READ_ONLY` 打开，实际发出 `EXAMINE`；正文明确使用 `BODY.PEEK`。账户操作串行化，取消或截止时间到达时关闭本次 TLS 套接字。关闭文件夹使用强制断开，不执行 `CLOSE` 或 expunge，失败清理同样不写入邮箱。认证失败不自动重试。

合成协议夹具覆盖 LIST、ID、EXAMINE、UID FETCH、SEARCH、信封 FETCH、BODYSTRUCTURE 和 BODY.PEEK；测试断言无 STORE、APPEND、COPY、MOVE、EXPUNGE、SELECT、CLOSE 或 SMTP，且未读状态不变。连接测试单独断言没有 FETCH。

## 可选本机访问、草稿与发信

- **本机客户端访问。** 在 **MCP → 本机 MCP 客户端接入** 为已启用的邮箱单独开启共享。持有专用接入令牌的同机客户端是独立数据接收方，能读取已开放邮箱的允许数据；只有正文许可开启时才提供读取正文的工具。它不能读取未开放的其它邮箱，也不会通过该入口代理第三方 MCP。配置和令牌保护见[连接指南](integrations.md#向本机-mcp-客户端共享邮箱)。
- **保存远端草稿。** 为目标账户打开“允许申请保存草稿”，默认关闭。批准后通过原 IMAPS 登录，仅向服务商报告且在授权范围内唯一可用的 `\Drafts` 文件夹 APPEND 一封草稿；找不到或出现多个候选时拒绝，不猜目录名、不创建文件夹。草稿可能在其它客户端同步显示，此操作不发送邮件。
- **发送。** 先在服务商官方设置中确认已允许 SMTP，再在桌面 MCP 页为目标账户单独保存 SMTP 客户端授权码。即使服务商允许同一授权码，SelfAnalyst 也会把 SMTP 作为独立目的地存入 Windows 当前用户 Credential Manager，不自动复用 IMAP 或桌面/MCP 令牌。保存或更换 SMTP 授权码不会自动启用发信，需重新明确打开“允许申请发送邮件”。

只在 SelfAnalyst 使用草稿或发信，不需要打开本机客户端共享。应用内请求在聊天中审批，本机 MCP 客户端的请求在桌面 **MCP → 邮箱写操作请求** 审批。每次都必须核对发件账户、收件人、主题及完整纯文本正文，并在受管桌面明确批准。只支持 `To` 收件人（最多 10 个），发信至少 1 个；主题最多 200 个 Unicode 字符，正文最多 12,000 个 UTF-8 字节。不接受附件、富文本、CC/BCC、任意发件地址或自定义服务器。权限开关只允许申请，不是发送许可；拒绝、过期、配置变化或重复批准不会生成新的写请求。

**批准不等于操作成功。** SMTP 接受只代表服务端接收，不承诺最终送达，也不自动往已发送文件夹追加副本。执行后连接中断且结果未获确认时，先到服务商核对草稿或发送状态，避免重复操作；应用不会自动重试草稿或发信。

## 模型发送、保留和删除

邮箱结果发送到模型前，应用边界必须可靠记录该会话含邮箱来源并核对实际模型接收目标。普通回复、压缩和会话摘要等派生流程也需遵守接收目标授权。正文不是因为连接器“内置”或“只读”就只留在本机。

不建立邮件全文库，不自动将邮件放入 Wiki、本体、embedding 或长期记忆，不后台同步。邮箱来源会话停止自动长期记忆提炼；原生语义检索和写入受额外策略限制。

**不承诺正文零落盘。** 工具结果、引用、助手转述和压缩摘要可能随现有聊天和 AgentState 保存。外部 MCP 客户端也可能独立保留收到的信息；应用内的模型目标授权不约束该客户端。删除会话按现有删除协调清理会话及来源标记；断开账户不删除已保存聊天、远端草稿或邮件、用户另存文件或备份，也不能撤回已外发数据。

## 错误和验收边界

对外只返回分类错误，不显示服务器原始响应、授权码或 MIME 正文。常见分类包括认证所需/失败、服务商限制、TLS 失败、搜索能力受限、超时、取消、预算超限、权限拒绝、引用过期和游标失效。

自动化验证使用合成账户、协议服务器、MIME 内容和权限边界。它不能替代真实邮箱账户、真实 Windows 凭据库、分发包服务加载或客户端互操作验证。真实账户测试需要用户另行授权且不得提交凭据。

定向验证：

```sh
mvn -pl self-analyst-app -am '-Dtest=ReadOnlyMailServiceTest,MailBodyReaderTest,MailProtocolTest,MailTlsTest' '-Dsurefire.failIfNoSpecifiedTests=false' test
mvn -pl self-analyst-app -am '-Dtest=MailWriteServiceTest,MailWriteProtocolTest,McpMailManagementTest,McpServerEndpointTest' '-Dsurefire.failIfNoSpecifiedTests=false' test
```
