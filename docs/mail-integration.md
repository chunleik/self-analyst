# QQ 与 163 只读邮箱

关联 OpenSpec change：`add-mcp-and-readonly-mail`、`default-all-mail-folders`。

## 支持范围

内置邮箱连接器在 SelfAnalyst 进程内运行，只提供列出账户、列出已授权文件夹、搜索邮件、按引用读取单封邮件四类操作。它不是对外开放的 MCP 服务，不新增邮箱监听端口。

- 普通 QQ 邮箱：完整的 `@qq.com` 地址，固定连接 `imap.qq.com:993`。
- 普通 163 邮箱：完整的 `@163.com` 地址，固定连接 `imap.163.com:993`。
- 只使用 IMAPS，验证证书链和服务器名称，仅接受 TLS 1.2/1.3。证书失败不回退明文，不提供忽略证书选项。
- 不支持自定义服务器、企业/VIP 邮箱、QQ 的其他域名别名、Gmail/Outlook OAuth、SMTP、发送、草稿、标记已读、移动、删除、附件下载或后台全量同步。

例如 `synthetic@qq.com` 和 `synthetic@163.com` 仅为本文及测试使用的合成地址，不对应可用测试账户。自动化验收不使用真实邮箱或授权码。

## 获取授权码

1. 在服务商官方网页登录自己的邮箱，找到 POP3/IMAP/SMTP 或客户端服务设置。
2. 开启 IMAP，并按服务商要求完成验证，为 SelfAnalyst 获取客户端授权码。不要填写网页登录密码。
3. 在“连接与工具”中选择 QQ 或 163，填写完整邮箱地址，选择文件夹及独立正文权限，先点击“保存更改”保存未启用的账户配置。新账户默认全部文件夹；旧账户保留原来的指定范围。
4. 输入授权码，点击“加密保存并启用邮箱”，核对弹出的邮箱、读取范围、正文许可、模型接收目标、系统加密保存及聊天留存说明后确认。取消不会提交授权码或启用请求。表单不再需要额外勾选处理授权、后续轮次启用或持久保存三个选项。
5. 授权码由 Windows 当前用户 Credential Manager 加密保护并保留至之后启动；应用会回读核验，不写入 TOML、连接 JSON 或普通导出。当前非 Windows 平台没有已实现的安全持久化后端，会明确报不可用，不偷偷改为仅会话或明文保存。
6. 保存并启用不等于已与服务商连通。可再点击“测试连接”；测试不改变账户授权，也不读取正文。会话首次使用邮箱内容时仍需确认实际模型目标，目标改变后重新确认。

**软件只读不等于授权码只读。** QQ/163 客户端授权码可能允许其他客户端执行更大的操作范围。SelfAnalyst 的只读限制来自程序的协议路径，不是服务商签发了天然只读令牌。请为本应用使用可独立作废的授权码；本地断开不能替代在服务商处作废授权码。

## 加密保存、兼容与断开

系统安全存储由 Windows 负责加密及访问保护，SelfAnalyst 不自制加密文件，也不把解密密钥与配置放在一起。它不能隔离同一登录用户下的恶意程序或管理员。新凭据写入及回读核验成功后，才提交新的引用和启用状态；确认尚未提交的失败会尝试删除新项并保留原有效状态，清理失败会提示待清理，不能把失败说成已经安全保存。

若配置替换可能已完成但后续操作报错，会先读取持久状态核对。已确认提交的凭据不会被误删；响应丢失、内容异常或无法确认结果时，界面保留原完整配置并显示“状态待确认”，不自动重试，也不声称账户一定未启用。请点击“刷新状态”核对后再操作，不能仅凭报错重新提交授权码。核对前暂停邮箱新增、编辑、启用与断开；刷新失败或返回不完整状态不会解除限制，关闭再打开设置也不会跳过核对。

已有匹配的系统库凭据可以在不再次输入授权码时确认启用。旧的 `session` 账户仍可读取原配置，但不会被自动迁移或标为已加密持久保存；要使用新流程需重新输入授权码。仅会话凭据在重启后仍失效。

改动邮箱服务商、地址、文件夹范围或正文许可并保存后，账户先停用，需重新确认启用；修改显示名等无关信息不改变既有启用状态。“断开”仍可使用：先停止后续读取，再尝试清理本机凭据。它不删除聊天或远端邮件，不能撤回已发送给模型的数据。普通“保存更改”不会自动启用，界面移除三个选项也不会取消模型发送保护。

## 文件夹范围

“连接与工具”的邮箱表单提供两种范围：

- **全部文件夹**：允许读取该账户通过 IMAP 暴露的当前以及以后新增的可读文件夹，包括嵌套目录。不需要手工把目录名列全，也不需要输入 `*`。
- **指定文件夹**：逐行填写完整的 IMAP 文件夹名，仍限 1–32 个且精确匹配。`INBOX` 表示收件箱，不是时间或未读筛选；`*`、`ALL` 都不是全部目录开关。不同服务商的目录名称及层级分隔符可能不同，不要把界面中文名称当成实际 IMAP 名称。

全部模式下指定目录输入框不可编辑，但保留原内容，切回指定时可继续使用。“保存更改”成功后新范围作为未启用配置保存，完成明确启用确认后才允许新范围读取。未保存时放弃或关闭不会扩大权限；从旧配置升级或导入旧备份，也不会静默把原白名单改成全部。

全部范围不等于已经读取所有邮件。Agent 仍需按需列举目录、对单个目录分批搜索并按引用读取正文，不自动跨账户读取或后台全量同步。文件夹列举不再受指定列表的 32 个限制，但一次 IMAP LIST 最多允许 256 项，名称最多 256 字符，另受协议输入及时间预算限制；超限会明确报错，不悄悄返回前 32 个并声称完整。目录是否向客户端开放、全部历史是否可见由服务商决定。

**文件夹范围、正文权限和模型发送授权彼此独立。** 新账户虽然默认选择全部文件夹，仍默认未启用、未允许正文、未确认处理披露。要让 Agent 读取正文，需选择正文、保存元数据后通过明确按钮核对处理/保留说明并确认启用；会话首次使用邮箱数据时仍确认实际模型接收目标，换目标后重新确认。邮件结果及派生摘要可能留在聊天中。

将全部改为指定或关闭账户后，后续检查不再允许范围外读取，旧权限版本生成的引用和游标失效；已保存的聊天以及模型已经接收的数据不会被撤回。

## 连接测试和 163 身份声明

测试依次验证固定目标的 TLS、认证、协议能力、文件夹列举以及只读打开 INBOX。163 在打开文件夹之前发送 IMAP ID，真实声明 `name=SelfAnalyst`、应用构建版本和 `vendor=SelfAnalyst`。开发类路径没有构建元数据时版本标为 `development`，不会冒充其他客户端或虚构支持邮箱。

缺少 ID 能力或出现 `Unsafe Login` 会报告服务商限制。请核对官方 IMAP 开通状态、客户端授权码和服务商限制，不通过更换伪造身份或关闭 TLS 校验绕过。

连接测试成功只代表本次最小流程成功，不证明所有历史邮件可见，也不自动授予正文、模型发送或工具权限。

## 搜索、覆盖范围与引用

每次调用重新核对账户启用状态、会话授权、文件夹和正文权限；返回结果前再次核对，防止等待期间撤权后继续提供结果。多个可用账户而请求未指定账户时，要求明确选择，不自动跨账户读取。

支持文件夹、时间、发件人、主题、未读条件。默认每页 20 条，最多 50 条。每次只搜索最多 500 个 UID 组成的窗口，并限制实际信封数和传输字节。单个文件夹超过 100,000 封邮件时返回预算限制，避免协议库为巨大序号缓存分配无界内存。结果只含有界主题、发件人、收件人、日期、未读状态、UID、Message-ID 与大小，不自动拉取正文生成预览。

- `coverage` 记录请求时间、实际检查邮件数、最低检查 UID 和是否截断。
- `providerVisibleRange=unknown` 表示不能判断服务商向 IMAP 客户端开放了多少历史邮件。
- 游标继续向更早的 UID 窗口搜索。UID 可能不连续，因此某页可以没有命中但仍有下一游标。
- 服务器不支持中文所需字符集时返回能力受限错误，不回退为下载整箱正文的本地搜索。
- 没有结果不证明旧邮件不存在。请在官方设置中核对客户端收取范围，SelfAnalyst 不自动修改该设置。

引用与游标为有界内存中的随机不透明标识，有效期 15 分钟，重启后失效。它们绑定账户、原始文件夹、UIDVALIDITY、UID/继续位置、查询条件、权限版本和会话。权限变化、邮件移动、UIDVALIDITY 改变、过期、换会话或修改查询后旧游标不会被解释为另一封邮件；需要重新搜索。Message-ID 仅作辅助显示，不承诺跨文件夹线程一致性。

## 正文和附件预算

正文仅按需读取，默认最多返回 20,000 个 Unicode code point。单次操作还分别限制：

- 解码文本总量：256,000 字节。
- 明文 IMAP 协议输入总量：2,000,000 字节，包含编码后 MIME 数据及服务器元数据；不含 TLS 封装开销。
- MIME part 数：64；嵌套深度：12。
- 总执行时间：30 秒；网络连接及单次读写另有有限超时。

先读取 MIME 元数据，优先选择纯文本。HTML 只做本地文本提取，移除脚本、样式和嵌入内容，不执行脚本、不请求远程图片或链接。附件（包括嵌入邮件和有文件名的 inline part）仅返回有界文件名、类型、大小和 inline 标记，不打开附件流，不解码附件。过大的文本 part 不下载；超出字符、解码体积、嵌套或 part 预算时明确返回 `truncated` 和限制原因，协议输入超限则安全失败。

邮件正文、标题、地址和附件名称都属于不可信数据，不能作为批准工具调用、改变模型目标、发送信息或修改设置的依据。

## 协议只读与取消

使用 Angus/Jakarta Mail 执行协议，不自行构造 IMAP 命令。所有文件夹以 `READ_ONLY` 打开，实际发出 `EXAMINE`；正文明确使用 `BODY.PEEK`。账户操作串行化，取消或截止时间到达时关闭本次 TLS 套接字。关闭文件夹使用强制断开，不执行 `CLOSE` 或 expunge，失败清理同样不写入邮箱。认证失败不自动重试。

合成协议夹具覆盖 LIST、ID、EXAMINE、UID FETCH、SEARCH、信封 FETCH、BODYSTRUCTURE 和 BODY.PEEK；测试断言无 STORE、APPEND、COPY、MOVE、EXPUNGE、SELECT、CLOSE 或 SMTP，且未读状态不变。连接测试单独断言没有 FETCH。

## 模型发送、保留和删除

邮箱结果发送到模型前，应用边界必须可靠记录该会话含邮箱来源并核对实际模型接收目标。普通回复、压缩和会话摘要等派生流程也需遵守接收目标授权。正文不是因为连接器“内置”或“只读”就只留在本机。

不建立邮件全文库，不自动将邮件放入 Wiki、本体、embedding 或长期记忆，不后台同步。邮箱来源会话停止自动长期记忆提炼；原生语义检索和写入受额外策略限制。

**不承诺正文零落盘。** 工具结果、引用、助手转述和压缩摘要可能随现有聊天和 AgentState 保存。删除会话按现有删除协调清理会话及来源标记；断开账户只停止后续读取并清理本地凭据，不删除已保存聊天、远端邮件、用户另存文件或备份，也不能撤回已经发送给模型的数据。

## 错误和验收边界

对外只返回分类错误，不显示服务器原始响应、授权码或 MIME 正文。常见分类包括认证所需/失败、服务商限制、TLS 失败、搜索能力受限、超时、取消、预算超限、权限拒绝、引用过期和游标失效。

自动化验证使用合成账户、协议服务器、MIME 内容和权限边界。它能验证客户端协议契约，不能替代真实 QQ/163 账户、真实 Windows 凭据库或分发包服务加载验证。真实账户测试需要用户另行授权且不得提交凭据。

定向验证：

```sh
mvn -pl self-analyst-app -am '-Dtest=ReadOnlyMailServiceTest,MailBodyReaderTest,MailProtocolTest,MailTlsTest' '-Dsurefire.failIfNoSpecifiedTests=false' test
```
