# SelfAnalyst v0.3.0

本版本将嵌入式事件存储切换为合并活动区间模式，显著降低长期磁盘占用；包含不兼容的存储行为变更。

## 更新内容

- 嵌入式事件服务采用合并事件存储：连续相同状态的心跳延长同一活动区间，不再保存永久逐心跳副本。固定样本验证中新库约为旧基线的 16.8%，实际缩小比例随使用模式不同（见 [合并存储验证记录](../benchmarks/merged-event-storage.md)）。
- 事件库成为权威数据，需要定期备份；普通事件查询、统计、Wiki 和合并事件导出继续可用。
- 设置页显示合并存储模式、活动库与迁移备份占用、增长速度和数据库健康；迁移备份需显式确认后才清理。
- 旧原始查询、导出与重建接口退役：原 HTTP 接口返回 `410` 与稳定能力退役错误码；`events.raw.*` 配置退役（`events.raw.dir` 仅用于定位迁移输入），新增 `events.export.maxRangeDays` 和 `events.storage.lowDisk.warnBytes`/`blockBytes`。
- 修复 Maven Shade 中间产物（`*-shaded.jar`）干扰可执行 JAR 解析的问题，保障打包流程稳定。

## 从 v0.2.8 升级

**本版本包含不兼容的存储格式变更，升级前请备份数据目录。**

1. 正常退出旧版 SelfAnalyst，并备份现有配置和数据，再安装或解压 v0.3.0；新旧版本不要同时使用同一数据目录。
2. 首次启动时自动暂停采集，在独占锁下将现行双层数据迁移到紧凑事件库，校验通过后切换；迁移中断可安全恢复，失败时保持原数据并明确报告，不会用空库冒充迁移成功。
3. 迁移成功后整个数据目录可能暂时比升级前更大；在设置中显式确认“清理迁移备份”后才释放旧文件，同时失去逐心跳历史和旧格式回退能力。
4. 新库开始接收数据后不要直接降级运行：旧版本只接受旧格式数据根，也不应将旧 `events.db` 覆盖回新数据根。如需回退，先备份新数据，再按 [存储与恢复说明](../runtime-storage.md) 操作。
5. 外部 ActivityWatch 模式不迁移外部服务数据，保持现有连接行为。
