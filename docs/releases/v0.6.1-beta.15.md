# SelfAnalyst v0.6.1-beta.15

本次计划接续 [v0.6.1-beta.14](https://github.com/chunleik/self-analyst/releases/tag/v0.6.1-beta.14)，新增“连接与工具”、受控远端 MCP 和内置 QQ/163 只读邮箱。继续使用 Pre-release、非 latest 通道，不替代 [v0.6.0 稳定版](https://github.com/chunleik/self-analyst/releases/tag/v0.6.0)；应用内“检查更新”仍只查询稳定版。

这份文件记录版本准备时的范围。[功能 PR #151](https://github.com/chunleik/self-analyst/pull/151) 已正常合并，版本 PR、发布 tag 与远端便携/安装包验收仍是后续门禁；发布页在完成后补充实际结果。

## 更新内容

- **连接与工具设置**：新增带桌面认证的本机管理入口，分别管理远端 MCP 和内置邮箱。添加与保存、凭据设置、测试或发现、工具批准、启用是独立步骤；默认禁用，保存本身不联网，测试不自动启用或批准。默认设置入口仍是“模型设置”。
- **远端 MCP**：统一管理初始化、工具发现、调用、取消与关闭。连接错误不阻断本地工具；已启用连接异步发现，目录变更在下一轮聊天生效，撤权立即阻止尚未执行的旧轮次调用。工具使用独立命名空间，不能覆盖原生工具。
- **QQ/163 只读邮箱**：在应用进程内提供列出账户、列出授权文件夹、搜索邮件、按引用读取单封邮件四类操作，不新增外部邮箱 MCP 服务或监听端口。
- **可见的调用确认**：外部 MCP 每次调用都需要聊天中的确认卡，服务端绑定会话、轮次、目标、配置版本、工具定义和精确参数。工具描述或 schema 变化后需要重新批准；拒绝、超时、关闭、参数改变或撤权后不会执行。远端“只读”注解、邮件正文和模型文字不能代替用户确认。
- **邮箱来源与模型目标保护**：邮箱结果首次进入某个会话的模型前，需要确认实际接收目标和会话保留说明。服务端先保存邮箱来源，再提供结果；聊天、压缩、列表摘要及修复会话等模型路径都核对实际目标，更换接收地址后需重新确认，HTTP 重定向不转发邮箱数据。
- **独立配置与凭据**：连接元数据保存在当前数据根的 `config/integrations.json`，格式版本为 1，不与 TOML 双写。新增凭据默认仅本次进程有效；显式选择持久保存时使用 Windows 当前用户 Credential Manager，不支持的平台不会回退到普通明文配置。
- **旧版聊天兼容**：修复 `legacy_default` 旧版聊天路径的原生工具兼容回归，避免新增邮箱策略误查不存在的持久会话。该路径仍不提供 MCP/邮箱工具，`websearch.*` 修改仍受确认限制；模型参数不能伪造该兼容上下文。

本轮新增 Jakarta Mail API 2.1.3 和 Eclipse Angus Mail 2.0.5，更新第三方声明；继续复用现有 MCP SDK。打包 JAR 冒烟脚本新增不联网的 IMAPS/MIME 服务加载检查，功能 PR 的 Windows CI 已通过该检查；最终发布 tag 的便携/安装包仍需独立执行验证。

## 升级前注意：旧联网搜索的安全收紧

旧 `websearch.*` 仍使用原 TOML/模型外设置，不复制或自动迁移原 URL 和密钥，修改后继续按原提示重启。

旧搜索现在也需要工具批准与逐次调用确认，并受 HTTPS 公网目标限制。原先使用明文 HTTP、内网或环回地址的 MCP 搜索配置不再发出请求；配置会保留以便手工修正，不自动绕过限制。依赖无人确认连续调用的原有使用方式需要调整。

## MCP 支持范围

第一期仅支持 Streamable HTTP，使用匿名或目标绑定的 Bearer 认证。目标必须是 HTTPS 公网地址，不接受 URL 内账号、查询参数、片段、内网、环回、链路本地、元数据地址或非全球单播地址。每次交换重新核对 DNS 解析结果并连接已检查的地址，按原主机名验证 TLS，不跟随重定向，不使用进程代理。

支持 JSON 响应和有界 SSE 响应流；不包含旧 SSE 传输、无限后台 GET 订阅、断线续传、stdio、OAuth 或任意命令导入。需要这些能力的服务器可能不兼容。初始化、请求、响应体、工具数量及结构大小均有上限；不能确定远端是否已执行的调用不会自动重试。

MCP 工具仍可能产生外部副作用。确认前请检查目标、工具说明与具体参数；本地确认机制不能保证远端服务正确、可信或只读。

## QQ 与 163 邮箱边界

### 账户与授权

仅支持普通 `@qq.com` 与 `@163.com` 完整邮箱地址，分别固定连接 `imap.qq.com:993` 和 `imap.163.com:993`。使用客户端授权码，不填写网页登录密码。只使用 IMAPS，验证证书链和服务器名称，仅接受 TLS 1.2/1.3；失败不降级为明文，也不提供忽略证书选项。

首次配置先保存未启用账户，再单独设置授权码、测试、选择文件夹和正文权限并启用。默认文件夹为 `INBOX`，正文读取是独立权限。测试只核对 TLS、认证、协议能力、文件夹及只读打开 INBOX，不读取正文，不证明全部历史邮件可见。

163 在打开文件夹前发送真实 `SelfAnalyst` 客户端 IMAP ID，不冒充其他客户端。缺少 ID 能力或出现 `Unsafe Login` 时报告服务商限制，需要核对官方开通状态和授权码，不能通过伪造身份或关闭 TLS 校验绕过。

不支持企业/VIP 邮箱、QQ 其他域名别名、自定义 IMAP 服务器、Gmail/Outlook OAuth、SMTP、发信、草稿、标记已读、移动、删除、附件下载或后台全量同步。

### 客户端只读、搜索与正文

客户端以 `EXAMINE` 只读打开文件夹，以 `BODY.PEEK` 读取正文，关闭和失败清理不执行写入或 expunge。账户操作串行化，取消或超时会关闭本次连接，认证失败不自动重试。

**软件只读不等于授权码本身只读。** QQ/163 授权码可能允许其他客户端执行更多操作。建议使用可独立作废的授权码；在应用内断开不等于在服务商处撤销授权。

搜索按账户、授权文件夹、时间、发件人、主题或未读条件进行，不自动下载正文生成预览。默认每页 20 条，最多 50 条；每次仅扫描有界 UID 窗口，并限制信封数量和传输字节。超过预算会明确报告限制或截断。服务商开放的历史范围未知时返回 `providerVisibleRange=unknown`，无结果不代表旧邮件不存在。服务器不支持所需中文字符集时报告能力限制，不退回整箱正文下载。

邮件引用与游标绑定账户、会话、文件夹、UIDVALIDITY、查询和权限版本，有效期 15 分钟，重启后失效。邮件移动、权限变化或引用失效后需重新搜索，不会把旧引用解释为另一封邮件。

正文按需读取，默认最多返回 20,000 个 Unicode code point，并限制协议输入、解码总量、MIME part、嵌套深度和执行时间。HTML 只转为本地纯文本，不执行脚本、不请求远程图片或链接。附件仅返回有界元数据，不读取附件流；过大或截断内容会说明原因，不承诺完整读取。

## 隐私、留存与凭据

邮箱结果可能发送给用户确认的模型接收目标，连接器内置和协议只读都不表示内容只留在本机。邮箱来源会话停止自动长期记忆提炼，拒绝会向 embedding 外发邮件衍生查询的语义搜索；原生工具采用本地只读允许清单，设置或记忆写入需单次确认，其它原生工具默认拒绝。

不建立邮件全文库，不后台同步，不自动把邮件放入 Wiki、本体、embedding 或长期记忆。**不承诺邮件正文零落盘**：工具结果、引用、助手转述和压缩摘要可能随现有聊天与 AgentState 保存。

删除会话按现有删除协调清理本地会话与来源记录。断开邮箱停止后续读取并尝试清理本地凭据，不删除已有聊天、备份、用户另存文件或远端邮件，也不能撤回模型已接收的数据。

新增凭据绑定连接 ID 和精确目标，邮箱还绑定服务商与完整地址；改目标不能把旧 Bearer 发送给新服务器。会话凭据退出后清理；持久凭据由操作系统保存。系统拒绝删除时会显示待清理提示，进程退出或崩溃后残留的孤立项可能需要在 Windows 凭据管理器手工清理，不能把“断开”当成已彻底擦除。

Windows 保险库不是同一登录用户下恶意进程的隔离边界。新机制不会自动迁移旧 `websearch.api-key`、ChatGPT 授权文件或其他已有凭据。日志关闭可能输出远端原始内容的 MCP SDK 记录，只保留分类状态，不记录授权码、Bearer、邮箱正文或服务商原始错误。

既有窗口与文件采集边界不变：不持久化 UIA 正文、截图或音频；文件采集仍只收集显式配置目录内的文件系统元数据，除安全解析 `.gitignore` 外不读取普通文件正文。

## 备份、升级与回退

升级前通过托盘完全退出旧版，备份完整运行数据根、配置及配置到根外的事件、记忆与索引目录。不要让不同版本同时使用同一数据或凭据目录，建议先在独立测试数据目录试用。

新增连接元数据和邮箱来源记录纳入数据根格式准入；来源表使用独立版本标记，不应手工删除标记或降低格式版本。连接导出只包含公共元数据；导入清除机器凭据引用、启用状态、工具批准与邮箱披露确认，恢复配置不代表恢复了认证。JSON 备份不包含 Windows 保险库秘密，仅会话凭据在重启后需要重新输入。

旧版本没有本期 MCP 权限与邮箱来源保护，不能把降级当成安全兼容路径。需要回退时，先断开新增连接并按需在服务商处作废授权，退出应用，另存当前完整数据，再将兼容的升级前完整备份恢复到隔离目录。恢复会丢失备份后的新增数据，不能靠覆盖单个数据库保留全部状态。

继续沿用 Wiki schema 5。beta.7 或更早版本不能直接打开升级后的 Wiki 数据库；自动 Wiki 备份不替代完整备份。既有 ChatGPT 预览资格、刷新凭据兼容和远端撤销限制仍适用，不应把新版凭据复制回旧版。
