# SelfAnalyst v0.6.1-beta.9

这是接续 v0.6.1-beta.8 的预发布版本，包含“关于”发布时间和被阻塞摘要的修复入口增强。它不替代 v0.6.0 稳定版；应用内“检查更新”仍只查询稳定版，请从本预发布页面手动下载。

## 升级前请完整备份

本轮没有新增数据库迁移，继续使用 beta8 已引入的 Wiki schema 5。由 beta8 升级到本版不会再次引入 schema 4→5；从 beta7 或更早版本首次升级到 schema 5 时，旧版不能直接打开升级后的 Wiki 数据库。

升级前通过托盘完全退出旧版，备份完整运行数据根、配置文件和所有配置到运行数据根之外的数据目录（包括事件、记忆和索引目录）。不要让稳定版和预发布版同时使用同一数据目录。首次 schema 5 升级会先创建并核验 `llm-wiki.db.before-summary-repair-v5.bak`，再进行事务迁移；自动 Wiki 备份只覆盖 Wiki，不能代替整个应用的备份。没有兼容且可恢复的升级前完整备份时，不应尝试降级，也不要手工修改 SQLite `user_version`。

## 更新内容

### 当前版本发布时间

- “关于 SelfAnalyst”弹窗显示当前精确桌面版本的 GitHub Release 发布时间，支持 beta/rc，按界面语言及本地时区显示。
- 基本信息立即显示，发布时间异步读取；同版本的有效时间可缓存供离线显示。没有有效缓存时明确提示暂不可用，开发构建显示开发版并跳过查询。
- 重复打开合并请求；关闭或切换帮助内容后的迟到响应不会重新打开或覆盖弹窗。查询不发送桌面令牌、后端地址或用户活动，不自动下载安装更新。

对应 [PR #122](https://github.com/chunleik/self-analyst/pull/122)。

### 全天阻塞与额度耗尽修复

- 当“昨天”全天摘要被失败或周期额度耗尽的下级阻塞时，折叠卡片直接显示“修复下级摘要”和准确时间范围，定位实际阻塞的小时或半天。
- 已结束的小时、半天及全天摘要，在失败或周期额度耗尽时均可进入本地修复；汇总修复必须拥有完整的直接下级，不能把不完整证据伪装成完整上级摘要。
- 保留原始统计、证据来源和累计模型用量，用户补充内容仍需逐项确认、完整本地校验并明确保存。子摘要改变时触发并发冲突保护，不能静默覆盖。
- 保存后上级按正常调度重新评估；仍存在其他失败依赖或上级额度不足时，不承诺立即恢复全部摘要。

对应 [PR #123](https://github.com/chunleik/self-analyst/pull/123)。本轮复用已有修订存储，不新增迁移、运行依赖或采集范围。操作及数据边界见[修复指南](https://github.com/chunleik/self-analyst/blob/v0.6.1-beta.9/docs/summary-repair.md)和[运行数据备份与回退](https://github.com/chunleik/self-analyst/blob/v0.6.1-beta.9/docs/runtime-storage.md#摘要修复存储升级与回退)。

## 安装、试用与回退

1. 完成退出与完整备份后，下载安装包，或把便携 ZIP 解压到新目录后运行 `SelfAnalyst.exe`。默认使用当前用户应用数据目录；添加 `portable.marker` 后使用程序旁数据目录。
2. 在测试数据或已备份数据上打开“关于”，核对版本和本地时区发布时间；断网后可检查同版本缓存。首次离线没有缓存时显示暂不可用。
3. 在“昨天”被阻塞条目中核对修复入口的目标时段，尝试本地编辑→逐项确认→校验→保存，再核对来源标记和上级剩余阻塞原因。
4. 如需回退，先退出新版并另存当前完整数据，再将兼容的升级前完整备份恢复到隔离目录，显式使用旧版打开该目录。不要只把旧 Wiki 库覆盖进混有新版聊天、索引和事件状态的目录。
5. 恢复旧备份不包含备份后的活动、聊天和修订，请保留新版数据副本；无可用备份时保留新版，不承诺无损降级。

升级或卸载应用文件不会删除默认用户数据。
