# SelfAnalyst 国际化（中/英双语）SDD 规格说明书

> **迁移状态：** 现行行为契约已迁移至 [`internationalization`](../../openspec/specs/internationalization/spec.md)。本文档仅保留为旧 ID、历史背景和源码追溯，不再独立维护。

> Specification-Driven Development spec. 本文档定义 SelfAnalyst 桌面端的中/英双语国际化（i18n）行为契约：**后端所有发给 LLM 的提示词** + **桌面 UI 的全部界面文案**按有效语言切换；语言由新增配置键 `app.language=zh|en|auto` 决定（默认 `auto`，读系统 Locale 自动判定，用户可显式覆盖）。实现必须可追溯至本文档中的规格 ID。

## 2. 实施前背景与缺口

实施本特性前，SelfAnalyst 是**中文优先、硬编码单语**：

- 后端发给 LLM 的提示词写死中文；
- 桌面 UI 的界面文案硬编码中文；
- 没有语言/locale 配置，日期格式固定 `Locale.CHINA`。

由此产生两类问题：

1. **输出语言不可控**：中文 system prompt 把模型往中文输出上拉；英语用户即便用英文提问，也容易得到中英混杂或中文回复。
2. **写死的中文字面量泄漏**：提示词里有让模型**照搬中文短语**的指令（如 `SelfAnalystAgent` 中"明确告知用户『建议记录以下发现』"），以及 `ChatSummaryService` 强制"用一句**中文**概括"——这些与英文用户的语言不一致，是确定性 bug，与模型能力无关。

本特性据此实现中/英双语国际化，覆盖后端 LLM 提示词与桌面 UI 文案；语言由
`app.language` 决定，默认 `auto`，并修复写死中文字面量泄漏。

本特性沿用既有配置范式（`UserConfigStore` 分层默认 + 同目录临时文件替换，见 `SPEC-CFG-*`）与桌面 UI“无构建步骤、`<script>` 顺序加载、共享全局 `state`”的现有结构。

## 3. 与既有 spec 的关系

- **SPEC-I18N-DEC-001**：本特性**修订**以下既有约束中"输出/文案固定为中文"的隐含前提，仅改变**语言呈现**，不改变各特性的交互、数据契约与发送语义：
  - `SPEC-AGT-*`（`core.md` §7 SelfAnalystAgent）：system prompt 由"固定中文"改为"按有效语言选 zh/en 变体"；新增"以有效语言回复"约束。Agent 的工具集、ReAct 流程、迭代上限等不变。
  - `SPEC-CFG-*`（`core.md` §6/§6b）：`ConfigTools` 白名单新增 `app.language`；`DesktopConfigController` 默认值集合新增 `app.language=auto`。
  - `SPEC-CSP-API-011`（`chat-session-store.md` 会话摘要）：会话摘要的生成语言由"固定中文"改为"跟随有效语言"；其异步、可降级、不阻断收发的语义不变。`ChatSummaryService` 提示词中写死的"中文"二字被本 spec 取代。
  - `SPEC-ADV-*`（`behavior-advice.md`）/ `SummaryService`：活动摘要与建议改写的提示词语言改为跟随有效语言。
  - `desktop-chat-tab.md`、`desktop.md`、`config-toml.md` 等所有桌面 UI 文案：由硬编码中文改为经消息目录按有效语言渲染；布局、交互、键盘行为不变。
- 上述被修订条文继续有效，**仅"语言"维度被本 spec 统一接管**。

## 4. 设计结论（决策与取舍）

- **SPEC-I18N-DEC-002（仅 zh + en）**：只支持中文与英文两种语言，有效语言（effective language）恒为 `zh` 或 `en` 之一。
  - *取舍*：覆盖当前用户面；不引入复数规则、RTL、按区域格式化等完整 ICU 复杂度。新增语言留待后续，但消息目录结构须能容纳第三种语言而不改调用点。

- **SPEC-I18N-DEC-003（单一语言解析点）**：有效语言由**唯一解析入口**根据 `app.language` 与系统 `Locale` 计算，后端与前端都从该结论取语言，不各自重复判定。
  - *取舍*：避免前后端判定不一致导致"提示词英文、界面中文"的割裂。

- **SPEC-I18N-DEC-004（`auto` 默认 + 显式覆盖）**：`app.language` 默认 `auto`，按系统 Locale 自动判定，零配置即可对中/英环境给出母语体验；用户可显式设 `zh` / `en` 覆盖。
  - *取舍*：默认 `auto` 而非默认 `zh`，让英文环境开箱即英文；保留显式覆盖以应对"系统英文但想要中文"等场景。

- **SPEC-I18N-DEC-005（提示词维护双份而非运行时翻译）**：每条 LLM 提示词维护 `zh` / `en` 两份**人工撰写**的变体，按有效语言选用；**不**在运行时调用 LLM 翻译提示词。
  - *取舍*：双份维护有成本，但保证提示词质量、零额外延迟与 token 成本、可控可审。

- **SPEC-I18N-DEC-006（前端消息目录，无构建步骤）**：前端界面文案集中到**消息目录**（key → {zh, en}），所有用户可见文案经查找函数 `t(key)` 取值；目录以既有 `<script>` 方式加载，**不引入打包器 / 框架 / 构建步骤**。
  - *取舍*：保持 vanilla ES5 + 无构建；放弃成熟 i18n 库与按需加载，换取与现有架构一致、零工具链。

- **SPEC-I18N-DEC-007（语言生效时机：后端重启、前端重载）**：后端语言取自**启动期不可变 `Config` 快照**（应用无配置热重载，与 `llm.model` 等键一致；主对话 Agent 的 `sysPrompt` 亦在启动时一次性构建）。故 `app.language` 变更后：**后端**提示词 / Agent 语言需**重启后端**才生效；**前端**界面文案在下一次加载 / 刷新 WebView 时生效（无构建、无框架，不做运行时整页重渲染）。
  - *取舍*：让后端语言随启动快照固定，避免引入 Agent 热重建 / 配置热重载（改动生命周期、风险高），与项目既有"多数配置键需重启"的范式一致；前端整页热切换需响应式渲染、与无框架约束冲突，故改为"刷新生效"。结论：`app.language` **进** `RESTART_REQUIRED`（后端需重启），UI 另需刷新。

- **SPEC-I18N-DEC-008（不做运行时本地化的内容）**：以下不在运行时国际化范围：源码注释、日志、项目文档、`config.toml` 模板注释、ActivityWatch 自带 Web UI（`self-analyst-aw` 模块）、OS 提供的应用 / 窗口名、已落盘的历史数据（既有会话摘要等保持其生成时语言）。项目文档仍按仓库规范统一使用简体中文。
  - *取舍*：聚焦"用户在桌面端实际看到与 LLM 实际收到"的语言；历史数据回填语言成本高、价值低。

## 5. 目标

- **SPEC-I18N-GOAL-001**：存在单一有效语言（`zh`/`en`），由 `app.language` + 系统 Locale 唯一确定，后端与前端共用同一结论。
- **SPEC-I18N-GOAL-002**：后端所有发给 LLM 的提示词按有效语言选用对应语言变体，且指示模型以有效语言回复。
- **SPEC-I18N-GOAL-003**：桌面 UI 所有用户可见文案按有效语言渲染，无硬编码单语字面量遗留在渲染路径。
- **SPEC-I18N-GOAL-004**：消除写死的、与有效语言不一致的字面量泄漏（`SelfAnalystAgent` 的"建议记录以下发现"、`ChatSummaryService` 的"用一句中文概括"等）。
- **SPEC-I18N-GOAL-005**：`app.language` 可经现有配置通道读写；默认 `auto`；非法值回退到 `auto` 的判定结果。
- **SPEC-I18N-GOAL-006**：默认（`auto`）下，中文系统得中文体验、英文系统得英文体验，均无需用户配置。

## 6. 语言解析契约

### SPEC-I18N-RES-001：有效语言定义

- 有效语言 `effectiveLang ∈ {zh, en}`，由 `app.language` 决定：
  - `zh` → `zh`；`en` → `en`。
  - `auto`（默认）→ 读系统 `Locale.getDefault()`：其语言代码以 `zh` 开头则 `zh`，否则 `en`。
  - 任何无法识别 / 非法的 `app.language` 取值，按 `auto` 处理（SPEC-I18N-GOAL-005）。

### SPEC-I18N-RES-002：解析单一入口

- 有效语言由唯一解析入口计算（SPEC-I18N-DEC-003）；后端各提示词构建点、前端渲染点均从该结论取语言，不各自实现判定逻辑。
- 后端从启动期 `Config` 快照解析有效语言（`Config.effectiveLanguage()`）；前端从后端取得有效语言（SPEC-I18N-RES-003）。生效时机见 SPEC-I18N-DEC-007（后端重启、前端刷新）。

### SPEC-I18N-RES-003：有效语言对前端可得

- 后端须在前端初始化阶段使**有效语言对前端可得**（复用既有配置 / 状态通道，或注入到所服务的页面）；前端据此选择消息目录的语言列。
- 具体承载通道由实现决定；契约只要求：前端在首屏渲染前能拿到与后端一致的 `effectiveLang`。

## 7. 后端提示词国际化契约

### SPEC-I18N-PROMPT-001：覆盖范围（目标提示词清单）

下列发给 LLM 的提示词均须提供 `zh` / `en` 两份变体并按有效语言选用：

| 提示词 | 当前位置 |
|--------|---------|
| Agent 基础系统提示及其动态拼接段（记忆、Wiki、文件索引、联网搜索、配置管理等小节标题与说明） | `src/main/resources/prompts/agent/system.*.md` 及同目录能力片段，由 `AgentPrompts` 装配 |
| 纯改写系统提示 | `src/main/resources/prompts/agent/plain-completion.*.md` |
| 活动摘要提示（`buildPrompt`） | `SummaryPromptService` |
| 建议改写提示（`buildAdvicePrompt`） | `SummaryPromptService` |
| 会话摘要提示（`buildPrompt`） | `ChatSummaryService` |

`AgentPrompts` 使用的提示词以 UTF-8 classpath 资源保存，供开发期直接编辑；资源随 Maven 构建进入 JAR，修改后需要重新构建并重启应用，不支持运行时热加载。各资源的用途、调用时机和占位符契约见 `src/main/resources/prompts/agent/README.md`。

### SPEC-I18N-PROMPT-002：以有效语言回复

- Agent 的系统提示须包含明确指令：**以有效语言回复用户**。
  - **SPEC-I18N-PROMPT-002a**：`effectiveLang=en` 时，系统提示为英文且指示用英文回复。
  - **SPEC-I18N-PROMPT-002b**：`effectiveLang=zh` 时，系统提示为中文且指示用中文回复。

### SPEC-I18N-PROMPT-003：消除写死字面量泄漏

- 提示词中**不得**出现要求模型照搬、且与有效语言不一致的固定字面量。具体修复：
  - **SPEC-I18N-PROMPT-003a**：`SelfAnalystAgent` 中"明确告知用户『建议记录以下发现』"——`en` 变体须用等义英文表述，不得输出中文短语。
  - **SPEC-I18N-PROMPT-003b**：`ChatSummaryService` 提示词中写死的"用一句**中文**概括"——改为"用一句**有效语言**概括"，会话摘要语言跟随有效语言（修订 `SPEC-CSP-API-011`）。

### SPEC-I18N-PROMPT-004：日期 / 时间本地化

- 提示词中向模型注入的 `{{current_time}}`，其 `Locale` 跟随有效语言（`en` 用英文 locale 格式，`zh` 用中文 locale 格式）。
- "ActivityWatch 时间戳为 UTC、展示须换算本地时间"的语义说明也随有效语言给出对应语言文本。

### SPEC-I18N-PROMPT-005：兜底文本本地化

- 确定性兜底文本（如预算阻断提示、Wiki 未启用说明等当前写死中文的固定串）跟随有效语言。
- 由用户原文拼接得到的确定性兜底会话摘要（`SPEC-CSP-API-011b`）保持用户原文，不强制改写语言；其包裹 / 提示性文字（若有）跟随有效语言。

## 8. 前端 UI 国际化契约

### SPEC-I18N-UI-001：消息目录

- 新增前端**消息目录**：稳定 `key` → `{ zh, en }` 文案映射，以既有 `<script>` 方式加载；当前顺序为 `utils.js` 之后、`state.js` 之前，并先于所有使用文案的业务模块。
- 目录结构须能在不改调用点的前提下容纳第三种语言（SPEC-I18N-DEC-002）。

### SPEC-I18N-UI-002：查找函数 `t(key)`

- 提供查找函数（如 `t(key[, params])`）：按有效语言返回文案；支持占位符参数替换（用于含变量的文案）。
- `key` 缺失或对应语言文案缺失时，须有确定性回退（回退到另一语言或返回 `key` 本身），不得抛错中断渲染。

### SPEC-I18N-UI-003：覆盖范围

- 所有**用户可见**文案经 `t(key)` 取值，渲染路径中不得遗留硬编码的中/英字面量。覆盖：
  - **SPEC-I18N-UI-003a**：`index.html` 中的静态界面文本（标题、标签、按钮、占位符、tab 名等）。
  - **SPEC-I18N-UI-003b**：10 个 JS 模块在运行时生成 / 注入的文案（动态列表、提示、错误信息、确认框、空状态、toast 等）。
- **不**纳入覆盖（非用户界面文案）：`console.*` 日志、内部 key/枚举值、来自后端或用户数据的内容（会话正文、AW 数据、模型回复等本就由数据 / LLM 决定其语言）。

### SPEC-I18N-UI-004：语言切换时机

- 前端按 SPEC-I18N-RES-003 取得的有效语言在**加载时**选定语言列；变更 `app.language` 后**刷新 / 重开窗口**生效（SPEC-I18N-DEC-007），无需重启后端。

### SPEC-I18N-UI-005：语言选择入口（可选呈现）

- 配置界面**应**让用户能看到 / 设置 `app.language`（`zh`/`en`/`auto`）。其呈现遵循 `config-toml.md`：原始文本编辑器直接编辑 `config.toml` 即满足最低要求；是否额外提供下拉控件不作硬性接口约束。

## 10. 非目标

- **SPEC-I18N-NON-001**：不支持中、英以外的语言；不引入复数规则、RTL、按区域的数字 / 货币格式化等完整 ICU 能力。
- **SPEC-I18N-NON-002**：不在运行时用 LLM 翻译提示词或界面文案（SPEC-I18N-DEC-005）。
- **SPEC-I18N-NON-003**：不引入打包器 / 前端框架 / 构建步骤（SPEC-I18N-DEC-006）。
- **SPEC-I18N-NON-004**：不做前端整页运行时热切换语言；切换经刷新生效（SPEC-I18N-DEC-007）。
- **SPEC-I18N-NON-005**：不对源码注释、日志、项目文档、`config.toml` 模板注释、ActivityWatch 自带 Web UI、OS 提供的应用 / 窗口名做运行时本地化（SPEC-I18N-DEC-008）。
- **SPEC-I18N-NON-006**：不回填 / 迁移已落盘历史数据的语言（既有会话摘要等保持原语言）。
- **SPEC-I18N-NON-007**：不改变任何特性的布局、交互、数据契约与发送语义——本特性只改"语言呈现"维度。
