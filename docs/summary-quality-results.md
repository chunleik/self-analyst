## 效果边界

标题事实不能证明任务完成。引用有效、JSON 合法或规则通过，均不等于自然语言语义已被证明。抽查仍需注意“持续开发”“任务序列推进”等可能超过标题支持程度的措辞，以及跨应用主题归组是否合理。评测的主题关键词命中只是代理指标；模型真实性审阅栏保留人工确认语义，不伪造自动判定结论。

复现方法见 [摘要质量评测指南](summary-quality-evaluation.md)。默认离线，不调用模型；真实评测需显式 `-Live` 与环境变量。旧摘要不会自动付费重算。

## 后续稳定性优化：stabilize-summary-generation

首轮后的三日实际生成暴露了重复字段校验、标题元描述误拒、进程内缓存及单次尝试预算的局限。本轮按引用派生与误拒、周期账本与检查点、主题聚合三阶段实施。上面的“应用不一致仍拒绝”等首轮记录只描述当时行为；现在模型冗余的 apps/evidence 不再参与确定字段校验，输出从有效成员引用在本地派生，未知引用及不合法的必需结构仍拒绝。

### 可重复回归

- 固定种子 20260923 的 500/750/1000 条事实集合各含16个测试侧主题，涵盖跨应用/时间的同主题、同层短任务、通用词干扰、长标题尾部差异和正文诱饵。金标准没有进入生产提示词或规划器。
- 16项大规模验收区分输入处理、模型成员归属、卡片传递与展示引用；充分预算下结构完整，不足预算下显式计数。脚本化响应验证协议，不充当真实模型的语义准确率。
- 应用清单即使引用所有事实，也不能在独立词面代理中获得高主题分数；自然语言真实性仍待人工判断。
- 检查点覆盖旧/新载荷兼容、并发预留、真实用量超预留、跨进程恢复、输入/模型变化不重置额度、发布失败零模型恢复和关闭等待。暂停恢复含凭据在旧请求进行中热更新，以及启动扫描暂时失败的回归。
- 正式评测适配器直接复用 PlainTask：temperature=0.2、相同 system prompt、不发送 max_tokens 或 response_format、真实 usage 优先。离线入口8个案例通过，0次模型调用。

### 复验中继续暴露的问题

9月22日首份结果的助手侧抽查发现，跨应用数据库/接口、性能诊断和项目文档能形成可解释主题，但仍有同词不同领域的误归、主题重叠及过宽分类。至少3处主题混杂涉及10条事实，15个主题的展示证据存在重复文本。一个“保留笔记”表述略强于标题能直接支持的“查看相关草稿”。这些是局部审阅发现，不是用户金标准或语义准确率。

该日3条未归类事实中，2条在已有主题中存在同标题证据，另1条含义不明且只有观察；未发现因此遗漏独立重要主题，但不能据此推断其他日期没有遗漏。

另外两日的诊断继续暴露“观察动词＋界面名称枚举”误拒，促成局部元描述及独立动作反例回归。还有一次模型输出未知事实编号，按引用契约拒绝，未静默删除或猜测修补。

底层SDK原有默认重试还可能使一次账本调用对应多次HTTP尝试。本轮修复前的失败 receipt 无法还原实际HTTP次数，历史调用数只应理解为外层逻辑调用；缺失 usage 的预留也不是供应商最终账单。最终正式入口关闭隐式重试，通过本地HTTP错误端点验证一次请求对应一次外层准入；服务端可能计费的不确定结果仍保守占用额度。
