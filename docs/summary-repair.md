# 摘要对话修复

当一个已结束的小时、半天或全天摘要失败或周期额度耗尽时，可以从看板该时段或父摘要的失败依赖旁选择“对话修复”。“昨天”全天汇总等待下级时，折叠卡片直接显示“修复下级摘要 · 时间范围”，打开后绑定真实阻塞的小时或半天，不会误写全天；普通“追问”仍保留。已完成、未来、旧统计版本、缺失或普通等待生成的记录不提供修复写入能力。

例如“昨天 → 下半天质量失败 → 重试额度耗尽”，可直接从昨天卡片打开下半天修复，本地编辑、校验并保存。半天修复使用完整小时摘要，全天修复使用完整半天摘要，保留用户陈述来源。下级缺失或未完成时先处理下级；子摘要在编辑期间变化会导致旧草稿冲突，需要读取最新状态后重新核对。修复半天后全天按正常调度生成；如果全天自身也耗尽，其下级齐备后可继续从全天入口本地修复。

## 修订步骤

1. 打开入口，核对会话卡片的日期、时间范围和失败原因。打开只读取本地信息，预填问题不会自动发送。旧失败响应正文未保存时，会明确提示从当前允许事实重新整理，不伪造原失败句。
2. 可以发送修改意见，让模型生成有界的候选；也可以直接在卡片中编辑整体摘要、主要任务和任务片段，选择当前时段提供的事实引用。没有原草稿也能从空编辑器开始。
3. 自动采集的标题只支持适当的观察性描述，不能证明完成、部署、发布或解决了问题。如需补充实际行为，逐项核对任务文字并点击用户确认。该来源保存为 `user_confirmed`，表示用户自述，最高为 medium 置信度，不是独立核实。
4. 点击本地校验。字段反馈会指出未确认、引用无效、无依据断言、隐私或长度等问题。确认仅支持该任务的准确文字；改动草稿后必须重新确认。涉及用户确认成果的整体摘要由通过校验的任务描述组合，不能扩展新成果。
5. 核对最终预览后点击“保存修订”。普通聊天、模型回答“已保存”或校验通过均不会自动写入摘要。保存前服务端会再次核对目标版本、输入事实和草稿版本，并重新完整校验。

## 额度与本地模式

模型修订使用原目标周期的累计调用和 token 预算，同时受全局额度约束。换会话、修改问题或重启不会重置消耗；取消或结果未知的已发送请求仍按实际用量或保守预留结算。相同 turn 的重复请求复用已持久化结果，不重复发起付费调用。失败或中断的同一请求不会自动再次收费；如需重新请求模型，请发送一条新的修改意见。

打开、直接编辑、逐项确认、本地校验及保存不调用模型。即使没有可用模型或额度已用完，也可以建立并保存有效修订；空内容、删除全部有效主题或把有活动记录写成“无活动”不能通过校验。父周期仍受自己的额度与其他失败依赖限制，修复一个小时不等于全天已经恢复。

## 保存、冲突与恢复

- 保存原子写入摘要、最小用户陈述和修订审计，保留原失败与前后版本；原始活动、活跃/AFK/应用耗时和历史消耗不变。
- 后台生成先更新目标时，旧草稿保存返回冲突，保留输入。“读取最新状态”仅载入服务端已保存状态；仍符合质量失败条件时，可另选“将我的草稿应用到最新记录”，明确把当前未保存文字重新绑定当前版本。重新绑定会清除旧确认，需要逐项确认和校验。若后台已完成，则展示最新结果，不会覆盖它。
- 人工修订先发布时，旧后台结果不能覆盖或重新标为失败，已经发生的模型消耗照常计入原周期。
- 刷新或重启可恢复会话绑定和未提交草稿。删除会话清理未提交草稿；已保存的必要陈述和修订来源独立保留，删除聊天不会移除已提交的摘要证据。
- 下一次看板读取会展示“用户修订”来源。等待该小时的半天和全天摘要会在正常后台调度中重新检查，仍有阻塞时继续展示真实原因。

## 展示与隐私

看板不再显示“未识别应用活动”时长和“AFK 覆盖不足”统计诊断，旧快照与证据中的重复固定提示也会隐藏。底层覆盖与估计状态保留，真实 AFK 技术主题、正常应用统计、失败原因和修复入口不受影响。

修复只使用该时段允许的事实和用户主动补充的有界陈述，沿用脱敏和排除规则，不新增文件正文、截图或音频采集。请在确认卡片里检查脱敏后的最终文字。

## 升级前必读

本功能将 Wiki 数据库从 schema 4 升级至 5。请在正常退出旧版后先备份完整运行数据目录及配置的外置数据目录。新版会在升级既有 Wiki 数据库前生成一致性备份，并在事务内迁移；备份失败不会继续迁移。旧程序不支持 schema 5，不得直接用旧版打开新版数据，也不要手工降低格式号。具体路径、恢复步骤和回退的数据损失边界见[运行数据指南](runtime-storage.md#摘要修复存储升级与回退)。
