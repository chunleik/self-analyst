# 桌面端中/英双语国际化（i18n） — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax. **下方「Spec Gaps」标记的 spec 修订已于 2026-06-28 落实到 `docs/specs/i18n.md`，本 plan 与 spec 一致，可直接施工。**

**Goal:** 让 SelfAnalyst 桌面端支持中/英双语：后端所有发给 LLM 的提示词 + 桌面 UI 全部界面文案按有效语言（`zh`/`en`）渲染；语言由新增配置键 `app.language=zh|en|auto` 决定（默认 `auto`，读系统 `Locale`，可覆盖）；并修掉两处写死中文字面量泄漏。

**Architecture:**
- 新增 `com.selfanalyst.i18n.Lang`（枚举 `ZH`/`EN`）与 `LangResolver.resolve(appLanguage, systemLocale)` 作为**唯一语言解析点**（SPEC-I18N-RES-001/002）。
- `Config`（启动期不可变快照）新增 `appLanguage()`（原始值）与 `effectiveLanguage()`（解析为 `Lang`）。后端各提示词构建点统一从 `config.effectiveLanguage()` 取语言。
- 提示词 zh/en 变体以 Java 常量对维护：`SelfAnalystAgent` 把提示词组装抽到可测的 `AgentPrompts`；`SummaryPromptService` / `ChatSummaryService` 的 `buildPrompt*` 接收 `Lang` 参数。
- `/desktop/status` 响应新增 `language` 字段（= `config.effectiveLanguage()`），作为前端获取有效语言的通道（SPEC-I18N-RES-003）。
- 前端新增消息目录模块 `i18n.js`（`MESSAGES` + `t(key,params)` + `applyI18n(root)`），`index.html` 静态文案标 `data-i18n*` 属性（中文为内联兜底），10 个 JS 模块运行时文案改走 `t()`。

**Tech Stack:** Java 17（records/enum/text blocks）、Javalin、JUnit 5、vanilla ES5 JS（无构建/框架）、PowerShell 校验脚本。

**Spec:** `docs/specs/i18n.md` — all `SPEC-I18N-*` requirements。

## Spec Gaps（✅ 已于 2026-06-28 落实到 `docs/specs/i18n.md`）

实现过程中发现 spec 的一处契约与现有架构不符，**已按修订后的行为编排本 plan，且对应 spec 条目已同步修订**（下列记录保留作背景与决策追溯）：

- **背景**：主对话 `SelfAnalystAgent` 的 `sysPrompt` 在 `AppSession` 启动时**一次性**构建（`AppSession.java:140` → 构造函数内 `buildSystemPrompt()`）；`Config` 是启动期不可变快照，应用**无配置热重载**（`llm.model` 等键本就标注"需重启"）。
- **结论**：改 `app.language` 后，**后端提示词/Agent 语言需重启后端才生效**（与 `llm.model` 一致）；**仅 UI 文案**在 WebView 刷新即更新。无法做到"后端下一次调用即生效且无需重启"。
- **需修订的 spec 条目**：
  - `SPEC-I18N-DEC-007`：改为"后端语言随启动 `Config` 快照固定，变更 `app.language` 需重启后端使后端提示词生效；前端文案刷新生效"。
  - `SPEC-I18N-CFG-002c`：`app.language` **应**加入 `RESTART_REQUIRED`（写回提示注明需重启后端使提示词语言生效、UI 刷新更新文案）。
  - `SPEC-I18N-RES-002`：删去"每次按需读取以即时反映"的措辞，改为"由启动 `Config` 快照解析"。
  - `SPEC-I18N-TST-014`：断言 `app.language` **在** `RESTART_REQUIRED`（写回提示包含需重启）。
  - `SPEC-I18N-TST-017`：手动验收改为"切换 `app.language` 后，**刷新**使 UI 文案切换；**重启后端**使 Agent 回复语言切换"。
- 其余 spec 条目（RES-001/003、PROMPT-*、UI-*、CFG-001/002a/002b、NON-*、其余 TST）保持不变。

> 该修订已落实（用户于 2026-06-28 确认接受方案 1）。被否决的备选：坚持原"无需重启"契约需引入 Agent 热重建机制（改 `AppSession`/Agent 生命周期，成本与风险显著更高）。

### Task 1: 语言解析核心 + Config 接线

**Files:** `Lang.java`(Create)、`LangResolver.java`(Create)、`Config.java`(Modify)、`application.properties`(Modify)

实现要点：
- `Lang { ZH("zh"), EN("en") }`，含 `code()`；提供 `fromCode(String)`（未知→`null`）。
- `LangResolver.resolve(String appLanguage, java.util.Locale systemLocale) -> Lang`：
  - `appLanguage` 去空白小写后：`"zh"`→ZH、`"en"`→EN；`"auto"` 或 null/空/未知 → 看 `systemLocale.getLanguage()`：以 `"zh"` 开头→ZH，否则→EN（SPEC-I18N-RES-001、GOAL-005）。
  - 提供便捷重载 `resolve(String appLanguage)` 用 `Locale.getDefault()`。
- `Config`：在其工厂解析处用 `envOrProp(props, "app.language", "APP_LANGUAGE", "auto")` 得原始值；新增访问器 `String appLanguage()` 与 `Lang effectiveLanguage()`（后者调 `LangResolver.resolve(appLanguage(), Locale.getDefault())`）。记录于 `Config` record 字段或惰性计算（按 `Config` 现有风格）。
- `application.properties` 顶部「应用」段加 `app.language=auto`（含注释：`zh`/`en`/`auto`）。
