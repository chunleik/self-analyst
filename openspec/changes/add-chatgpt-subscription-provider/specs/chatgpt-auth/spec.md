## Purpose

定义用户从桌面模型设置通过系统浏览器授权 ChatGPT 账户的行为契约，涵盖官方动态客户端注册、PKCE 本机回调、授权状态、受保护本地凭据及失败隔离，避免把订阅资格或本地登录状态误报为模型访问权限。

## ADDED Requirements

### Requirement: SPEC-CGAUTH-001 明确授权能力与服务端支持边界
系统 SHALL 仅在用户主动启动 ChatGPT 登录时使用官方动态客户端注册授权流程，以本应用真实身份和稳定安装标识建立注册；首次使用官方规定的动态注册标识，随后使用本应用获发的 client ID。授权 SHALL 使用 authorization code、S256 PKCE、不可预测的 state 和 nonce 及本机回环 redirect URI，并请求所需身份、离线刷新及直接模型访问 scope。生产远端端点 MUST 使用受信任的 HTTPS 目标，令牌请求 MUST NOT 跟随重定向。系统 MUST 验证返回身份的签名、发行者、受众、有效期、nonce 和重授权账户标识，不信任仅解码的 JWT。服务端拒绝注册或授权时 SHALL 明确报告失败，MUST NOT 使用其它应用身份、浏览器 Cookie 或其它应用凭据代替。界面和文档 SHALL 说明 ChatGPT 订阅与 API 额度并非等价，实际模型权限由服务端预览能力、账户资格和授予 scope 决定。

#### Scenario: 首次动态注册
- **WHEN** 用户主动添加 ChatGPT 账户且服务端支持该授权流程
- **THEN** 系统使用本应用真实身份生成带 S256 challenge、state 和 nonce 的授权地址，通过系统浏览器完成注册及授权，在验证签名身份后保存本应用获发的客户端注册

#### Scenario: 身份有效但缺少直接访问权限
- **WHEN** 返回签名身份有效但令牌未包含所需直接模型访问 scope
- **THEN** 系统保留可供重新授权的注册，明确报告 chatgpt_plan_permission_required，不允许模型推理、不静默回退 API Key；再次授权使用已注册客户端请求用户同意

#### Scenario: 无效签名或错误账户
- **WHEN** 返回身份的签名、发行者、受众、有效期、nonce 或重授权账户标识不匹配
- **THEN** 系统拒绝该授权结果，不把其保存为可用账户，也不覆盖已有有效凭据

#### Scenario: 注册后令牌交换或身份验证未完成
- **WHEN** 受保护回调已带回本应用获发 client ID，但令牌交换、JWKS 请求或身份验证未完成
- **THEN** 系统可保留不含有效身份和 token 的待验证客户端注册供后续重试，不将其展示为可选账户或允许模型访问，只有后续签名身份验证成功才能激活账户

### Requirement: SPEC-CGAUTH-002 本机回调与授权生命周期
登录启动、状态查询、取消和断开接口 SHALL 受既有桌面认证及回环来源边界保护。回调监听 SHALL 只绑定回环地址，验证请求路径、state、当前授权尝试及有效期；一次成功回调只能消费一次。授权码、PKCE verifier 和令牌 MUST NOT 返回普通 UI 状态、进入持久 URL、日志或错误。授权尝试 SHALL 可取消并具有有限有效期，替换、取消、超时或应用关闭后旧回调 MUST NOT 改变当前连接。取消、拒绝授权或回调错误 SHALL 保留已有有效凭据，不自动改变模型配置。

#### Scenario: 伪造或过期回调
- **WHEN** 回调缺少匹配 state，或来自已取消、过期或已完成的登录尝试
- **THEN** 请求被拒绝，不交换授权码、不覆盖凭据、不报告新登录成功

#### Scenario: 重复启动和取消登录
- **WHEN** 用户发起新登录后取消，旧浏览器随后返回回调
- **THEN** 旧尝试不能覆盖当前状态；取消释放回调资源并保留既有连接及模型草稿

### Requirement: SPEC-CGAUTH-003 凭据隔离与本地保护
OAuth access token、refresh token 及客户端秘密 SHALL 仅由后端凭据组件持有，并与普通 TOML、会话、模型提示词和浏览器存储隔离。持久化 SHALL 使用操作系统保护或仅当前用户可读取的本地存储，并限制文件访问权限；不支持可靠保护时 SHALL 明确失败或仅保留内存，MUST NOT 静默保存为普通配置。状态接口 SHALL 只返回账户选择所需的标识和受限显示信息、连接状态、有效期或受限错误类别，不返回令牌、令牌片段或凭据摘要。断开连接 SHALL 尝试通过受信任元数据声明的 revocation endpoint 撤销该账户刷新令牌，并无论远端结果如何清除本地 OAuth 凭据及未完成授权；远端撤销不能确认时 SHALL 明确显示未确认状态，并阻止后续新请求使用该连接，MUST NOT 清除独立 API Key 或用户会话。

#### Scenario: 查看设置与高级配置
- **WHEN** 用户读取设置、有效配置或 TOML 原文
- **THEN** OAuth 令牌不出现在任何响应中，状态查询不触发远端请求或凭据刷新

#### Scenario: 断开 ChatGPT 连接
- **WHEN** 用户确认断开已连接的 ChatGPT 账户
- **THEN** 本地 OAuth 凭据被清除，新调用明确要求登录，已有 API Key 配置与本地聊天历史保持不变

#### Scenario: 远端撤销失败
- **WHEN** 断开账户时远端 revocation 请求失败或无法确认结果
- **THEN** 本地 token 仍被清除，界面准确说明远端撤销未确认，不声称服务端令牌已撤销；远端撤销等待期间不阻塞状态查询

### Requirement: SPEC-CGAUTH-004 有界刷新和失败隔离
系统 SHALL 在已授权模型调用需要时检查所选账户令牌有效期，并串行化同一连接的刷新，使用服务端返回的新 refresh token 替换旧值。刷新 SHALL 遵循服务端 earliest_refresh_at 等有效时间约束。临时网络或基础设施失败 SHALL 保留凭据并返回可重试的受限错误；服务端明确令牌失效、过期或重复使用时 SHALL 清除该账户 token、保留注册映射并要求重新登录，MUST NOT 自动改用 API Key、其它账户或其它供应商。注销或新登录与刷新交错时，较早刷新结果 MUST NOT 恢复被注销的凭据或覆盖较新登录。认证网络请求 SHALL 限制超时及响应大小，错误 MUST NOT 包含远端原文或凭据。刷新、身份校验和远端撤销的网络等待期间，系统 MUST NOT 持有阻塞状态查询、连接判断或其它账户凭据读取的存储锁。服务端成功返回的轮换 refresh token SHALL 先于身份校验等后续步骤持久化；返回的身份令牌验证完成前，新 access token MUST NOT 用于模型请求。身份校验因网络或密钥获取暂时不可用时 SHALL 保留已持久化的新凭据并返回可重试错误，后续调用继续校验而不重复刷新；校验明确失败或账户标识不匹配时 SHALL 清除该账户 token 并要求重新登录。

#### Scenario: 并发请求遇到过期令牌
- **WHEN** 多个模型工作同时需要刷新同一已过期连接
- **THEN** 刷新协调为单一有效结果，各请求使用最新有效令牌，不重复覆盖轮换后的 refresh token

#### Scenario: 刷新时断开连接
- **WHEN** 刷新尚未完成而用户断开连接
- **THEN** 迟到刷新结果被丢弃，本地状态保持断开，不恢复已清除的凭据

#### Scenario: 临时刷新错误与终止错误
- **WHEN** 刷新遇到临时网络失败，或服务端明确返回 refresh token 失效、过期或重复使用
- **THEN** 临时失败保留凭据并提示重试；明确终止错误清除 token 并保留注册，要求重新登录，均不回退至其它账户

#### Scenario: 刷新进行中查询状态
- **WHEN** 某账户刷新请求正在等待远端响应，界面同时查询 ChatGPT 状态或运行时判断连接是否可用
- **THEN** 查询不等待刷新网络请求而及时返回，刷新完成后才写回轮换结果

#### Scenario: 轮换成功但身份校验暂时不可用
- **WHEN** 令牌端点已返回轮换后的 refresh token，但身份令牌校验所需的元数据或密钥暂时无法获取
- **THEN** 新 refresh token 已持久化，本次调用返回可重试错误且不使用新 access token；网络恢复后的调用完成校验并直接使用该凭据，不再次消耗刷新

#### Scenario: 其它进程已完成轮换
- **WHEN** 刷新收到 refresh token 重复使用等终止错误，而本地存储中的 refresh token 已被其它进程更新
- **THEN** 系统不清除较新的凭据，改用存储中的最新有效令牌

#### Scenario: 跨进程刷新锁被占用
- **WHEN** 其它进程持续持有同一凭据目录的刷新锁
- **THEN** 当前请求在总计不超过 90 秒的锁等待期限内返回可重试失败，保留凭据、不发出刷新请求，状态查询不等待该刷新锁；等待被中断时及时终止

#### Scenario: 待校验刷新后重新登录
- **WHEN** 旧刷新身份仍待校验或正在校验，用户成功重新授权同一账户
- **THEN** 已验证的新登录替换旧待校验状态，后续模型请求使用新凭据，旧校验结果不得阻止或清除该新登录

### Requirement: SPEC-CGAUTH-005 多账户和重新授权隔离
系统 SHALL 允许保存多个独立的已验证账户注册，按稳定账户标识选择活动 ChatGPT 连接，MUST NOT 把不同账户的 token、client ID 或权限混用。登录新账户 SHALL 不自动覆盖其它账户凭据或保存模型草稿；界面可将刚成功授权的账户选入草稿，但 SHALL 保留原模型及其它草稿字段。断开某账户 SHALL 清除其 token 但保留可供重新授权的客户端注册和稳定安装标识，不影响其它账户；删除凭据与状态变更不得被该账户旧刷新覆盖。

#### Scenario: 添加第二账户
- **WHEN** 用户已连接一个账户并成功添加另一个已验证账户
- **THEN** 两个账户可分别选择，原账户注册与凭据保留，运行配置不自动切换；界面可选中新账户为草稿账户，但不覆盖其它草稿字段或自动保存

#### Scenario: 断开后重新登录
- **WHEN** 用户断开后重新授权同一账户
- **THEN** 系统复用该账户已注册客户端与稳定安装标识，获取新的权限与令牌，而不创建不必要的新注册或混用其它账户凭据
