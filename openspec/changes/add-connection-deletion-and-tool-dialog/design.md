## Context

见 proposal.md 的动机。当前 main 为 4957820（beta.16）。连接页在内存维护 snapshot/draft；整体 PUT 支持删除与凭据清理，但用户界面缺少入口，整体保存也可能误提交其它草稿。工具目录来自受管状态中的 tools 和新增 catalogAvailable 标记，不存在 resources/prompts 枚举能力。

代码没有显式 Langfuse/OTel 接入。SelfAnalystAgent 构建 OpenAI-compatible 与 ChatGPT Responses 模型；PlanMiddleware 可看到 ReAct reasoning/acting/model call，但 completePlainDetailed 的普通摘要和 UsageMeteredModel 的压缩不经过同一 middleware。PrivacyRuntime 和 MailGuardedModel 只保护原有采集/模型接收边界，不能作为向 Langfuse 分享邮件或正文的授权。

2026-11-14 用户将实施调整为“结合 MCP 删除和查询功能，一起写提案”。停止新增实现和测试，保留已做代码；本文统一后续设计，不追认 Langfuse 已实现。后续用户明确修订为开发者功能、允许选择上传隐私内容、服务器由客户指定，以下范围取代早先“仅本机、永远只元数据”的限制。

## Goals / Non-Goals

**Goals:** 定向删除不影响其它草稿；可访问地查看已发现 MCP tools；在开发者主动选择的本地/LAN/远程 Langfuse 中观测完整链路；既支持安全默认元数据，也支持明确授权的分范围隐私内容上传。

**Non-Goals:** 不自动启用开发者上传、不自动部署/登录 Langfuse，不补传历史会话、不新增原本未采集的数据，不实现 MCP resources/prompts；不绕过模型/工具执行权限，不把本地删除等同远端删除，不将费用估算当真实账单。原始附件/PDF、任意文件下载、隐藏思考流与二进制工具输出不在首期内容范围内。用户已进一步授权修订后实施、PR、必需检查通过合并和远端 beta 发版；不本地打包、不顺带合并 #154。

## Decisions

### 1. MCP 管理界面与服务端

- POST /desktop/integrations/delete 严格接收 kind、id、expectedRevision。管理器同步校验版本/种类/存在性，拒绝 legacy，从最新保存配置只移除目标及批准，复用 save 的原子提交、reconcile 与凭据清理；不接收整份 UI 草稿。
- 草稿删除只动内存；已保存删除确认显示保存的名称、地址和影响。成功仅从旧草稿移除目标、更新 revision，保留其它编辑。冲突保留草稿；响应丢失或无法确认提交时冻结写入，提示显式丢弃草稿后读最新状态，不盲目重放。
- 独立原生 dialog 只展示真实 tools；打开只读缓存，显式发现复用 /discover。带未保存元数据时隐藏旧目录并禁用发现，防止把旧目标工具标到新草稿地址。catalogAvailable 区分已发现的空目录与从未发现。
- 显示身份、连接/批准状态、名称、描述及 JSON Schema，不自动授权。使用 textContent、原生焦点隔离、Escape/关闭和焦点返回，关闭/销毁隔离迟到响应，中英与窄屏一致。

### 2. 开发者入口、独立配置与授权记录

UI 放在“配置 → 开发者功能 → Langfuse 观测”。开发者入口只是功能可见性，不授予发送权限。观测独立于 MCP/Agent 业务工具：运行数据根 config/observability.json 使用 schemaVersion/revision、原子保存与 CAS。公开配置包含规范化完整 endpoint、publicKey、sampleRate（默认 1.0，范围 0–1）、captureMode（默认 metadata）、内容类别和来源选择、scope/sessionId 及可选 CA PEM。协议固定 v4；secretRef 仅在本地存储封装内，不在公开配置中。enabled 和授权均不持久化，缺配置/重启均关闭。只保存选择不代表已经授权；单独授权记录绑定目的地、项目、类别、具体来源、会话/任务范围、隐私说明版本及有效期，不接受导入 JSON 伪造同意。

保存不联网，合成测试不启用。启用确认展示实际接收地址（本地/内网/远程，不只一个昵称）、项目、数据类别、会话/后台范围、HTTP/TLS 与服务器保留风险。两种模式均在明确点击启用后生效；内容模式的确认额外列明类别、来源与保留风险，首期所有启用授权只在当前应用运行内有效，重启不自动恢复，界面清楚提示。范围可选当前会话，或用户明确选择的本次运行内后续调用/后台任务；不默认全局授权，不单独扫描历史；后续实际调用仍可能携带历史会话上下文，确认必须披露这一点，不能称为仅新创建会话。开启开发者功能、保存 key、模型同意、MCP 工具批准均不等于内容上传同意。

更改 origin/basePath、项目公钥、可信证书配置或扩大内容范围时停用并重新确认，撤销/缩小范围立即清除未发送的旧范围内容。停用与“断开并清理凭据”分开，成功/失败/清理待处理分别显示。客户端不会宣称能撤回已在途或已被接收的请求。

复用 CredentialStore/WindowsCredentialStore 的读回验证保险库，为观测添加独立固定身份和专用 CredentialTarget，绑定规范化目的地与项目公钥。新 key 写入→配置原子提交→旧 key 清理；失败保留可核实状态。Secret Key、认证头不进入公共 GET、Agent 工具、TOML、导出或日志。不支持安全存储的平台明确拒绝持久连接，不降级明文/伪加密。公共 CA 或企业 CA 的配置不是关闭证书校验。

### 3. 客户自定义目的地、URL/TLS 与 OTLP

- 用户可指定本地回环、私有 LAN IP/域名及公网 HTTPS origin，可含经过严格校验的反代 basePath。网络规则由 Langfuse 专用 EndpointPolicy 管理，绝不改动现有 MCP PublicEndpointPolicy 的公网限制。
- HTTP 仅接受规范字面 127.0.0.1、[::1] 或解析全为回环的 localhost，启用前披露明文 Basic 不能防御本机恶意程序。本机指 Java 后端所在机器。LAN/公网仅 HTTPS，校验链、主机名、有效期；自建 CA 通过显式配置的观测专用 trust store（指纹可见）支持，不修改 OS 信任、不支持 trust-all 或忽略主机名。证书配置变更重新确认。
- URL 拒绝 userinfo、query、fragment、控制字符、非常规数字 IP、未指定/多播/链路本地、已知云元数据目标及 zone ID；拒绝编码路径分隔符、点段/双重解码歧义，规范化后唯一拼接 `/api/public/otel/v1/traces`，不接受任意路径或用户自定义认证 header。
- 启用/测试前通过只解析的 preview 显示目的地类别、IP 集合、CA 指纹及短期确认令牌；令牌绑定配置 revision/本次运行，正式动作使用该批准地址快照。在每次实际建立连接时重新解析、检查全部结果并固定连接到已检查 IP，TLS SNI/证书仍用原始主机名。公网域名不能静默重绑定回环/私网；LAN 域名限制到用户确认的具体主机/IP 集合，变化需重新确认，不将整个 RFC1918 网段视为授权。多地址混合类别/危险地址拒绝。实现若不能落实实际 IP pinning，就不得宣称防重绑定通过。
- 禁止重定向，不自动使用系统 HTTP 代理，不将 key 转发其它目的地；不执行网络扫描或自动探测邻居服务。请求只走固定 OTLP endpoint，错误响应不展示原文。权限记录绑定目的地/项目/证书配置，命名相同不代表同一接收方。
- 使用实际 OpenTelemetry Java SDK + 专用有界 SpanExporter 序列化官方 OTLP HTTP/JSON（官方支持；便于在传输层落实 IP pinning、禁代理/重定向），Basic Auth(publicKey:secretKey)、`x-langfuse-ingestion-version: 4`，不使用 gRPC 或旧 `/api/public/ingestion`。客户具体版本未知；一期要求支持该 profile，404/415/兼容失败给明确指引，不静默回退协议。自定义主机可能不是 Langfuse，用户确认和合成测试不是对服务商诚实性的保证。
- 测试只发送固定非内容 span；“接收端接受”不等于已在 Langfuse UI 索引。任何真实内容测试另按内容授权流程，不因测试 key 自动上传私有数据。

### 4. 元数据模式、内容范围与隐私规则

#### 默认元数据模式

固定 span 名称，例如 selfanalyst.turn、agent.reason、model.generation、tool.call、summary.generate、context.compact、mcp.discover、mcp.delete。允许应用版本、固定 provider/category、受控模型类型、性能时序、结束状态/错误分类、实际 token/明确估算来源、采样信息、随机 trace/span/session ID。

不传 prompt/回答/思考/摘要、标题、邮件、工具参数结果/描述/schema、图像、原始 URL/header、账户/路径、异常原文/堆栈。自由命名的模型/连接/远端工具使用运行内匿名标识，本地界面提供映射。元数据结构不接收正文，而不是先整段复制后脱敏。

#### 开发者内容模式：选择不等于一揽子许可

内容选项均默认未选，需逐类选取并在发送前确认接收方与范围；同一个 payload 只导出所有相关门槛的交集。未选类别用无内容的省略标记，来源无法可靠标记或混合无法安全拆分时整段降级元数据。

| 类别 | 可选择的内容 | 必须满足的附加边界 |
| --- | --- | --- |
| 模型消息与任务文本 | 实际合法构造的输入消息、应用 system 提示、回答、普通摘要和压缩文本 | 明确会话/后台任务范围；嵌入的工具、邮件、图片仍分别受下列门槛约束；不收集额外隐藏思考或网络 header |
| 工具输入/输出与目录 | 选定 MCP 连接的参数、文本结果，以及单独选择的描述/schema/自由名称；原生工具首期只记录元数据 | 按连接 allowlist（该连接内工具），不能把“允许调用此 MCP”当 Langfuse 数据授权；不额外调用工具、不抓取结果 URL、不上传任意二进制 |
| 邮件内容 | 所选邮箱账户的邮件头（发件人/收件人/主题等）与正文分别选择 | 已有合法读取权限仍需通过；单独 Langfuse 邮件授权绑定明确账户及目标；含邮件来源的消息、摘要、压缩、工具结果同样受门槛控制；邮件来源存在但账户归属不明时整段降级元数据；附件不下载、不导出 |
| 图片 | 首期不上传内容，界面明确未支持 | 图片与其无法隔离的衍生内容整段省略；媒体上传、预览与接收方授权留待独立后续变更，不采集截图、不抓取远端 URL |
| 模型隐藏的数据 | 不新增导出入口 | 只追踪实际调用；已经被过滤而不在调用中的内容不可为观测额外读取或补回 |

首期图片只导出有界类型/尺寸和“未上传图片内容”标志，图片内容选项在界面明确标为未支持，data URL/base64/二进制统一省略，不把文本内容同意解释为图片许可。聊天中由图片产生的文字也视为图片衍生内容，未有独立图片许可时相关无法隔离的 input/output 整段降级元数据。后续媒体上传需独立变更，核实 Langfuse 媒体流程、逐张/批预览及真实对象存储接收方授权；不静默回退链接或 MIME 附件。

#### 与采集/模型排除的关系

采集排除（未采集或禁止收集的 UIA 正文、屏幕截图、OCR、音频、普通文件内容等）是硬边界，开发者观测不能新增采集、补采、从数据库/文件系统绕道恢复。模型排除决定已有数据进入模型的范围，不等于 Langfuse 分享授权；两种观测模式均只看实际调用中已有的数据，不能为观测额外读取模型已过滤的本地事件或绕道恢复原始数据。实际模型消息可能仍包含用户主动输入的隐私，只有被选择且授权的类别才导出。授权观测不更改模型规则、邮箱范围或 ApprovalRegistry。

在任何内容模式下都不导出应用持有的 Secret Key、授权码、认证/会话 token、Cookie、私钥、完整支付凭据等结构化秘密字段，不启用全局 javaagent 或自动 HTTP header/body instrumentation。结构化字段屏蔽与已知密钥哨兵检测是附加保护，不承诺能识别用户自由文本/图片中的所有秘密或个人信息；预览、范围选择与风险告知不能被“已自动脱敏所以安全”的承诺代替。异常仍只导出固定分类，不给未经审查的原始 stack/message 旁路。

只有供应商 actual usage 写为实际 usage；estimated/reserved 单独标识，不当作实际费用。ChatGPT 订阅不按 API 单价冒充账单，首期不传 cost。

### 5. 调用链覆盖与异步隔离

每个聊天轮次或后台摘要任务为 root trace，Agent/model/tool 为子 span。统一模型装饰器覆盖 ReAct 模型、completePlainDetailed 普通摘要、UsageMeteredModel/压缩，并在真实订阅时创建 span，围绕实际网络完成/同步异常/异步错误/取消/超时 exactly-once 结束。复用现有 usage 来源，避免 middleware 与装饰器重复上报同一 generation。

Reactor Context 显式带本地 OTel context，通过调度线程切换保持父子关系；不把会话或邮件信息放传播 baggage，不向 MCP 服务注入观测认证或 trace headers。工具调用 span 包含确认等待时间，拒绝、执行、失败用受控状态表示，不另建批准等待 span，不改变 ApprovalRegistry 和邮件来源保护。被拒绝操作没有外部业务发送。

实际 SDK SimpleSpanProcessor 只负责非阻塞入有界队列，专用单工作线程批量 exporter 异步网络发送，初始预算：2048 个内存 span 队列、每批 128、5 秒调度、5 秒请求超时、每批最多两次有界退避、关闭最多 3 秒。必须确认实际 OTel exporter 重试/线程实现符合预算，否则封装有界传输。队列满丢弃并本地计数；429/5xx仅限同目的地有界重试，401/403不循环重试。目的地、密钥、内容范围或证书配置变更、停用使旧 epoch 的排队 span 丢弃，取消未发送批次；不能保证撤回已经在途/已经接受的请求。无磁盘队列、无启动补传、无历史扫描。内容额外限制单文本字段最多 16 KiB、单 span 64 KiB、单批 1 MiB，并标明截断/省略；图片内容首期不上传，禁止把 base64 或图片 URL 塞入属性或重试日志。限额为初始设计建议，可在不扩大数据类别的情况下按性能测试收紧。

### 6. 保留与删除边界

删除 MCP 连接只删 SelfAnalyst 本地定义/批准/凭据，不删除已送达 Langfuse 的既有观测。停用观测停止新采集与新导出并清空未发送队列，清理本地秘密不代表撤销服务端 key；用户在 Langfuse 管理保留/删除/撤销。内容可能留在 Langfuse 数据库、对象存储、服务端日志、备份及管理员可访问位置；即使客户端不建落盘队列，应用原有聊天/缓存、OS 和远端也可能保留。不可宣传“绝不落盘”“完全匿名”“零风险”或自动不留痕。

## Risks / Trade-offs

- 客户任意服务器可能由第三方控制 → 显示实际接收方/项目、严格地址/TLS、重新授权，客户端无法保证服务器侧删除或保留期限。
- 开发者内容可能含用户及第三方隐私 → 默认元数据，逐类/逐源/有界授权，邮件来源交叉检查，图片预览与单独存储目的地；不把开发者入口当无限数据许可。
- 模型隐藏数据容易被误当“已安全” → 独立观测授权不绕过模型过滤或采集硬边界；混合来源不明默认省略。
- OTel/媒体自动插桩可能重复或旁路 → 手工白名单 instrumentation、实际 payload 正反向哨兵与大小测试；兼容未知时显示不支持，绝不静默退化。
- 自定义 LAN 域名与代理/DNS → 专用实际连接校验、IP pinning、证书验证和单目标授权；不放宽 MCP，也不覆盖整个私有网段。
- 内容授权撤销时存在在途请求 → 清队列、停止后续发送并说明已在途无法保证撤回，不宣称远端删除。
- 系统保险库目前仅 Windows → 无支持的平台明确不可用；Linux 合成测试不代表 Windows 原生验证。
- 源归属不完整 → 恢复的旧会话、原生工具与未绑定会话的后台摘要只记录元数据；不中途重读历史或补采以获得内容，不把“支持路径的元数据”称为“所有路径内容已支持”。
- 恢复实施与交付 → 保留既有 diff 和已跑证据；完整 Java/Windows/视觉/实际用户服务验收分别记录，不把聚焦测试当最终通过，不自动归档。

## Migration Plan

无连接配置格式迁移。新观测配置缺失等于禁用、不联网；导出/导入观测配置不得携带秘密、启用/内容同意或机器相关引用。后续实现先补协议/元数据及分范围内容授权测试，再接入生命周期/模型调用与 UI，最后合成端到端和可选客户服务器验收。先完成本次规格修订，再按最新授权恢复实施、检查和 PR 交付；发布只走远端工作流。
