## Why

用户需要在同一轮产品改进中完成两件相互关联的事：明确管理 MCP 连接（删除、查看实际发现的工具），并把 SelfAnalyst 的调用链、耗时、token 与失败状态发送到客户自行指定的 Langfuse 服务器，方便观测。当前没有观测配置；只修改 ReAct 中间件还会漏掉普通摘要和上下文压缩，现有邮件模型授权也不包含 Langfuse。

## What Changes

- **统一提案后实施。** 保留已经写好的 MCP 删除/工具弹窗未提交代码，用户已进一步授权调整后实施、PR、检查通过合并及远端发版；现有代码不是 Langfuse 已实现的证据。
- 新增明确的“删除连接”动作，区分仅移除未保存草稿与按版本定向删除已保存连接；保留其它连接及未保存编辑，复用授权撤销和凭据清理。
- 新增连接绑定的 MCP 工具弹窗，展示真实已发现的 tools 名称、描述、输入 schema、批准与连接状态，不虚构 resources/prompts，不把发现等同批准或执行。
- 将 Langfuse 放入独立“开发者功能 → Langfuse 观测”，不作为 MCP 服务。客户自行配置本地、局域网或远程服务器、项目公钥、加密秘密和采样率；显示开发者设置不等于授权上传，保存/启用/测试/停用分离。
- 通过 OpenTelemetry Java + OTLP HTTP 导出对话轮次、Agent、模型、摘要、压缩和工具链路。默认关闭，默认选择元数据模式；允许经单独选择和明确告知的隐私内容上传，按模型消息/摘要、工具来源、邮件账户与头/正文分别授权；图片明确作为独立媒体范围，首期只记录元数据，不因文本同意上传二进制，不使用一个“全部隐私”选项推断所有范围。
- 目的地支持客户指定的本地/LAN/远程服务器；回环可使用明确披露的 HTTP，LAN/远程必须 HTTPS 并正常校验证书。按接收地址/项目/数据范围授权，防止重定向或 DNS 变化跨目标发送；不放宽既有 MCP 公网网络策略。
- 模型排除规则与观测独立：默认和内容模式均不增加被模型排除数据的读取；只观测实际调用已存在的数据，绝不新增被禁止的采集或改变模型权限。内容授权有界、可撤销，混合邮件来源不明时降级元数据。
- 异步有界、限时导出与关闭；失联、认证失败或队列满不阻塞聊天，不落盘缓存，不自动回补历史内容。

## Capabilities

### New Capabilities

- `developer-observability`: 客户自定义 Langfuse 的开发者配置、元数据/分范围内容授权、异步隔离、密钥和目的地边界。

### Modified Capabilities

- `mcp-integrations`: 版本化定向删除与只读工具目录弹窗的安全边界。
- `user-configuration`: 草稿隔离、删除确认、可访问弹窗，以及独立观测设置的知情启用和状态。

## Impact

涉及桌面连接 UI/受管 API、MCP 管理器、模型/Agent 调用链路（含普通摘要与压缩）、独立观测配置与系统凭据适配器、OTel 依赖、Java/Node/合成 OTLP 验证及双语文档。保留既有邮件权限和模型隐私保护，不改动采集边界；内容导出独立授权，不能把模型排除或现有邮件模型授权误当观测授权；不访问用户电脑、真实邮箱或实际 Langfuse，后续按用户最新授权走功能分支 PR、必需 CI 通过合并和远端 beta 发版，不本地打包、不顺带合并其它 PR。

当前工作区已包含第一部分的未提交实现；详见 `implementation-status.md`。Langfuse 部分当前仅设计，不能表述为已经接入。实际服务器地址、Langfuse 版本与项目密钥在后续用户连接时确认，不是写提案的阻碍。

本轮修订遵循用户“Langfuse 设置为开发者功能，可以上传隐私数据，服务器客户自己指定”。本轮先更新提案，再按用户后续明确授权实施和交付；不上传任何真实用户内容。
