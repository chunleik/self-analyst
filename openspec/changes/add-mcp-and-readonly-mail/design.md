# Design

## Context

动机和范围见 proposal.md。以下为已核对的实现约束，而非已实现的新能力：

- `SelfAnalystAgent.registerWebSearchMcp()` 直接构建 Streamable HTTP 客户端，AgentScope Toolkit 设置为串行。ReActAgent 构建会复制工具集；只修改模板不能保证当前实例和后续模型版本一致。
- `ConfigApplicationService` 管理 TOML 保存与模型运行版本；`TomlSupport` 将基本数组转换成逗号字符串并拒绝表数组，不适合表达多连接及原样参数。原始 TOML 编辑器可显示已有 API Key，不可将新邮箱授权码放进去。
- `LlmRuntimeManager` 已有每轮租约和旧资源退出语义，但当前工具集不是随模型配置完整热替换的独立资源。
- `EventServer` 对 `/desktop/*` 检查回环 Host/Origin 和 token/cookie；无桌面 token 的兼容模式会放行部分路径。因此新凭据、邮箱读取和批准接口还必须要求 `selfanalyst.managedDesktop`。
- AgentState 保存工具结果和历史，压缩生成滚动摘要；`chat.db` 保存用户可见消息。现有长期记忆默认 smart，并可能从助手回答自动提炼。仅关闭邮件缓存不足以实现邮件零落盘或排除长期记忆。
- 现有 `ChatGptCredentialStore` 为当前用户文件权限保护，不是系统保险库。新功能不迁移或重写此存储。

## Goals / Non-Goals

**Goals:** 通过可测试的统一边界接入多个外部工具源与两个邮箱预设；让新权限、网络目标、凭据生命周期和内容保存行为可解释；局部失败不影响既有本地功能。

**Non-Goals:** 不给邮箱内部调用套一层 HTTP，不注册公开 MCP Server，不新增后台邮件采集或发送能力，不将“内置”“本地优先”“只读”解释为无云端推理、无本地留存或服务商令牌天然只读。

## Decisions

### 1. 连接管理与业务适配分开

先在 `self-analyst-app` 内增加 `com.selfanalyst.mcp`、`com.selfanalyst.mail` 和可复用的凭据/策略包，不拆新的 Maven 模块。公共工具网关同时接收外部 MCP 工具描述和本地邮箱工具定义，但 `kind=remote-mcp` 与 `kind=builtin` 分开建模，后者没有 transport、URL 或 command。

外部 MCP 复用已有 SDK 的初始化、发现、调用与关闭，首期只支持 Streamable HTTP、匿名和 Bearer。拒绝 stdio、旧 SSE、OAuth、任意请求头及命令导入，而不是忽略不支持字段后自动运行。与启动外部程序相比，这降低首期执行和分发风险；后续增加 transport 必须单独修改规格。

### 2. 一份连接元数据，不改造拍平 TOML

使用固定运行根 `data/config/integrations.json`，顶层包含 `schemaVersion`、`revision`、`mcpServers`、`mailAccounts` 与独立的工具/目标批准记录。各集合使用稳定 opaque ID；普通读接口只返回公共数据及 credentialConfigured/storageMode，不返回秘密或系统保险库的任意项名。兼容搜索的批准记录可以引用其保留身份，但不得复制对应连接定义或秘密。

- 外部连接：id、name、enabled、transport、endpoint、authType、credentialRef、工具批准目录及有限资源预算。
- 邮箱账户：id、provider、email、displayName、enabled、allowedFolders、bodyAccess、credentialRef、storageMode、授权披露版本。
- 工具授权：本地源 ID、远端原始工具名、描述与 schema 的摘要、批准 revision。工具名使用本地命名空间及映射，不能覆盖本地工具或伪造来源。
- 新增连接默认 disabled；导入永不自动启用、测试、执行工具或保存凭据。导出排除凭据，并默认关闭条目、清除授权及机器专属 credentialRef。
- 乐观 revision 检查、同目录临时文件、原子替换和旧版本保留用于保存。保存只做本地校验，不在提交锁中执行网络请求。损坏/未知版本不被容错覆盖。

`ConfigApplicationService` 继续负责原有 TOML，不为了新功能重写配置模型。新仓库拥有自己的串行提交协调，UI 明确区分其 revision；避免跨文件假事务。

### 3. 兼容搜索不产生两份权威配置

统一管理器为 `websearch.*` 创建只读配置来源的保留入口 `legacy-websearch`，沿用现有默认关闭、构造期配置和重启语义，只有其客户端生命周期进入统一层。新 JSON 不能定义该保留 ID，设置页显示“来自高级配置”并定位原有键，不在新文件复制旧 API Key。

原有公开搜索的配置与问题选择习惯保持，调用权限有明确安全收紧：所有外部入口，包括旧搜索，都进入工具版本批准和逐次参数确认。原实现允许任意 mcp-url 且自动注册所有工具，不能将其视为可信只读白名单。旧入口也应用同一目标检查；不合规 URL 保留但不可用。ConfigTools 对 websearch 目标、密钥或开关的修改同样需要绑定变更的受管确认，模型不能自行改址后重启获得特权。

其注册不再与管理器重复执行。用户显式另建同端点连接时提示重复目标，但不默默复制凭据或启用。未来若要彻底迁移，另做带回滚的迁移 change；本期避免为两个文件建立复杂删除/回退语义。

### 4. 运行快照与即时撤权分别处理

连接状态与模型状态解耦。测试只做初始化和发现，产生有过期时间且绑定目标/凭据代次的诊断，不自动注册。启用后按已批准工具目录建立候选快照；新聊天在现有应用级 gate 下固定模型租约和工具目录，当前聊天不原地更换工具定义。工具集重建同时覆盖当前 Agent 与后续模型运行版本；若实施中 SDK 不能安全提供该行为，则不能以仅修改模板冒充完成。

注册数量、schema 深度/大小、工具结果和总截止时间均受本地上限约束。连接与初始化并行或惰性执行，不在应用启动路径串行等待所有远端超时。连接离线显示 degraded，不回滚已保存的合法元数据，也不影响本地工具。

每次调用仍读取最新权限：禁用、断开、改账户/目标、撤销工具批准立即阻止旧轮次开始新调用。清理旧连接等待在途调用退出且有截止时间；不能承诺撤回已发送请求。只读查询可有限退避，具有未知副作用的外部调用不自动重试。

### 5. 外部工具执行不能仅信任只读注解

工具发现不会自动批准工具。外部连接（包括旧搜索）每个工具首次出现或描述/schema 改变后需要显式选取批准；`readOnlyHint`、工具名称和描述不作为安全证明。首期所有外部 MCP 工具每次实际调用都显示接收目标、工具、参数及未知副作用提示，并取得绑定 session/turn、工具摘要、规范化参数摘要、连接 revision 的一次性批准。

批准等待不持有存储提交锁；受管桌面批准接口校验归属和最新权限，并只消费一次。取消、关闭页面、会话删除、工具变更或超时结束等待；未批准不发出 `tools/call`。非受管请求不能绕过此流程。测试/发现不调用业务工具，但需披露将与指定目标建立连接。

邮箱来源会话另有保守原生工具策略：只自动允许经核对不外发、不写入的本地查询，以及已授权邮箱读取。`WikiTools.semanticSearchWiki()` 会把 query 发给 embedding 服务，因此首期在这类会话拒绝语义检索，提示改用本地 `queryWiki`。`MemoryTools.correctMemory()` 和 `ConfigTools.setConfigValue()` 等写入则必须取得与实际动作绑定的一次性用户确认。其它工具未分类时拒绝，不仅根据注解判定只读。该标记避免仅靠关键词或模型自报判断内容来源，但不是通用信息流隔离，也不能清除已在模型上下文中的内容。

### 6. 网络目标与凭据绑定

远端连接要求 HTTPS 和正常证书/主机名校验；拒绝 URL 内嵌凭据、query/fragment、重定向、元数据地址、私网与环回解析。首期不支持自定义本地/内网 HTTP MCP，内置邮箱也不需要该出口。每次连接及重连都校验全部解析地址，并使用可阻止 DNS 重绑定的受控解析/建连策略；SDK 集成无法验证该策略时不得宣称 SSRF 防护完成或发布该入口。

凭据绑定规范化 scheme/host/port/path、连接 ID 和版本；修改目标后必须重新提供或重新确认目标匹配的新凭据，不自动发送旧 Bearer。邮箱端点仅来自固定 provider 预设，不接受模型、导入 JSON 或前端覆盖。大小限制覆盖 HTTP/SSE 累计读取，超时覆盖初始化、发现和单次调用的总期限。

### 7. 新凭据默认仅会话，显式选择安全持久化

新连接默认 session-only，退出后清除进程可控引用，重启显示 auth_required；界面必须提前说明需重新输入。选择“在本机保存”时仅使用可用的系统凭据库。Windows 首期实现当前用户 Windows Credential Manager 适配，其他环境无已验证适配时只支持会话模式，不假装成功持久化；以后支持其他系统保险库无需改账户模型。

新增/替换凭据采用 write-only 操作，建立新 opaque 引用后提交元数据，失败清理孤立项，成功后再移除旧项。凭据与旧账户/目标不能交叉使用；secret 不走 ConfigTools、模型、日志、前端持久存储或配置导出。系统凭据库不保证隔离同一 OS 用户下的恶意进程，不能宣传为绝对隔离。

账户断开先撤销本地调用资格，再关闭连接并清理本地项。QQ/163 通用授权码没有本应用可依赖的远端自动撤销流程，提供官方管理链接并准确提示由用户作废；断开不删既有会话或远端邮件。

### 8. 两个 provider 共用只读 IMAP 实现

采用 Jakarta Mail/Eclipse Angus；具体维护版本在实施开始时核对兼容及安全公告。固定 QQ 为 `imap.qq.com:993`、普通 163 为 `imap.163.com:993`，完整邮箱地址及客户端授权码认证。禁止信任所有证书、明文回退、借用网页登录密码或获取浏览器 Cookie。

163 在认证后、首次打开文件夹前发送 RFC 2971 IMAP ID，使用真实 SelfAnalyst 名称和构建版本；维护方字段取项目公开元数据，不虚构 support-email。测试至少经过安全连接、认证、ID、文件夹列表及只读打开 INBOX，才能发现“认证成功但读取被拒”的情况；不 FETCH 正文或发送邮件。

账户连接串行使用；每次请求有连接/读取/总截止时间，取消关闭或中断对应操作。使用 EXAMINE/READ_ONLY 和 BODY.PEEK，禁止 STORE/APPEND/COPY/MOVE/EXPUNGE、远端草稿及 SMTP。普通 close 不 expunge。测试必须断言网络命令和未读标志不变，不能只凭 Java 接口名断言只读。

### 9. 工具结果与邮件标识

首期工具仅为 `mail_list_accounts`、`mail_list_folders`、`mail_search_messages`、`mail_get_message`。账户与文件夹权限在后端复核；模型只选择已授权 ID，不能指定主机或 secretRef。未选择默认账户且账户有歧义时要求选择，不默默跨账户聚合。

搜索接受文件夹、时间、发件人、主题和未读条件，返回有界信封信息，不为了生成摘要读取每封正文。中文 charset 不支持时返回受限能力/错误；不静默全量下载匹配。每页默认 20、最大 50；搜索命中处理也必须有上限，优先服务器有界/范围查询，不在大邮箱上收集无限 UID 数组。覆盖字段区分请求时间范围、实际检查范围、服务商可见范围未知、截断和下一游标。

消息引用及不透明分页游标绑定 accountId、原始 mailbox 标识、UIDVALIDITY、UID、查询摘要和权限 revision；不用会变化的序号，Message-ID 只作展示/辅助线索。UIDVALIDITY 改变、邮件移动或过期引用返回 stale_reference，不能读取另一封信。首期不保证跨文件夹稳定会话线程。

正文按需获取，先检查 MIME/大小元数据，再以有界读取处理，限制编码后字节、解码后字符、part 数量和嵌套深度；默认最大返回 20,000 Unicode code point，并明确 truncated。优先纯文本，HTML 安全转文本，不执行脚本、不加载外链/远程图片。附件只返回元数据，拒绝 base64 正文或附件内嵌绕过限额。

### 10. 邮件数据保留与继承流程

授权分为账号读取范围、正文读取、模型处理及保留披露；读取范围可以限于选定文件夹，默认 INBOX。首次启用前展示当前模型的服务目标和会话持久化事实。模型服务目标变更后，含邮箱数据的会话再次向新目标发送前需重新确认；凭据轮换或同目标模型 ID 更换不视为新接收方。目标核对必须在实际租约内、先于所有模型发送，包括聊天前的压缩和 `ChatSummaryService` 的独立会话列表摘要；未获准时使用本地确定性摘要，不能先发往新目标再询问。

不建立邮件全文库或附件目录；短期有界内存数据可在轮次结束、断开或超时清理。但原始工具结果、助手引用和压缩摘要沿用既有会话存储，所以第一期不承诺零落盘。删除会话复用 chat.db 与 AgentState 删除协调；用户另存文件、备份和已发送给模型的副本不在断开或会话删除的撤回保证内。

后端在把邮箱信息返回模型前，先可靠地将会话标记为包含邮箱来源，不能由前端或模型取消。后续窗口、回复与压缩摘要均可能包含派生邮件信息，因此首期保守地停止该会话的自动长期记忆提炼，而不静默修改用户的 memoryPolicy；普通会话行为不变。已排队任务在发送模型和提交记忆前再次核对标记。显式手工记忆操作复用具体动作批准，不把模型自报“用户要求”或工具描述当作后端授权。删除会话清理此标记；标记无法读取/持久化时该邮箱调用 fail closed，不先暴露数据后补记。

### 11. UI 和错误反馈

`DesktopServer` 注入共享服务；新增 `/desktop/integrations` 和 `/desktop/mail` 控制器，所有账户、配置、测试、批准和数据读取均要求 managedDesktop，普通状态响应也不泄露账户详情给无认证调用者。请求体有严格 allowlist 和大小限额。

设置增加“连接与工具”视图：外部连接、内置邮箱、兼容搜索三类来源明确；邮箱主表单仅需 provider、邮箱和授权码，安全持久化为显式选项。测试、保存、授权、启用状态独立。复用 `llm-settings.js` 的草稿/请求代次/关闭取消模式，异步状态不覆盖未保存内容。错误只显示分类和可行动指引，例如认证失败、协议未启用、Unsafe Login、TLS、限流、超时、过期引用、权限变化；不展示服务端原始响应或 MIME 正文。

## Risks / Trade-offs

- [系统保险库跨平台差异] → 首期 Windows 持久化需原生验证；其他环境明确仅会话，不使用普通文件降级。
- [授权码权限比本软件只读策略更大] → 明确披露、固定目标、禁用写命令；授权码泄露仍可能影响远端账号，鼓励为本应用单独生成并可作废。
- [远端 MCP 工具或描述恶意变化] → schema/描述批准版本、逐次参数批准、有界不可信输出；批准不等于第三方服务可信或无副作用。
- [工具 SDK 复制、热替换及等待批准复杂] → 先做合成协议/轮次一致性测试，不在进行中的工具集原地增删，也不阻塞配置锁。
- [邮件进入历史后长期派生] → 会话级来源标记、自动记忆排除与明确保留披露；更细粒度的正文不落盘模式不在本期。
- [大邮箱与服务商收取范围] → 有界分页和 coverage，失败/范围未知不等于“邮箱没有邮件”，不自动更改服务商设置。
- [官方帮助示例包含明文 143] → 只采用其 ID 兼容要求，连接统一使用已核实的 993/TLS，不照抄不安全样例。
- [本轮没有真实账户及 Windows 系统] → 协议夹具能验证客户端契约，不能证明真实服务商/系统保险库已通过；后续用户授权的真实验收单列，不能在本轮调用真实邮箱。

## Migration Plan

1. 实施获得新授权后从本 change 的 tasks 开始，保持旧 `websearch.*` 配置不变，新文件缺失等价没有新连接。
2. 新文件只包含用户显式保存的数据，不自动连接/导入账户；启用前完成认证、披露和工具授权。现有数据根准入/版本检查应纳入新增文件，不在准入前创建凭据或网络资源。
3. 旧搜索迁移代码所有权并接受明确的安全收紧：合规且启用的配置可初始化，但工具未经用户批准不能调用；旧明文/私网目标显示不支持。邮件和新自定义 MCP 不因旧设置获授权。
4. 回滚旧版本时不覆盖未知的新 JSON、不自动清除系统凭据；如需清理，先在支持版本中明确断开。备份包含账户配置时不含系统秘密，换机器后显示需重新认证。
5. 实施并验证后同步主规格与用户文档；所有验收完成才归档。实施阶段之后已进一步取得 PR、合并及发版授权；须先通过远端门禁，不本地打包或自动归档。

## 实施补充：传输和接收方约束

实施保持原范围，远端 MCP 采用 SDK 会话语义与独立受限 HTTPS transport 组合，因为默认 Java HttpClient 无可控 DNS 钉扎。支持有限 JSON/SSE POST 响应，不提供后台 GET 订阅、事件续传或自动重试；有界时间内不结束的响应安全失败。启用连接异步发现，未就绪连接下一轮再发布，不阻塞应用本地启动。

安全复核发现 SDK 默认模型 transport 跟随重定向、MCP 默认日志可能记录远端内容。两个模型构建入口改用不跟随重定向的自有 transport；MCP 命名空间日志关闭，由本地分类状态替代。逐次确认前深复制执行参数，UI 显示副本与实际调用使用相同内容，防止等待期间嵌套参数变化。这些是落实既定目标/秘密/批准边界的实现细化，并非新增产品能力。

## 交付复核补充

发布前保留旧版 `legacy_default` 原生工具入口：仅服务器创建且未托管的旧版上下文不查询持久会话来源，其 MCP/邮箱能力仍不开放，`websearch.*` 配置修改仍需受托管会话确认。增加真实会话策略回归，防止把旧版标识交给持久会话 ID 校验器。

打包验证增加无网络的 IMAPS provider 与 MIME activation 加载探针，在既有 `check-packaged-jar.ps1` 中使用待测 JAR 与所选 Java 运行时执行；CI 和发布流程因此分别覆盖 shaded JAR 与便携包运行时。探针不登录邮箱、不创建用户数据、不启动采集器；本地仍不打包。
