## Context

动机见 proposal.md。共享 UI 已有帮助菜单和固定链接解析；桌面通过受管窗口校验后的 `help_action` 调用系统浏览器，Web 使用带 `noopener noreferrer` 的独立标签页链接。原生“关于”是系统消息框，不适合直接添加交互链接，因此在帮助菜单的“关于”前添加入口。

## Goals / Non-Goals

**Goals:** 复用两种运行模式的既有边界，以静态动作标识映射唯一目标，保持可访问性和错误恢复。

**Non-Goals:** 不新增任意 URL 原生 API、插件权限、依赖或网络请求；不改变现有公开官网内容、更新检查、关于信息和发布流程。

## Decisions

- 将 `website`、`documentation`、`knowledge` 加入现有菜单动作及前后端固定映射。目标由程序决定，原生命令继续验证受管窗口来源。相比直接把 URL 从前端交给外壳，这不会扩大可打开目标范围。
- 中英文使用相同仓库首页地址，文案分别为“项目官网”和“Project website”；入口位于分隔线之后、“关于”之前，不增加主导航宽度。保留使用指南并紧随“帮助文档”和“个人知识指南”，均使用 main 上已核验存在的文档；个人知识指南内已有 Neo4j 指南链接，不再新增冗长的重复入口。文档尚无英文译本，英文菜单如实打开现有文档。
- 复用原有本地化失败对话框；原生官网与新增文档打开失败时保留其安全重试动作，确保失败链接点击也走受限原生路径。Web 继续使用真实锚点，在用户点击事件内打开新标签页。
- Node 回归覆盖固定目标、双语文案、所有链接路径存在性、DOM 顺序、原生动作、失败重试、草稿保留及键盘焦点；Rust 单元测试覆盖两种语言的固定地址和未知动作拒绝。

## Risks / Trade-offs

- 浏览器可能静默拦截新标签页，应用无法可靠判断 → 只对可检测异常显示失败，不制造已打开的成功提示。
- 原生外链与 UI 跨模块 → 保留现有权限检查，分别补充 Node 和 Rust 回归。
- 当前环境没有 Cargo/Maven 且真实浏览器访问受限 → 先运行可用的 Node、语法和 OpenSpec 验证；原生构建、整库测试及视觉验证必须如实列为待验证，不能视为通过或绕过限制。

## Migration Plan

无需数据迁移。交付为基于当前 main 的独立功能分支及草稿 PR，等待必需 CI；合并和发布需另行授权。回滚只需还原本次菜单、双语资源和固定动作映射及其文档。
