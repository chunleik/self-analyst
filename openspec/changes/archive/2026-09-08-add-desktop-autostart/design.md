## Context

动机见 proposal.md。现有 Rust 桌面壳在获取命名 mutex 后启动 Java，健康检查成功后创建托盘及可见窗口。重复启动目前仅弹出提示；托盘操作依赖名为 main 的已创建窗口。安装版与便携版已有不同的资源及工作目录解析规则。此次涉及系统注册、跨进程唤起和安装生命周期，因此需要设计文档。

## Goals / Non-Goals

**目标：** 将自启动管理封装于桌面壳，复用后端生命周期；让窗口可见性由启动来源与用户唤起共同决定；注册操作和状态读取可替换为测试适配器。

**非目标：** 不创建 Windows 服务，不支持登录前启动，不增加定时重启或失败无限重试，不通过 Java 配置、浏览器或 Agent 修改系统启动项，不新增跨平台支持。

## Decisions

### 当前用户 Run 入口与状态归属

选择由 Rust 封装当前用户 `Software\Microsoft\Windows\CurrentVersion\Run` 下专用 `SelfAnalystDesktop` 值，内容为带引号的当前 EXE 绝对路径和固定 `--autostart` 参数。不经过 cmd 或 PowerShell，不注册 Java 或保存会话 token。Windows 的 Run 机制在用户登录后执行，执行时序由系统决定，参见 [Microsoft 官方说明](https://learn.microsoft.com/en-us/windows/win32/setupapi/run-and-runonce-registry-keys)。实施需按该接口限制校验命令长度，超限明确失败。

选择此方案是因为当前壳已限定 Windows 且使用 windows-sys，NSIS 也可处理同一入口。相比任务计划程序，无需任务定义和额外调度状态；相比新增通用自启动插件，可保持注册归属和卸载行为集中可检查。

同一用户只保留一个产品入口，最后一次显式开启决定路径。菜单勾选仅表示入口匹配当前 EXE 和参数；若入口指向其他分发，当前菜单不勾选，开启时说明将替换旧路径。关闭和卸载仅移除与自身路径匹配的入口。菜单打开及操作完成后重新读取，失败显示不可用而非猜测状态。Run 注册与系统是否允许执行是不同状态，不解析或写入未公开的系统禁用状态格式；文档说明系统启动应用设置和策略可阻止运行。

### 显式启动来源与隐藏窗口

启动入口在竞争单实例前解析 `--autostart`。健康检查成功后始终创建托盘及主窗口，但自动模式从构建窗口时设置不可见，避免先显示再隐藏的闪现。保留窗口对象使现有托盘恢复路径可复用。手动启动保持可见；所有恢复入口统一执行取消最小化、显示和聚焦。启动失败沿用清理和日志路径，不显示主窗口。

选择隐藏创建而非延迟创建，避免托盘事件、认证初始化和重复启动各自实现窗口创建逻辑。代价是隐藏状态仍有 WebView 资源占用。

### 单实例唤起与初始化竞态

保留 mutex 作为唯一后端的所有权约束；首实例获取锁后立即建立当前用户、当前登录会话内的命名事件监听，用于接收固定的“显示窗口”信号。事件名与单实例作用域一致并按当前用户隔离，访问权限限定当前用户，不传输 token、路径或任意命令。该信号只改变界面状态，不提供业务访问能力。

手动第二实例在有限等待内连接并发出信号；首实例尚未建好通信对象时短暂重试，失败明确提示后退出。自动第二实例直接静默退出。首实例将收到的信号记为待显示状态，窗口就绪后在主线程消费；窗口就绪前后的切换必须同步，防止丢失唤起请求。退出时停止监听并关闭句柄。

相比只显示“已运行”，该方式能满足后台自启动后的自然打开体验；相比引入完整消息协议，固定事件只承载本次必要的窗口唤起行为。

### 安装和便携生命周期

沿用既有 EXE/resource 解析及后端工作目录逻辑，自启动不依赖系统传入的工作目录。NSIS 增加所属入口清理，并区分升级替换与真正卸载，原位置升级不重置开关。不得无条件删除产品名相同但指向其他分发的入口。

便携目录移动不后台扫描修复；用户在新位置显式开启后覆盖旧入口。自动化测试使用隔离存储适配器，真实注册验收使用测试账户和正式分发，避免把临时构建路径留作长期入口。

## Risks / Trade-offs

- 系统启动应用设置或策略阻止执行 → 如实展示注册状态，用户文档说明系统控制边界，不承诺执行时间。
- 安装升级内部触发卸载钩子 → 在安装验证中覆盖启用和关闭两种升级路径，防止误删入口。
- 登录时后端资源竞争或启动失败 → 复用现有有界等待、清理和日志，不引入无限重试。
- 唤起信号先于窗口就绪 → 持久到进程状态中的待显示标记与主线程消费保证请求不丢失。
- 多个分发争用产品入口 → 只在显式开启时替换，并进行路径归属检查；卸载不影响其他分发。

## Migration Plan

首次更新不创建启动项，用户从托盘显式开启。实施完成后同步 desktop-shell 主规格和用户文档。回退旧版本前先关闭自启动；若已回退，可从系统启动项管理清除该入口。所有升级、回退、卸载均保留用户数据。

实施核对发现 Tauri 默认卸载模板会无条件删除产品名对应的 Run 值，因此使用独立值名 SelfAnalystDesktop，由项目钩子执行路径归属检查。该调整不改变用户操作和行为规格。
