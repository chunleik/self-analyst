## Context

动机与范围见 proposal.md。本变更跨越配置保存、模型构造、会话互斥、后台服务、预算和桌面反馈，需要设计文档明确版本与资源边界。

当前 AppSession 在启动时加载 Config，构造 SelfAnalystAgent、Wiki worker 及桌面控制器。SelfAnalystAgent 在构造时分别创建聊天与 plain 模型，压缩器还持有 plain 模型的计量包装。桌面 raw/结构化配置与 ConfigTools 分别直接持久化 UserConfigStore；UserConfigStore.load 只合并默认值和用户值，用于有效值展示及差异判断时遗漏环境变量。重启键集合也存在多份声明。

fee54e5 已实现 TOML 优先级及连接测试读取新保存参数。本 change 在此基础上建立运行时应用机制，不将该提交记为新的待实施工作。现行主规格仍规定模型在重启后生效；行为变化通过本 change 的增量规格提出，实施完成前不改写主规格。

## Goals / Non-Goals

**Goals：**

- 用明确的提交点协调磁盘配置与新工作所见的模型版本。
- 把稳定的会话、存储、工具和预算资源与可替换模型运行资源分离。
- 对客户端提供“已保存配置”“新工作实际采用的配置”“仍在运行的旧版本”三种信息。
- 覆盖取消、错误、首次配置和关闭，并避免 Agent 在自己的工具中保存配置时死锁。

**Non-Goals：**

- 不通过重启整个 AppSession 实现热更新，不迁移存储或重置应用会话。
- 不引入文件监听、远端配置中心、配置历史、自动文件回滚或跨进程事务。
- 不改变现有工具权限、会话 gate、模型超时、远端重试策略或摘要低温策略。
- 不因模型更新而使已保存但需重启的预算、压缩阈值、语言、maxIters、端口等提前生效。
- 本期仅维持现有连接测试能力；不把 /models 测试扩展为真实聊天验证。

## Decisions

### 1. 分离用户覆盖、解析结果和运行快照

引入共享配置解析器，输入为用户覆盖、环境快照、JVM 支持入口与默认值，输出包含值、来源和继承来源链。Config.load、连接测试、有效配置读取、结构化差异比较均使用它。UserConfigStore 继续负责原文读取和持久化，不把完整有效配置写入用户文件。

对结构化提交，应根据“用户显式提交了哪些键”更新覆盖，而非以是否等于默认值决定是否落盘。raw 继续逐字保存，空字符串与删除键的区别保留既有规则。旧结构化接口和 ConfigTools 的空值表示删除；raw 显式空密钥表示未配置，不能被环境变量重新覆盖。

解析后的配置不代表全部正在运行。每个组件维护自己的应用快照，LLM 的候选只取五项热更新参数；所有其它参数来自当前运行基线。Embedding 的继承来源参与差异计算，但不切换其现有客户端。仅改变来源或注释时更新保存信息，不重建模型。

替代方案是让所有读取直接调用 Config.load。这可以读到最新文件，却不能区分运行快照、来源或待重启值，也不解决显式覆盖被忽略的问题，因此采用分层解析。

### 2. 串行保存与不可失败的版本发布

增加进程级配置应用服务，接受 raw 全量文本和结构化覆盖更新。配置工具、控制器以及其它共享同一 TOML 的应用写入入口必须经此服务提交。文件设置专用接口仍保持原有采集应用行为，但持久化必须参加同一写入协调，不能直接绕过服务覆盖文件。

保存流程：

1. 取得配置更新锁，确认应用未开始关闭，重新读取当前用户文件；结构化修改合并到该文件。
2. 解析并校验候选，计算真实组件差异。LLM 保存校验温度有限且位于 0..2，输出上限为非负整数，base URL 为可解析且带主机的 HTTP(S) 地址；密钥空白或占位允许保存为明确未配置状态。未知 raw 键仍仅警告。
3. 为变化的 LLM 参数准备候选运行资源，或准备无模型的 unavailable 版本。准备阶段不得执行模型请求，也不得重新启动工具、存储或非 LLM 组件。
4. 使用同目录临时文件替换用户文件。成功后在一个不执行网络、磁盘或构造操作的短临界区发布新保存快照和新工作默认版本。工作入口获取版本及只读状态查询与该提交区协调，不能观察到一半的发布状态。
5. 释放更新锁，异步清理没有使用者的旧模型资源；不能在保存响应前等待当前聊天退出。

候选构建或文件替换失败均释放候选并保留旧文件、旧运行版本。提交点之后的资源清理错误单独记录，不把已成功提交响应误报成未保存。正常运行时版本发布只有预先准备好的引用交换与计数更新；进程崩溃后的恢复继续以持久化文件为准，不承诺磁盘与内存的跨崩溃原子事务。

按进程生命周期标识和单调序号区分版本，不用密钥或配置散列作为公开版本号。保存版本和模型版本分离：只改注释也会保存，但模型版本不增加。串行构建与提交使晚到的旧候选不能覆盖新配置。多客户端 stale 文本冲突和外部写入锁不在本期保证范围内。

替代方案是保存后发事件让各组件独立重建。它容易产生部分成功、不同组件版本不一致及较早异步构建覆盖较晚保存，因此本期使用统一协调和一次发布。

### 3. 稳定 Agent 门面与按版本管理的模型运行资源

保留对桌面与后台消费方稳定的 Agent 门面，将 memory、会话状态存储、应用聊天 gate、工具注册和 UsageMeter 归属于稳定服务。门面不能因启动时缺失密钥而永久为 null；模型未配置时返回明确不可用。

引入按版本管理的 LLM runtime，包含聊天模型、plain 模型，以及绑定该版本的 ReAct 执行对象与压缩执行适配。新版本沿用当前生效的 Agent 参数和共享资源，避免不可变 SDK 模型绑定将新模型漏在某条路径之外。每次执行从既有持久会话状态读取，不把旧版本的可变会话缓存复制进新版本。

实施时先核对 SDK 执行对象、toolkit、state store 和 HTTP 资源的所有权，建立候选构造和释放的组件测试。版本退休只释放版本自己拥有的模型资源与适配，不允许 SDK 关闭操作顺带关闭共享工具或状态存储。必要时使用不转移共享资源所有权的适配层。该核对不改变公开行为和版本化方案。

替代方案是完整重建 SelfAnalystAgent/AppSession，会重复初始化工具、MCP、数据库和后台任务，并使控制器仍持有旧引用；按版本资源配合稳定门面可避免这些问题。

### 4. 在逻辑工作边界取得并释放版本租约

一轮聊天在取得现有应用级 gate 后、压缩前获取一个 runtime 租约，并将其显式传给该轮压缩及 ReAct 执行。整轮所有 reasoning/tool/model 步骤固定该版本；ConfigTools 在轮内提交新配置也不会改变本轮租约。

独立摘要、Wiki 摘要、长期记忆提取等在逻辑任务开始时获取租约。一次任务有多次模型调用时仍复用同一租约。Reactor 请求在实际订阅／开始执行时取得版本，不能在创建惰性对象时固定版本，也不使用依赖线程绑定的 ThreadLocal。

每个版本记录活跃使用者数。发布后旧版本退休但继续服务已有租约，完成、异常、取消在统一终止路径恰好释放一次；无人使用后才释放模型资源。UsageMeter 始终为同一实例，用量仍由既有 Agent 中间件和 SUMMARY 包装负责，租约层不新增计量。

锁顺序禁止配置保存等待聊天 gate。模型发布只需短提交锁，执行期间不持有它；释放租约和资源清理也不得反向获取配置更新锁。这样配置工具在聊天内部调用保存时不会等待自己结束。

### 5. 首次可用与再次不可用属于相同生命周期

未配置模型时仍创建可独立工作的本地存储、会话服务及稳定门面。首次保存可构建的连接配置后发布可用 runtime，桌面聊天和摘要通过门面立即取得它；此前仅因模型缺失而未就绪的 Wiki LLM 工作，在其它依赖满足且功能已启用时通过现有调度器恢复。

避免在保存提交之后才进行可能失败的模型初始化。后台服务应在启动时具备等待模型可用的状态，或在候选准备阶段完成必需的本地准备；不得在提交区执行 worker 启动或 MCP 网络连接。启动期间与模型无关的依赖失败继续显示各自降级原因，不能宣称“填写密钥修复所有服务”。

清空有效密钥发布 unavailable 版本并停止接收新的 LLM 工作，已有租约继续按现有取消和超时规则完成。新密钥得到远端 401、限流或网络错误属于该版本调用失败，不自动回退旧供应商。用户可修改配置重试。

### 6. 保存状态与有效配置接口

保留现有保存端点和兼容字段，在成功结果中新增 revision、llmRevision、application。application 至少包含 LLM 及发生差异的其它组件：

| 字段 | 含义 |
|------|------|
| status | applied、draining、restart_required、unavailable |
| changedKeys | 影响该组件的有效配置键，不包含值 |
| message | 可本地化的用户提示码及必要参数 |
| activeWorkCount | 仍采用旧版本的工作数量，仅在适用时提供 |

draining 表示新工作已采用新版本、旧工作尚未结束，不表示新配置仍在等待应用。LLM 有效参数没有变化时保持当前状态。不可用是可保存的配置状态；候选准备或保存失败返回错误及 saved=false，不生成成功应用结果。

新增 GET /desktop/config/effective，返回当前进程标识、保存 revision、按键的已保存有效值与来源、LLM 默认版本及旧版本工作数、运行中组件的有效值及待重启差异。对敏感键只返回掩码和是否设置，内部比较真实值但绝不输出散列、真实密钥或底层认证请求。

该读取应基于当前文件解析已保存配置；运行组件继续返回真实已应用快照。外部编辑文件后可展示差异，但不自动发布模型。打开编辑器时及保存后刷新；有 draining 状态时做有限状态刷新，结束后停止轮询。raw 编辑仍使用原文，不把脱敏响应写回文件。

重启策略统一声明到后端配置元数据中。差异比较使用最新保存值与组件实际运行值，保证重复保存仍提示未应用的值，改回当前值后清除提示。对 Embedding 的继承密钥差异明确提示对应组件，而不是把已热更新的整个 LLM 标为需重启。

### 7. 连接测试沿用解析规则，不改变运行版本

连接测试保留显式请求参数优先的兼容约定，未提供参数时采用当前保存配置。编辑器当前文本的解析与后端配置语义对齐；应优先把待测 TOML 交由后端解析，保留旧客户端参数请求入口。显式空值与省略值不能混淆，未保存的测试不能写盘、增加运行版本或替换实际模型。

本期维持 /models 和现有 Embedding 测试方式，界面避免把测试成功解释为所选模型已完成聊天或运行配置已应用。

## Risks / Trade-offs

- SDK 对共享资源的关闭语义不明确 → 实施前用组件测试确认所有权，并将版本资源释放限定于明确拥有的资源。
- 工具内保存造成锁反转 → 保存从不取得聊天 gate；用包含配置工具调用的完整轮次测试验证。
- 保存时只改 LLM 却带入 pending 启动配置 → 候选从实际运行基线构造，仅替换五项热更新参数；覆盖混合提交回归测试。
- 长任务使旧客户端释放延后 → 沿用当前取消与超时，展示旧版本工作数量，测试异常和取消路径。
- 公开来源信息导致密钥泄露 → raw 维持原认证边界，其余接口和日志统一脱敏；假密钥回归测试扫描响应。
- 配置修改不会重算已存摘要 → 新任务才使用新模型；既有 Wiki、摘要快照和会话历史不因配置变化自动重生成。
- 配置准备期间保存耗时 → 不执行远端测试，限制为本地构建；保持编辑器保存中状态并禁止重复提交。
- 系统在文件替换后崩溃 → 下次启动从磁盘配置恢复，保留现有文件耐久性边界，不引入配置历史。

## Migration Plan

1. 先统一解析与后端配置生效元数据，再引入运行版本管理和统一保存服务；配置键、文件路径及存储内容格式保持不变。
2. 迁移控制器、ConfigTools、摘要、Wiki 与首次启动降级路径；接入新状态接口并保留旧响应字段。
3. 运行增量规格对应回归测试，必要时完成应用模块全部测试；确认 UI 提示、旧客户端兼容和中英文文案。
4. 同步相关主规格、README 与架构说明，验证并归档 change。部署新构建时按正常应用升级启动，此后的五项 LLM 参数更改无需重启。
5. 若需要退回旧应用构建，用户配置文件仍可读取；旧构建恢复原有重启生效语义，不自动修改、回滚或删除用户文件。

## Open Questions
