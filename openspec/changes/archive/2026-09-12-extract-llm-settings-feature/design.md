## Context

动机见 proposal.md。当前 `desktop-ui/config.js` 展示原文编辑器，`DesktopConfigController` 同时承担通用配置、原文保存和连接检查。运行参数由 `LlmSettings` 描述，`ConfigApplicationService` 统一协调保存，`LlmRuntimeManager` 已实现新工作切换、旧租约释放。`ConfigApplicationService.update` 会整文件重生成，且把空值当作删除，因此不能直接承载本功能的注释保真和显式清空语义。

`menu-harness/frontend/src/agent/settings.ts` 及其样式提供连接表单、模型发现、密码不回显和过期响应隔离的参考；其 Provider CRUD、数据库及多协议运行接口不适用于本期单连接模型。按本仓库的原生 JS 和语言资源方式实现，不从参考项目导入业务 API、真实配置或外部开源客户端代码。

现行 `user-configuration` 中 SPEC-CFGUI-UI-001..005 禁止结构化表单，SPEC-TOML-UI-001..004 要求直接呈现原文；本 change 明确修改这两条契约并补充专用保存例外。Agent 运行协议、低温摘要、预算及热更新契约不变，无需修改 agent-runtime 规格。

## Goals / Non-Goals

**目标：**

- 形成可独立测试的模型设置边界，让界面只依赖模型设置 DTO，让存储和运行应用接入现有设施。
- 为不同前端复用保留 HTTP 契约，使后续存储替换能够集中在适配器内完成。
- 为普通表单建立局部更新和只写凭据语义，同时保持高级原文可编辑。

**非目标：**

- 本期不发布通用组件包，不建立共享服务或新 Maven 模块。跨项目共享的打包、主题 API 和版本发布需要后续独立变更。
- 不把模型设置模块变成推理代理；业务请求继续由原有 Agent/摘要运行资源处理。
- 不改变旧通用结构化端点、ConfigTools 的空值删除语义，也不改变旧 raw 连接检查的兼容含义。

## Decisions

### 1. 应用内功能包与宿主适配器

新增 `com.selfanalyst.llm.settings`，包含设置服务、请求/响应 DTO、预设目录、探测器和存储接口。`LlmSettingsRepository` 的 TOML 适配器调用统一配置服务；继续复用既有 `LlmSettings` 作为运行值对象，避免复制数值校验规则。`CredentialState` 与包含密钥的内部连接对象分离，后者禁止自动生成含明文的日志表示。

桌面控制器只负责认证边界内的请求解析、调用服务及本地化错误。运行发布仍由配置服务已有的 prepare/publish 接口连接 `LlmRuntimeManager`，不额外建立第二套 RuntimeApplier 生命周期或提交锁。前端使用独立 `llm-settings.js`、`llm-settings.css`；提供加载、脏态检查、放弃及销毁入口，由配置窗口宿主管理页签和关闭。

选择包级边界的原因是当前只有应用消费该功能。独立 Maven 工程或网关会增加依赖与部署成本；直接把表单加入通用 config.js 又会保留当前耦合。

### 2. 查询、局部保存与凭据契约

| 方法与路径 | 请求/响应要点 |
|---|---|
| `GET /desktop/llm-settings` | `protocol` 固定为 `openai-completions`；非敏感字段分别含 effectiveValue、savedValue、source；`credential` 只含 configured、source、hasUserOverride；运行信息沿用版本和 application 结果，但不透传原有含密钥掩码的 configured/running map |
| `PUT /desktop/llm-settings` | `{updates: {baseUrl?, model?, temperature?, maxTokens?}, reset: [字段名], credential: {action, value?}}`；返回 saved、版本、组件结果及重新读取的脱敏设置快照 |
| `GET /desktop/llm-settings/presets` | 返回 id、显示名称、本地化提示及 baseUrl；自定义项不强行填入远端地址 |
| `POST /desktop/llm-settings/discover-models` | 草稿 baseUrl、credential；返回 ok、code、models、latencyMs、truncated |
| `POST /desktop/llm-settings/test` | 草稿 baseUrl、model、credential；返回 ok、code、latencyMs；不返回生成内容 |

`updates` 和 `reset` 不能包含同一字段；未知字段和错误类型返回 400。省略字段保持当前文件的覆盖关系，前端只提交实际编辑字段。reset 删除对应 TOML 赋值，允许恢复环境变量或默认值。界面展示来源并提供恢复继承操作，避免把有效值全部固化为用户覆盖。

凭据 action 采用 keep/replace/clear/reset。replace 要求非空值；clear 产生 `llm.api-key = ""`；reset 删除该键。空白密码输入在前端映射 keep；后端不接受 replace 空值，也不把任何掩码作为占位协议。新入口无凭据时可保存为未配置，供后续补填。

表单初次加载不请求 raw API，关闭和保存成功即清理密码字段。旧 raw API 仍按原规格给已认证用户显示完整原文；本功能不宣称密钥已加密存储。使用已有正式语言资源维护页面和后端错误文本。

### 3. 锁内定向 TOML 更新

在 `ConfigApplicationService` 增加受限的定向变更入口：取得现有提交锁后，读取最新原文并严格解析，生成目标字段 edit，再交给原有 commit。读取失败或原文非法时直接失败，不能借 `loadUser` 的容错空集合覆盖文件。远端探测绝不持有提交锁。

新增可测试的 TOML 原文编辑辅助器。利用解析器定位信息结合受限词法扫描确定赋值的键、值及注释边界，支持表内、顶层点分键、引号键以及普通单行标量。更新仅替换值区间；删除覆盖时移除赋值并保留独立/行尾注释。多处编辑按偏移倒序应用。缺失项优先写入已有合法 `[llm]` 表；无法插入时采用经完整解析验证的不冲突位置。未知配置与非目标多行内容原样保留，不按行粗略解析整份 TOML。

对目标的多行复杂表示或不能证明安全的插入位置，返回 `unsupported_toml_edit` 并指引高级编辑，不退回整文件重生成。候选文本再次解析，比较变更前后的 flat map：差异必须严格等于请求，非目标值必须一致。随后复用类型、模型、文件过滤、raw 设置及候选运行资源校验。仅更新值不会修改对应行尾注释；恢复继承时保留注释但不保留被删除的赋值。

该方案比调用旧结构化 update 多一个原文编辑层，但避免用户仅调整模型就丢失整份注释。比浏览器编辑 raw 更容易测试，也避免模型页面获得全部配置密钥。

### 4. 并发与草稿协调

沿用同进程提交锁，定向更新总在锁内读取最新文本。因此其它入口先提交的无关键不会被旧表单覆盖。同一 LLM 字段的并发更新保持后提交者生效；本期不增加乐观锁或跨进程事务，不把进程内 revision 描述为外部编辑冲突检测。

配置窗口一次只保留一个可编辑视图。模型设置为默认页签，高级配置为原文页签；切换时有脏态则询问放弃或取消。确认放弃后销毁草稿、取消探测，再读取目标视图；需要保存时用户取消切换后自行保存。保存进行中禁用字段、切换及关闭，防止响应改变已离开的视图。原文保存规则不变。

运行状态刷新只更新只读区域。模型发现与测试各有 AbortController 和请求代次；地址、密钥或模型等相关参数改变时取消旧请求并使结果失效。密码变化、失败响应或校验提示不触发全表单重绘。旧配置键定位入口直接选中高级页签并遵守同样的草稿确认。

### 5. 预设、模型发现和生成测试

预设仅包含连接地址，沿用参考项目当前的 OpenAI、DeepSeek、OpenRouter、自定义 OpenAI-compatible 选项；实现时核对官方地址，不复制快速变动的模型能力数值。保存不持久化 preset ID，重新打开时依据规范化地址匹配预设，否则显示自定义。预设不触发网络请求，用户手工模型永远可用。

发现请求 `GET {baseUrl}/models`，只解析 `data[].id`，过滤空白/非字符串/超长 ID 并去重，最多返回 500 条、单 ID 最长 256 字符。响应读取上限为 1 MiB，不能先完整缓存再截断。发现不判断模型是否为聊天模型，生成测试才验证所选模型。

新生成测试发送固定 `user: "Reply OK."`、`stream: false` 和小输出上限（16 tokens）的 Chat Completions 请求，不带业务温度、会话或工具，不自动重试或回退供应商。测试上限用于探测，不更改用户 maxTokens。不同模型可能不支持该探测参数，此时返回受限的参数不兼容分类，不能错误声称凭据一定无效。验证协议结构及非空文本结果；不展示或存储生成正文。测试是显式的连接诊断，不进入 Agent/摘要工作计量流水，界面提前提示供应商可能计费。

探测使用 Java HTTP 客户端，连接超时 10 秒、单请求总时限 15 秒、禁止重定向。网络慢响应也受总时限约束，超过上限及时关闭响应流。错误分类包含未配置、认证失败、权限不足、模型不存在、限流、超时、网络失败、协议响应无效、参数不兼容、响应超限和目录不支持；不透传任意响应正文或可能含 URL/密钥的底层异常。

keep 探测只允许规范化基础地址与当前已保存有效地址相同；变更地址需在密码框明确重新输入目标密钥。允许用户主动指定本地 HTTP 兼容服务，不把普通 localhost 地址当作错误。旧目录检查端点行为保持兼容，原文视图文案标明其仅检查目录连接。

### 6. 生效状态与宿主运行边界

保存后复用原有 SaveResult 及 application 状态，并以重新查询后的值更新前端基准。当前工作继续持有旧租约，新工作采用新配置；低温摘要策略不受表单温度改变影响。Embedding 继承密钥变化继续显示需重启，其它原来未启用的功能不被模型保存激活。

测试成功只属于当前草稿，保存成功只证明配置提交完成。界面分别显示这两种状态；后台可用性探测与配置状态不混用。初次凭据补填不需要重启，但不把本地资源成功构造当作远端必然可调用。

## Risks / Trade-offs

- [TOML 目标定位损坏原文] → 使用严格解析与候选语义差异校验，覆盖 CRLF、引号、注释及复杂语法；不能证明安全则拒绝并保留高级入口。
- [新 DTO 意外包含密钥] → 响应采用明确字段投影，禁止直接序列化运行值对象；测试检查查询、失败和日志均不含密钥与摘要。
- [目录可用不代表生成可用] → 独立显示发现与测试结果，失败仍允许手工模型和本地保存。
- [同字段并发编辑覆盖] → 文档明确后提交者生效，仅发送局部更新；不在本期引入新的并发协议。
- [参考界面依赖较重] → 只迁移布局与交互意图，沿用本项目 CSS 变量、原生 JS、认证 API 和国际化。
- [最小生成会计费且部分模型不兼容] → 用户主动点击、有事前提示、无重试、输出受限，返回准确的失败类别。

## Migration Plan

1. 在现有应用内增加模块、专用接口与测试，再接入配置窗口页签。旧五个配置键、文件路径及加载优先级保持有效，无数据迁移脚本，也不修改真实用户配置。
2. 验证原文入口、结构化兼容入口、Agent 配置工具及新入口共用一次提交协调。用本地 HTTP 测试服务验证探测，不在自动化测试中使用真实密钥或付费请求。
3. 更新架构与用户配置说明，严格验证并同步两个主规格。仅在实施、测试及同步完成后归档 change。
4. 如果需撤销实现，通过功能分支恢复界面和接口代码；配置仍是旧版本可识别的五个键。回退不恢复旧密钥、不自动重写用户文件，也不引入配置历史。
