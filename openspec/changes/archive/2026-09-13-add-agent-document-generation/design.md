## Context

动机与格式范围见 proposal.md。`SelfAnalystAgent` 使用串行 Toolkit 和应用级聊天 gate；`ChatSessionStore` 以 chat.db 保存 UI 权威状态，消息正文存在 20,000 code point 上限。`DesktopAgentController` 输出文本流与 canonical 结果，文件不能作为大段正文或 base64 附带。桌面有受管 WebView 和系统浏览器两个入口，分别使用 token header 与会话 cookie。

原始事件已经有独立 `RawEventQueryService` 和受保护查询契约，区别于合并 heartbeat 的事件投影。现行 SPEC-RAW-006 禁止 Agent 逐条查询 raw；本变更仅开放后台文件导出，模型仍不能读取 raw 正文。需同步该条规格，不能借用派生导出宣称支持原始数据。

## Goals / Non-Goals

**Goals:**
- 在 JVM 内完成确定性格式生成，Agent 只选择内容、结构和查询条件。
- 使文件发布、会话关联、取消和崩溃恢复具有明确的一致性规则。
- 用户另存副本与应用内版本分别管理，桌面保存对话框成为目标目录选择入口。

**Non-Goals:**
- 不提供 shell/Python 执行、任意 SQL、任意路径读写或第三方远程转换服务。
- 不在第一版实现图表编辑器、外部图片抓取、动画、宏、模板上传或 Office 文档导入。基础图表可后续扩展；本期 PPT 以可编辑文本和表格为验收基线。
- 不承诺不同 Office 阅读器完全相同的像素布局；PDF 作为固定排版格式独立生成，不要求与 DOCX/PPTX 逐像素一致。

## Decisions

### 1. 两种输入，共用文档服务

在 `self-analyst-app` 新增 `com.selfanalyst.document`，暂不增加 Maven 模块。文档服务提供生成、读取元数据、读取有界生成源和清理能力。AppSession 创建 DesktopServer；文档服务在 DesktopServer 创建会话 writer 后初始化，再注入 Agent 及桌面控制器，避免重复打开 chat.db。

- `generate_document` 接受格式、标题和有版本 schema 的结构化内容。报告结构包含 section/paragraph/list/table，演示包含 slide/title/body/table，工作簿包含 sheets/columns/rows。字段类型与每格式支持范围校验后再渲染；JSON/Markdown 输出遵循同一数据结构的确定性转换。
- `export_data` 接受来源、bucket 或受控实体、时间窗、字段和过滤条件。raw、projection、file-metadata、wiki 分别走类型化适配器，不执行模型 SQL/AQL 文本。原始数据导出可使用七格式，Word/PDF/PPT 按表格分页；超预算时建议 CSV/JSON/XLSX 或缩小范围，不能静默抽样。
- `read_document_source` 允许读取本会话报告的结构化生成源以修改；数据导出只返回查询描述，不返回导出记录。原始文件下载为用户界面专用通道，不作为模型工具。
- `list_documents` 返回当前会话的分页简要成果列表，让历史上下文已压缩时仍可按文件名定位版本；不返回正文或原始数据。

不以自由 Markdown 作为所有格式唯一输入，避免 PPT 分页及工作簿类型信息丢失；也不让模型输出 Office 二进制或可执行代码。输入 schema 由工具说明公开，格式不支持时返回可修正的错误。

### 2. 受控数据获取与一致性

原始导出复用原始服务健康、分页、覆盖与认证策略，经受管内部调用适配器获取，不向模型暴露 token。投影复用事件服务查询边界，Wiki/File 复用已有查询服务。原始调用的身份由受认证聊天请求建立，不能仅以“后端配置了 token”代替请求认证。

导出开始固定时间条件和数据边界：raw 为各分区固定接收序列高水位，使用稳定键分页排除后来到达的记录；投影、Wiki 和元数据使用有界只读快照或先在读取事务内逐页写入受管临时数据集。若现有查询未提供高水位，给内部导出适配器增加这一能力，不改变普通查询返回语义。长事务设置时限，避免导出长期阻塞采集。

数据集持久保存来源、条件、时区、生成时间、覆盖和记录数。JSON 使用 metadata/records 结构；XLSX 使用说明工作表与数据工作表；DOCX/PDF/Markdown/PPTX 使用说明段或说明页。CSV 保持普通表头数据行，元数据位于成果详情，不插入干扰解析的注释行。

CSV 对不可信公式前缀进行转义，说明其为电子表格安全展示格式；JSON 保留忠实字段类型及原值。原始结果中嵌套 data 在表格格式中保留为 JSON 字符串，除非用户明确选择展开字段。

### 3. 本地渲染和布局

Office 使用 Apache POI 的 XWPF、XSSF/SXSSF、XSLF；其组件覆盖 DOCX、XLSX、PPTX，SXSSF 提供大表写入方式，见 [POI 组件说明](https://poi.apache.org/components/) 和 [官方介绍](https://poi.apache.org/)。PDF 采用 PDFBox 配合本项目有限的标题、段落、列表与表格排版器；字体嵌入与编码注意事项参考 [PDFBox 官方 FAQ](https://pdfbox.apache.org/3.0/faq.html)。这只是基础文件生成能力，不将库支持格式等同于自动优质排版。

渲染器负责中文断行、单元格换行、表头重复、页边距和页码；PPT 使用固定 16:9 简洁主题，按文字测量和可用高度拆页，标题/正文/表格使用原生对象。PDF 随包携带经许可检查的中文字体并嵌入所用字形，Office 设置中英文字体及备用字体。不依赖用户安装 Office 或额外运行时；不调用任意 HTML/外链渲染。

实施先以中文长段落、宽表、跨页表、特殊字符和 PPT 溢出样例验证依赖及布局，再整合业务。确切依赖版本和字体文件在该验证任务中锁定并记录许可；若候选不能满足规格，更新设计后替换渲染适配器。

### 4. 元数据、版本及发布协议

chat.db 增加 document_jobs 和 document_artifacts 表，复用 writer lease 与事务协调；文件及生成源位于 `memoryDir/documents/<sessionId>/<artifactId>/`。目录全部由服务端标识派生，用户标题仅用作净化后的下载名。

job 保存状态、sessionId、userMessageId、规范化请求摘要和错误码；artifact 保存系列 ID、版本号、可选 parentArtifactId、名称、格式、字节数、内容校验值、来源元数据及生成源相对标识。原始缓存不放入 chat.db，不进入模型历史或日志。文档元数据通过会话独立成果列表返回，避免消息裁剪导致文件失联；用户轮次标识为保留的来源标记，不随消息外键级联删除。

同一轮次的规范化请求摘要包含格式、内容或查询以及父版本；唯一约束防止同请求重复发布。新轮次请求形成新版本；失败请求重试复用逻辑 job，重新写临时文件。版本号在发布事务中分配。

发布顺序：记录 RUNNING → 写受管临时文件及生成源 → 关闭并检查格式/大小 → 同卷移动为最终受管文件 → 在事务中发布 READY artifact。只有 READY 可下载。移动后事务失败的文件为孤儿，恢复时清理；READY 缺失或校验不符标记不可用，不提供损坏内容。启动将遗留 RUNNING 标记失败并清理临时文件。取消与最终发布在同一协调点排序：取消先到则不发布，发布先到则保留成果。

会话删除 intent 同时撤销文档访问，后续幂等清理目录与表记录；下载持有短读取租约，删除可以等待读取结束，关闭句柄后继续清理。绝不删除用户另存路径。会话内文件不自动过期；容量超限要求删除不再需要的会话或减少导出量。

### 5. API、Agent 与界面

新增 `GET /desktop/chat/sessions/{sessionId}/documents`、`GET /desktop/chat/sessions/{sessionId}/documents/{artifactId}` 和对应 `/content`。列表分页，服务端固定页大小上限；生成状态通过该列表读取，前端仅在生成期间短轮询并在流结束后刷新，复用请求代次防止会话串写。content 仅允许 READY，设置 attachment、正确 MIME、UTF-8 文件名、no-store 和 nosniff，不把 token 放到 URL。

前端在读取会话后独立获取该会话的有界文档列表，不增加正文读取和消息存储的体积，也不给已有消息 mutation 开放写附件权限。工具结果仅携带 job/artifact 标识及简短元数据；最终聊天回答无文本仍遵守现有错误处理，但文件卡片独立显示。

服务使用显式不可变执行上下文携带 sessionId/userMessageId/受管认证状态，不能依赖可能跨 Reactor 线程失效的裸 ThreadLocal。文档工具继续串行，渲染和数据读取在有界工作线程执行，聊天 gate 在工具工作结束前不释放。纯渲染不记 LLM token；内容组织沿用既有计量。

### 6. 原生保存和浏览器下载

Tauri 增加窄接口保存命令，前端只传 sessionId/artifactId。Rust 从受管后端元数据获取建议文件名，使用原生文件对话框选目标，再以内部已知端口和 token 流式读取 content。禁止前端指定下载 URL、源文件路径或无需对话框的目标路径，拒绝重定向；命令仅允许既有受信任桌面窗口和本次受管 origin。

目标同目录创建临时文件，校验长度/摘要并关闭后完成替换；目标存在时要求覆盖确认，确认后目标若被另一个程序更改则重新确认或失败。Windows 使用支持保留旧文件的替换机制，不能先删除目标再移动；非原子替换不可用时明确失败。路径比较拒绝覆盖受管数据库、原始数据、文档源或程序资源。取消对话框无写入，失败清理本次临时文件并保留目标。

浏览器使用相同 content 接口和已建立 cookie，以普通附件下载避免把整个大文件载入 JS 内存。下载位置由浏览器管理；页面仅报告“已发起下载”。WebView 使用原生命令，不依赖普通链接能注入 token header。

### 7. 初始资源预算

以下为可在性能验证后调整的内部默认值，调整不能取消有界和不截断契约：结构化源 1 MiB、JSON 深度 32；直接数据导出 100,000 条、64 列；报告/PDF 200 页、PPT 100 页；单成果 50 MiB；单次生成 120 秒并服从更早的聊天取消/超时；受管成果累计 1 GiB，临时空间同步计入。数据源本身更严格的查询上限优先，不自动拆时间窗绕过限制。

限制作为工具能力说明和错误详情提供；写入每页/块检查累计字节、时间与取消状态。达到总量上限不自动删除旧文件。禁止模型生成公式、宏和外部资源；不可信文字采用格式内安全文本编码。

## Risks / Trade-offs

- 中文字体及长表格容易造成布局差异 → 先做格式样例和视觉检查，PDF 嵌入字体，PPT 自动拆页；结构可解析不能替代视觉验收。
- 文件系统和 SQLite 不能共同提交 → READY 发布协议、孤儿清理及故障注入测试覆盖每个断点。
- raw 高水位和派生快照增加查询复杂度 → 分数据源验证导出期间持续采集不重不漏；快照失败明确失败，不降为不一致结果。
- 同步工具占用聊天 gate → 第一版设置时间与大小预算；持久任务仅用于恢复状态，不引入脱离当前轮次的后台调度。
- 受管文件长期占空间 → 总预算、失败清理和会话删除控制；已另存副本不计入应用预算。
- 新依赖和字体扩大安装包 → 检查许可、打包资源和精简 JRE 所需模块，并在无 Office 的环境验证。

## Migration Plan

桌面验收可使用仅显式启用的 `document-review` 构建特性，把单实例命名空间隔离为验收实例；其余后端启动、认证、会话和保存命令共用生产路径。验收使用独立目录、关闭采集和本地模拟模型，不关闭用户已运行的实例。正式发行构建不启用该特性。

1. 在功能分支实施；先完成渲染验证，再增加兼容的数据库表及受管目录，不改写已有正文。
2. 新会话响应字段为增量字段，旧会话返回空成果；文档源带 schemaVersion，未来不兼容版本明确不可修改但保留已生成文件下载。
3. 整合工具、API、两种消息面与原生保存；通过针对性测试、全量测试、安装/便携包验证后同步主规格及中文指南。
4. 回退时使用受支持的应用版本回退或备份恢复，不自动删除新增文档目录；实施需验证旧版本的数据库版本检查，若旧版本拒绝升级数据库，明确需恢复升级前备份。外部另存副本不参与回退。
