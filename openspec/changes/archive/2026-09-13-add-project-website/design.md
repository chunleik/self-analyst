## Context

动机见 proposal.md。现有桌面界面依赖受保护的本地 Java API，不能直接作为公共官网发布；仓库已有 Windows Release 工作流和产品截图。官网语言要求独立于桌面应用的 internationalization 规格。双语路由、静态托管子路径和发布边界需要在实施前明确，因此保留设计文档。

## Goals / Non-Goals

**Goals:**
- 提供无需后端和安装构建依赖即可预览的静态产品官网。
- 保持双语内容等价，兼顾直接分享、搜索引擎和禁用脚本时的可用性。
- 复用现有版本发布机制，并让官网资源与应用资源隔离。

**Non-Goals:**
- 不提供在线应用、账号、支付、云端采集、自动更新服务或官网统计追踪。
- 不修改桌面语言策略、现有 Release 打包流程或引入自定义域名。

## Decisions

### 独立静态目录

使用 `website/` 中的 HTML、共享 CSS 和少量 JavaScript，发布目录内资源。与直接发布 `docs/` 或桌面 UI 相比，目录范围清楚，不会暴露内部探索文档，也不依赖桌面认证。首版采用单页分区的产品官网，包含首屏、功能、截图、下载、快速开始和隐私区；采用清晰排版、足够留白和响应式布局，截图只展示已经核对的公开内容。

### 两份完整语言页面

使用 `website/zh-CN/index.html` 与 `website/en/index.html`，根入口提供自动选择及无脚本时的双语链接。显式路径优先；根入口读取有效的 localStorage 偏好，否则依据浏览器首选语言的 `zh` 前缀选择简体中文，其他选择英文。存储读写捕获失败；切换使用真实链接。页面声明正确的 lang、标题及描述，使用相对资源路径。相比纯 JavaScript 替换整页文案，此方案保留无脚本正文并允许语言链接直接分享；用结构和入口检查防止双语遗漏。

### 下载链接保持稳定

主按钮使用 `https://github.com/chunleik/self-analyst/releases/latest`，旁边提供 `/releases` 全部版本。说明安装包与便携包的差异，按钮明确为前往 Releases 选择下载，不伪装为直接文件下载。首版不调用 Releases API，也不写死版本号或资产文件名，以避免限流和命名变化。实施前验证公开正式 Release 是否存在；不存在时使用全部版本页并明确尚无正式下载，不制造失效的直接下载入口。

### 内容依据与语言范围

以当前 README、PRIVACY.md、desktop-shell 及相关采集规格核对文案；两种语言均明确可选模型服务的数据发送。模型配置说明链接现有使用指南，外部文档只有中文时标注语言。官网正文英文是用户授权例外，维护说明和 OpenSpec 文档仍为简体中文。

### GitHub Pages 发布

新增专用 Actions 工作流，在 main 的官网相关变更后及手动触发时上传官网目录并部署到 github-pages 环境。PR 执行官网检查，不部署；部署任务仅允许 main。实施时核对 GitHub 官方当前推荐的 Pages Actions 版本与权限，仅给予所需的 contents 读取、pages 写入和 id-token 写入权限，并限制部署并发。仓库 Pages 来源设置为 GitHub Actions；默认 URL 为 `https://chunleik.github.io/self-analyst/`，上线前不声称该地址已可用。

## Risks / Trade-offs

- 双份 HTML 文案可能漂移 → 检查两种语言的分区、入口和隐私事实，并同步维护。
- 已有截图可能包含个人信息或旧界面 → 实施时视觉核查，必要时改用明确标注的示例素材。
- GitHub Releases 不随官网语言切换 → 官网提供完整双语下载说明并明确跳转目的地。
- Pages 设置或仓库权限未就绪 → 本地预览和 PR 检查先完成，记录发布阻塞，不把工作流成功前的状态当作上线。
- 浏览器拒绝存储或脚本 → 真实语言路径和普通链接保证核心内容可用。

## Migration Plan

在功能分支完成官网、验证和主规格同步，经 PR 最新提交的必需检查（含 Windows 全量验证）通过后按授权合并，再启用或确认 Pages 并验证公开 URL。上线失败时回滚官网相关提交或重新部署前一版静态产物；无需迁移应用数据。保留工作区既有 docs/README.md、docs/explorations/ 和其他无关变更。
