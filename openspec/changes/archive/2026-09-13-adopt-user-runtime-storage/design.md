## Context

动机见 [proposal.md](proposal.md)。当前桌面壳已分离安装版资源目录与工作目录，但免安装版将 EXE 目录同时作为工作目录；Java 配置以 `./data/config/config.toml` 为入口。`AppSession` 构造期间即初始化用量、事件、记忆和索引存储，守卫必须早于这些操作。桌面壳另有 Windows 单实例 mutex，本次保留其唤起窗口语义。

## Goals / Non-Goals

**Goals:** 以一个稳定运行根承载默认数据布局；所有正式 Java 启动入口在业务存储开放前完成独占及格式准入；错误可被桌面壳解释。

**Non-Goals:** 不迁移旧目录或升级旧格式，不替换桌面壳 mutex，不保证多个桌面实例同时运行，不改造外部事件服务，不建立网络文件系统或跨机器互斥协议，不增加备份工具或运行中切换目录。

## Decisions

### 1. 分离分发根、运行根和数据根

- 分发根继续按安装布局标记解析 JAR/runtime，不能受工作目录改变影响。
- 默认运行根继续使用 Tauri `app_local_data_dir()` 和现有稳定 identifier `com.selfanalyst.desktop`；Windows 对应 `%LOCALAPPDATA%/com.selfanalyst.desktop`，不拼接版本号。此处复用现有安装版路径，不另创第二份用户目录。
- 非安装分发只有 EXE 同级普通文件 `portable.marker` 存在时选择 EXE 目录作为运行根；不按旧 `data/` 存在与否推断模式。安装布局优先，忽略其旁边的便携标记；标记无法检查或目录不可写时报告失败，不静默换位置。
- 数据根为运行根的 `data/`，默认配置和业务数据保留现有相对布局；后端日志在运行根，握手文件仍在系统临时目录。启动诊断可先于数据准入写入，但不能写到数据根内。壳引导日志保留现行用户目录位置，因此显式便携不是“完全不留系统痕迹”。
- 直接运行 JAR 保留调用者工作目录语义，统一执行数据守卫，不擅自重定向用户目录。开发和测试需使用独立临时运行根。

替代方案是所有 Java 路径改为绝对路径或按程序版本分目录；前者扩大本次变更，后者割裂历史数据，因此不采用。

### 2. Java 独占守卫

使用 Java 21 `FileChannel.tryLock()` 获取 `data/app.lock` 独占锁，守卫持有唯一通道至所有业务资源停止。路径创建后使用真实规范路径识别数据根，锁文件不得是符号链接；正常退出不删除、不替换锁文件，避免其他实例锁住不同文件对象。返回空结果或同 JVM 重叠锁异常视为占用，其他 I/O 异常归类为锁不可用，不降级启动。

Java 接口统一，底层仍是 OS 锁。协议要求所有参与实例先锁后用，不宣称能禁止不遵守协议的程序修改数据。参见 [Java 21 FileLock](https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/nio/channels/FileLock.html) 和 [FileChannel](https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/nio/channels/FileChannel.html)。不选择 PID、心跳或原子目录方案，避免残留和超时误判；也不选择端口占用，避免把数据身份映射到端口。

守卫位于生产会话创建边界，不能只保护 Tauri 路径。测试可显式传入临时数据根，但不能通过生产开关跳过守卫。正常关闭先停工作线程、采集与 HTTP，再关闭数据库，最后释放锁。关闭流程必须幂等；构造部分失败要关闭已创建资源后再释放锁。若不能确认资源已停止，保持锁直至进程终止，不能释放后继续驻留。

实施核对发现部分既有 shutdown 使用有界等待而未保证线程已终止，因此生产会话保守持锁至 JVM 退出。进程内强引用保留锁句柄，构造部分失败后尝试清理，入口最终终止进程；普通退出同样显式终止 JVM。基础守卫的显式关闭能力用于独立生命周期测试，不提供生产无锁开关。

### 3. 格式标记、首次初始化与旧数据原地接纳

采用 `data/storage-format.json`，内容为 `{"formatVersion":1}`；本次读写仅接受整数 1。版本号表示受管数据集合的兼容契约，与应用发布版本分开。任何不兼容存储变动都必须重新评估该号；普通版本升级不自动递增。

获取锁后再检查标记。标记缺失且数据根除 `app.lock` 和保留的 `storage-format.json.tmp` 外没有任何条目时，可以初始化。已有配置、数据库或空业务子目录时进入只读兼容检查，不因“非空且无标记”直接拒绝。正式标记存在但无效时仍拒绝启动，不能按无标记旧数据覆盖它。

兼容检查以当前变更实施前的实际存储结构为基线：盘点受管配置、数据库、事件文件和索引的布局及可读取的结构/版本元数据，逐类建立识别规则与脱敏测试夹具。不能仅凭文件名、目录名或数据库可打开就判为兼容。允许已识别的空业务目录、合法空配置及尚未启用的缺失可选存储；已有存储必须逐项确认兼容，混合目录中任一存储不兼容、损坏、不可读或无法识别均拒绝，不能部分补标记。

检查器只读访问现有数据，不实例化会建表、迁移、清理、重建索引或恢复写入的业务存储。需要定位配置指定路径时，可在持锁后只读解析当前配置及路径覆盖项，但不启动配置应用服务、不持久化默认值；正常配置加载和运行仍在准入之后。数据库检查须包含现有日志状态且不得因探测触发恢复写入；无法无写入确认时拒绝并解释原因。根外有效存储若参与本次接纳也须只读检查，既有根外并发保护限制仍适用。

全部确认兼容后，原子补写格式 1 标记，再正常启动；这只登记已有格式，不是业务格式升级或位置迁移。检查阶段除锁文件及标记发布文件外，不新增、修改或删除业务文件。标记发布前中断时，下次重新执行完整检查；残留临时标记不构成已验证证据，只有新检查成功后才能替换它。

初始化先写同目录临时文件并强制刷盘，再原子发布正式标记，成功后才创建配置或业务目录；不支持原子移动时失败，不使用可能产生部分标记的替代发布方式。标记就绪但业务初始化中断时，下一次按相同格式继续正常初始化；不宣称这是数据库损坏修复或断电事务保障。

明确声明的格式过新、过旧、损坏、不可读，以及无标记且无法确认兼容，均拒绝业务存储开放，不强制覆盖版本、不删除旧数据。检查范围以受管数据根和本次接纳所需的有效存储为准；用户自定义到根外的 memory/events/index 路径保持现行语义，其独立共享或重叠不由根锁保证，用户文档明确禁止多个运行根共享这些写入位置。本次不增加外置路径多锁协调。

### 4. 启动失败和用户界面

顺序为：选择运行根 → 创建数据根并获取独占锁 → 检查已有标记，或对无标记旧数据只读确认兼容 → 原子初始化/补写所需标记 → 正常加载配置 → 初始化存储及服务 → 发布端口 → 展示界面。兼容检查需要的只读路径解析属于准入检查，不得触发业务初始化。

用稳定退出分类区分 `DATA_IN_USE`、`DATA_LOCK_UNAVAILABLE`、`DATA_FORMAT_UNSUPPORTED`、`DATA_FORMAT_INVALID` 和 `DATA_ROOT_UNAVAILABLE`，壳映射为本地化消息。无标记数据明确不兼容归类为格式不支持，无法识别或检查失败归类为格式无效，并给出可读原因。无端口发布时壳读取子进程退出结果，不把格式拒绝一律显示为超时，不探测或连接其他实例端口；直接 JAR 输出相同分类及可读原因。错误不包含配置值或密钥。

设置只读显示模式、运行根和数据根，并通过受信任 Tauri 命令打开当前已解析的数据目录；浏览器界面可显示路径但不冒充支持原生打开。命令不接受任意用户或模型传入路径，不加入运行中切换模式或目录编辑。备份入口另行设计。

### 5. 分发与现行规范协调

`build-portable.ps1` 当前预建数据目录和空 TOML，需要移除，让标准包只携带程序资源。标准 ZIP 不包含 `portable.marker`，说明如何手动创建该标记启用显式便携；选择包含旧数据的目录后执行原地兼容检查。审核 dist、installer 和冒烟脚本中的同类预置行为；旧包已生成的合法空配置和已识别空业务目录由兼容检查接纳。

构建输出目录已有 `data/` 时拒绝清理，允许通过 `-OutputDirectory` 指定新的工作区目录；安装包构建通过 `-DistributionPath` 复用该分发，避免验证过程删除用户已运行的 portable 数据。

更新桌面进程边界、构建条款及配置路径条款；保留配置优先级、动态端口、认证和桌面 mutex 原行为。独立数据根互不争抢数据锁，不等于解除现有桌面单实例限制。

## Risks / Trade-offs

- [旧程序不遵守新协议] → 无法拦住它们；文档明确禁止旧版与新版共享目录并发运行，不承诺能识别所有旧进程。
- [旧数据被误识别为兼容] → 逐类只读验证当前结构，覆盖混合格式与部分损坏；只有全部通过才补标记，不能要求用户手工伪造标记。已有安装版数据无需换目录，显式便携可原地接纳旧 portable 数据。
- [外置路径共享或网络盘锁语义不同] → 保证限于同一本地受管数据根和遵守协议的实例；根外共享不在本次保证范围，锁失败一律停止。
- [启动前创建日志造成“非空”误判] → 只检查 `data/`；打包、日志及框架初始化均需验证不提前向其中写入。
- [资源关闭期间释放锁过早] → 增加独立进程竞争和关闭顺序测试，部分构造失败也覆盖。
- [全局格式号遗漏变化] → 将兼容性评估纳入后续存储变更评审，禁止以更改标记绕过真实不兼容。

## Migration Plan

无数据位置迁移或业务格式升级步骤。实现后使用临时空目录及当前无标记格式的脱敏夹具验证默认/显式便携/直接 JAR 三条路径，再发布带默认目录变化说明的免安装包。选定目录的数据确认兼容后原地补标记；未选中的旧目录不读取、不搬运，已有不兼容数据明确失败并保留。

回退程序必须先停止新版，使用旧版自己的原始数据目录；不得用旧版打开新版数据，也不通过删除或降级标记实现回退。主规格同步和 change 归档只在实施与验证完成后执行。
