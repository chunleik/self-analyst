## Context

见 proposal.md。生产请求使用 localhost 和全局超时；旧测试仅监听 IPv4，50 毫秒预算可能在连接建立前耗尽。服务端无限 accept 与主线程 join 形成永久等待。

## Goals / Non-Goals

保证测试服务端每个等待都有期限，且超时断言确实覆盖收到认证请求后不返回响应。保持生产请求、依赖与 CI 作业时限不变。

## Decisions

- 使用非阻塞 accept 加截止时间轮询；连接建立后恢复阻塞并设置读写超时。按完整 HTTP 头读取，避免单次 TCP read 的分片假设。
- 成功握手与响应超时拆为独立测试。响应超时给予连接足够预算，服务端收到请求后通过有界通道等待客户端完成，禁止固定短 sleep 提前关闭连接造成假阳性。
- 新增没有客户端连接的回归测试，直接覆盖原无限 accept 的触发条件；保留父进程 watchdog 执行证据。
- 不通过延长 CI 作业时限或跳过测试解决问题。

## Risks / Trade-offs

慢机器仍可能无法及时建立连接 → 测试明确失败并收尾，而非将连接错误误报为响应超时通过。测试耗时增加数秒 → 用于扩大握手调度余量，避免毫秒级竞态。
