## Context

见 proposal.md。Tauri 将可执行路径 canonicalize 后用作安装资源根，Windows 返回 `\\?\` 路径。随包 Java 能读取该 JAR 的 manifest，却无法通过该路径加载主类；普通路径已通过真实后端冒烟。

## Goals / Non-Goals

修复 Java 参数边界，保留资源根与用户工作目录分离。不调整数据准入、不升级 Java、不迁移用户数据。

## Decisions

- 在启动参数边界转换 verbatim 磁盘路径和 UNC 路径，使用 Windows 原生字符串保留所有路径字符。普通路径保持不变；不对未知设备路径进行猜测转换。
- 不切换后端工作目录：工作目录属于用户数据根，切到安装目录会违反现有存储契约。不仅删除固定前缀：UNC 必须恢复双反斜杠。
- 使用 Rust 单元测试覆盖路径形式，并通过真实 Java 启动验证转换结果；安装包验证补充桌面壳启动链路，避免仅运行普通路径 JAR 的测试漏报。

## Risks / Trade-offs

- 超长路径在 Java 中另有兼容限制 → 此次保持等价绝对路径，不宣称扩展 Java 自身的路径长度支持。
- 安装测试可能影响本机已安装入口 → 本地使用解包到临时目录的安装资源与独立测试数据验证，不覆盖用户安装或配置。

## Migration Plan

构建本地修复安装包和校验文件，验证后交给用户安装；无需数据迁移。代码按功能分支保留，未经授权不合并或发布。
