## Context

背景见 proposal.md。CI 运行 `34814708221` 在热更新取消测试退出后报告 JUnit 临时目录非空。当前夹具自行创建 `UsageMeter` 并注入 Agent；Agent 的关闭仅收敛模型工作和关闭自身存储，计量器由外部所有者管理。计量器的异步落盘会创建 `usage/`、写临时文件并原子替换，因此遗漏清理可以与 JUnit 目录删除竞争。`SelfAnalystAgentOpenAiCompatibilityTest` 已有显式 `meter.flush()` 的清理范例。

## Goals / Non-Goals

**Goals:**

- 在夹具退出前完成用量持久化和后台资源释放。
- 通过可重复断言暴露遗漏清理，而非依赖 Windows 文件系统竞争出现的概率。

**Non-Goals:**

- 不将共享计量器所有权转移给 Agent，不修改生产关闭协议。
- 不关闭 JUnit 临时目录清理、不重试掩盖异常、不增加固定睡眠。

## Decisions

1. 在夹具中先关闭 Agent，使在途工作收敛，再调用 `meter.flush()`。使用 `finally` 保证 HTTP 服务与请求执行器清理不会因前一步异常而跳过；显式关闭并等待请求执行器结束。
2. 回归测试记录已知用量，关闭夹具后检查持久化计数和计量执行器终止状态。需要访问执行器时只采用测试侧反射，不增加生产接口；反射目标集中在一个测试辅助方法中。测试在旧清理逻辑下应稳定失败，在修复后通过，并在自身 `finally` 中兜底释放资源。
3. 继续使用 PR #38 的既有工作树 `.worktrees/readme-translation-clean`，保留 README 翻译；实施阶段同步最新 main，避免切换或覆盖主工作区的无关开发。
4. 不改变可观察业务契约，使用 CLI 支持的 `skip_specs: true`，不新增增量规格，也无需同步主规格。

## Risks / Trade-offs

- [CI 日志未列出残留子文件，尚未动态复现竞争] → 先让回归测试验证后台执行器未终止，再修改夹具；若不能证实，继续调查，不将推测表述为已验证根因。
- [现有 `flush()` 有两秒等待上限] → 回归验证执行器确实终止；本轮不扩大为生产持久化重构，若验证显示另有缺陷则先修订规划。
- [关闭逻辑异常导致后续资源泄漏] → 使用可靠的清理嵌套并保留原始异常，回归测试自身也兜底清理。
- [后台计量回调与测试返回存在时序差异] → 断言以已知计量完成和执行器生命周期为依据，不用睡眠等待日志或目录变化。

## Migration Plan

无需数据迁移。实施后依次运行回归测试、相关测试与完整 Maven 测试；更新 PR 说明，推送功能分支并确认最新提交的必需检查通过。回退可撤销独立测试修复提交。合并仍遵循用户授权。
