## Context

见 proposal.md。现有 smart 将推断和低置信候选放入 pending，confirm_all 全部待确认。用户已确认取消人工审批，并在会话内澄清错误记忆。

## Goals / Non-Goals

后台完成筛选、保存及历史待确认记录处理；会话承担用户纠错入口。保持本地存储、预算限制和原始采集数据边界，不提供新的管理页面。

## Decisions

- 移除面板渲染、专用查询、绑定和布局占位，保持后端提炼独立运行。
- smart 为默认自动筛选策略；confirm_all 作为兼容输入按 smart 执行，off 继续关闭自动提炼。新自动候选只保存合格 active，不产生 pending。
- 统一新旧记忆评估条件：明确长期价值、证据支持、confidence 至少 8、非敏感且无凭据。行为归纳可以评估，但不能仅凭旧 approvalPolicy 或模型 auto 标记激活。凭据在模型调用前过滤，低可信、敏感推断及一次性内容丢弃。
- 启动后后台分批重评历史 pending，使用有界内容和 evidence，计入 LLM 预算。合格项原 ID 更新为 active，不合格项物理删除；无效响应、模型或存储失败不视为否决，保留未完成项并退避重试。按 ID 与版本校验写回，避免覆盖用户并发更正或重新创建已删除记忆。
- 用户明确质疑记忆时提示通过当前会话给出正确内容或要求忘记；已给出明确更正时直接处理，不重复询问。指代不清则先追问。
- 显式更正和忘记走可返回真实持久化结果的受控记忆操作，不依赖回复发送后的异步提炼。off 只关闭自动提炼，不阻止明确纠错。替换内容与停用旧内容原子完成，避免新旧冲突；失败时如实告知，不声称已更新。

## Risks / Trade-offs

- 模型误评历史内容 → 证据、置信度和确定性过滤共同约束；技术失败不删除数据。
- 后台任务与用户更正并发 → 条件更新、串行原子保存及幂等重试。
- 历史删除不可由代码回滚恢复 → 不合格记录的物理删除属于用户确认范围；回滚仅恢复代码，不伪称恢复数据。

## Migration Plan

加载后自动调度历史重评，不要求打开会话。保留 active、disabled、rejected 和 legacy 数据。完成一条不重复评估；失败项等待后续后台重试。同步用户文档说明默认自动处理与会话澄清方式。
