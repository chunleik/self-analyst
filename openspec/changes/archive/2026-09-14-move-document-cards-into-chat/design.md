## Context

现有 documents.js 只向固定文档容器渲染列表。服务端 Artifact 已包含 sessionId、userMessageId 和文件状态，可用于定位生成轮次。需求动机见 proposal.md。

## Goals / Non-Goals

**Goals:** 在两种消息面中提供一致的轮次文件附件，复用文档获取和保存逻辑。

**Non-Goals:** 不更改文件生成格式、存储结构和保存协议，不从模型正文解析可信文件引用。

## Decisions

- 以服务端 userMessageId 对齐所属轮次，作为独立附件节点插入对应助手内容之后，不拼接到 Markdown 正文。相比仅将整个列表搬到消息区底部，这能保留历史上下文。
- 提取共用卡片渲染与保存操作，供增强消息面、fallback 和可展开成果列表使用；文档刷新应仅更新附件区域，避免打断输入、选区和流式消息。
- 保留 generation 和会话 ID 校验。按文档 ID 去重，沿用分页接口；已加载历史页在刷新时合并更新，避免轮询使历史卡片消失。
- 无法定位轮次的历史文档保留在会话内成果列表，不猜测归属。该入口默认收起，替代右侧固定文档区域。

## Risks / Trade-offs

- 增强组件和 fallback 的 DOM 生命周期不同 → 实施时核对两种消息面的挂载与重渲染路径，并分别覆盖测试。
- 自动刷新可能重复卡片或重置保存反馈 → 使用稳定文档 ID 更新，保留正在执行的保存状态。
- 大量历史文件不适合一次加载 → 保留分页及明确的继续加载入口，验证跨页刷新不丢失已加载成果。

## Migration Plan

仅更新前端资源，无数据迁移；既有文件沿用服务端关联信息。回退前端资源即可恢复原布局。
