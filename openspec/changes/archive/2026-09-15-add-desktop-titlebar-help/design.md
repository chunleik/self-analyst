## Context

动机与用户可见范围见 proposal.md。当前主窗口由 self-analyst-desktop/src-tauri/src/lib.rs 动态创建，使用系统标题栏；tauri.conf.json 的 windows 为空，窗口参数应在实际创建处调整。共享 desktop-ui/index.html 的 .brand 形成桌面重复品牌。托盘已提供关于信息，Web 版通过同一后端页面工作。此变更跨越 Rust 窗口层、共享页面及认证能力边界，需要设计文档。

## Goals / Non-Goals

**Goals:**
- 帮助准确位于产品名称右侧，与窗口控制同一行；保持两层顶部结构。
- 前端负责布局、菜单与焦点，Rust 负责窗口行为、原生关于和受限外部打开。
- Windows 原生交互与页面渲染分别验证，共享菜单行为尽量复用。

**Non-Goals:**
- 不引入新前端框架、帮助中心后台或在线诊断服务。
- 不改动时间轴布局、采集逻辑和用户数据；不调整默认窗口尺寸。
- 不新增自动更新、快捷键大全或问题代提交。

## Decisions

### 1. 自定义标题栏，保留 Windows 窗口语义

采用自定义标题栏路径，在 Rust 创建主窗口时配置窗口装饰，在共享页面增加仅桌面显示的标题栏。窗口命令集中封装，关闭调用正常 close 路径，由既有 CloseRequested 处理隐藏到托盘，不调用销毁或进程退出。

窗口拖动区域与帮助、窗口按钮的可点击区域分离，监听实际最大化状态而不只在点击时切换图标。系统菜单、边缘缩放及 Windows 11 最大化悬停贴靠必须保持；优先结合现有 windows-sys 与窗口框架能力实现命中测试和系统消息处理。实施第一项先做最小窗口验证，记录所需 API、DPI 坐标转换和资源清理方式，再接入完整菜单。若当前依赖组合不能满足契约，先更新设计，不把缺失贴靠体验静默当作完成。

原生菜单栏会增加一行；导航栏右侧方案无法满足红框位置，因此均不采用。当前不引入第三方标题栏插件；如验证表明确需新依赖，先更新 change 的影响与设计。

实施细化：主窗口以 decorations(false) 创建，在显示前安装 SetWindowSubclass。页面通过受限 titlebar_layout 命令提供 CSS 矩形及 devicePixelRatio；Windows 侧在 WM_NCHITTEST 中以 ScreenToClient 转换鼠标位置，返回 HTCAPTION、HTMAXBUTTON 等系统命中类型。框架已有的缩放边缘结果优先保留。对同 UI 线程的 WebView 子窗口使用 HTTRANSPARENT 将这些区域交回主窗口，不接管框架的 TAURI_DRAG_RESIZE_WINDOW。重复安装通过 GetWindowSubclass 避免；每个子类回调的状态在 WM_NCDESTROY 中移除子类并释放。页面监听尺寸、焦点与原生 WM_SIZE 通知，刷新实际最大化状态和命中矩形。

上述路径已编译并通过坐标与权限单元测试，仍须通过原生鼠标和贴靠实机验证才能视为该决策验收完成。隔离入口采用 feature 限定的 titlebar-review 二进制，复用正式程序的 Windows 资源清单，避免给全部链接目标追加清单造成重复资源。验证状态见 verification.md；本轮不降低原生验收要求。

### 2. 两种运行环境共用菜单逻辑

以受管壳初始化注入的环境标识及可调用桥接能力决定桌面布局，不能仅凭 localhost 或端口判定。环境标识只用于呈现，不充当权限校验。初始化应尽早决定布局，避免品牌先出现再消失。

桌面版：图标、SelfAnalyst、帮助位于标题栏；主导航删除品牌。Web 版：不渲染窗口按钮，保留主导航品牌，帮助置于状态组之后、设置之前。文件入口显示时仍要通过 800×600 和英文验收；可压缩装饰性间距，不隐藏功能来挤出空间。

视觉起点：标题栏 34 CSS px，产品名称与帮助间隔 24px，菜单文字约 13px；主导航保留现有 16px 左右内边距与高度。菜单使用现有颜色变量、浅色悬停、边框及轻阴影，宽度以最长英文项目为准，并限制在视口内。这些是视觉调优参数，不写成不可变行为契约。

### 3. 菜单状态和焦点独立管理

按用户实机反馈，帮助入口仅保留「帮助」或「Help」文字，不显示右侧下拉三角；桌面与 Web 共用该文字入口，展开状态仍通过 aria-expanded 提供。

新增小型帮助模块管理一个菜单实例，桌面和 Web 仅改变锚点。使用 button、menu、menuitem 的对应语义和 aria-expanded；菜单覆盖内容，具有明确层级。处理点击外部、Esc、Tab 和窗口失焦，确保外部点击不被强制抢回焦点。Esc 返回帮助入口；打开关于后焦点交给对话框，关闭后返回原入口。

### 4. 固定链接与关于复用

指南地址按有效语言映射到项目仓库 README.zh-CN.md 或 README.md；反馈地址固定为项目 Issues。实施时从仓库正式地址确定并验证链接，不从用户内容或模型输出拼接。桌面原生命令接受指南/反馈这种操作标识而非任意 URL，服务端按当前有效语言选择固定 HTTPS 目标。只授权当前受管窗口和当前后端页面；不得为远程任意 origin 放开命令。

Web 版直接使用固定链接，以新标签页和 noopener、noreferrer 打开，不跳转当前页面。检测到打开失败时显示可复制链接；系统接受打开请求不代表联网成功，不承诺检测浏览器中的网络错误。

桌面帮助关于复用托盘 show_about_message 的来源和展示路径；Web 版使用现有页面对话框风格显示产品名、Web 版标识及当前 location.origin，不新增仅为获取桌面版本的后端接口。关于保持本地展示，不把服务地址发给外部链接。

### 5. 语言和权限沿用既有机制

帮助及窗口按钮名称加入中英文资源，遵守现有语言重启生效规则。原生关于继续使用后端确认的有效语言。窗口 capability 和 Rust 命令来源校验遵循现有受管页面约束；动态端口不是开放所有 localhost 来源的理由。与 open_data_directory 并行 change 共享 lib.rs 时，仅增加本变更所需注册，不覆盖其他命令。

## Risks / Trade-offs

- 自定义窗口可能丢失系统贴靠、系统菜单或拖动恢复 → 把这些列为首项可行性验证和最终 Windows 实机验收，不仅做 DOM 测试。
- DPI 与多显示器导致命中范围错位 → 在四种显示缩放下验收并记录环境。用户已明确本次没有多显示器，免除本次混合 DPI 多显示器实机验收，不作为归档阻塞项；保留多显示器适配契约，在具备设备条件时补验，不标记为已验证通过。
- 英文及文件状态开启时顶部拥挤 → 在最小窗口同时开启相关入口验收，调节间距及菜单定位。
- 菜单快捷键干扰会话输入 → 仅在菜单打开或入口聚焦时处理菜单按键，测试草稿与会话切换保持。
- 去除原生装饰后的初始化失败可能使窗口难操作 → 在集成前验证窗口控制权限和初始化时序，保留系统关闭路径，失败不能显示不可控制的正常就绪窗口。

## Migration Plan

仅随桌面程序及其配套前端发布，无配置或数据迁移。先完成针对性测试，再运行跨模块测试与桌面构建；收集桌面和 Web 中英文截图及窗口操作记录。同步主规格、更新双语 README 后归档。交付遵循功能分支与 PR；合并前检查最新提交的必需检查（含 Windows 全量验证）。回滚时成套恢复桌面壳和前端，避免自定义页面与原生装饰配置错配。
