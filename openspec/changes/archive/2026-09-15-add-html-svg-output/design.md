## Context

动机见 proposal.md。现有 DocumentRequest 使用 schemaVersion=1 的 blocks/sheets，DocumentRenderer 按七种格式分派；DocumentService 负责有界写入、校验、发布、生成源和版本关联。下载控制器已经使用 attachment 响应。新增源码表达会跨越当前“被动文档结构”的边界，因此需要单独设计。

## Goals / Non-Goals

**Goals:**
- 将页面代码与普通报告数据区分，复用既有受管成果生命周期。
- HTML 能离线交互并操作内嵌 SVG；独立 SVG 可被浏览器与矢量工具读取。
- 在不运行用户源码的前提下检查结构、预算和资源依赖。

**Non-Goals:**
- 应用内预览、自动打开、网站托管、联网应用和外部资源下载。
- 独立 SVG 脚本、Office/HTML/SVG 任意互转、运行时执行模型源码验证业务正确性。

## Decisions

### 1. 增加独立的源码结构版本

保留 schemaVersion=1 的现有结构；新增 schemaVersion=2，字段限定为 `schemaVersion`、`kind` 和 `content`，kind 为 html 或 svg，content 为完整源码字符串。格式与 kind 必须对应，不能混用 blocks/sheets。标题继续由现有工具参数提供。沿用 1 MiB 输入与现有文件预算，源码同样计入限制。

相较于把源码塞进 paragraph，该结构避免普通报告文本被误认成代码，也不放宽现有七种格式的校验。源码作为生成源参与请求哈希和不可变版本，read_document_source 返回有界结构；过大时明确要求缩小源，不返回截断后可误用的源码。

### 2. 区分报告路径与直接数据导出

generate_document 接受 HTML/SVG 的专用源码；HTML 也支持 schemaVersion=1，由本地模板转义渲染正文和表格。直接数据导出可经该模板生成自包含 HTML，保留分页查询、来源及覆盖元数据，不要求模型转写原始数据。SVG 首版仅接受专用矢量源码，直接导出 SVG 或将普通 blocks/sheets 转为 SVG 时明确拒绝。已有七种格式保持原路径。

### 3. 使用解析器进行静态校验

HTML 以非执行解析器检查完整文档结构及资源属性；内嵌脚本和样式按源码保留，不把文档整体转义。输出确保 UTF-8 声明，加入本地控制的 CSP，默认禁止联网资源与连接，仅允许所需内联脚本、样式和内嵌资源，禁止 frame/object、base 和表单提交。输入不能覆盖该策略；不依赖响应头，因为下载文件离开服务器后响应头不生效。

静态资源属性和 CSS 引用采用解析后检查，允许文档内部片段引用，拒绝外部依赖且不静默删除。不要用正则表达式声称能判断任意 JavaScript 是否安全；CSP 也不构成任意脚本的完整沙箱。工具明确要求生成离线页面，验收覆盖实际交互和无网络依赖。生产生成过程不启动浏览器、不执行脚本。

独立 SVG 使用关闭 DTD、外部实体、XInclude 和外部 schema 访问的 XML 解析器；检查 SVG 命名空间、viewBox/尺寸、嵌套与大小预算。拒绝 script、事件属性、foreignObject 和非内部资源引用，包括 CSS url/import 与 href/xlink:href；允许 defs、渐变、marker、clipPath、use 等文件内引用。保留原有矢量内容，不以截图替代，不自动修补残缺 XML。

### 4. 沿用附件交付

新增格式枚举及 MIME 映射，校验后走现有临时文件到 READY 的发布流程。文件卡片只呈现转义后的元数据，不将源码插入 DOM；不新增预览路由。检查原生保存扩展名和浏览器附件名，保持既有鉴权及跨会话拒绝行为。

相较于 iframe 预览，该方案符合用户只需下载的范围，也避免把成果放入应用的受信任页面环境。应用不向输出注入凭据、配置或本地路径；下载文件中的脚本由用户浏览器运行，应用不提供权限桥接。

## Risks / Trade-offs

- 任意脚本无法靠静态校验保证逻辑正确或完全安全 → 不宣称源码审计或完整沙箱；限制资源、保持附件交付，并用离线样例验收核心交互。
- 过度清理可能破坏 SVG 内部引用或 HTML 脚本 → 按格式区分校验策略，覆盖渐变、marker、use 和动态 SVG 更新，失败明确报告。
- 源码消耗较多模型上下文 → 沿用有界生成源限制，超限失败并建议简化；不放进聊天正文。
- 浏览器与矢量工具的字体、脚本能力不同 → HTML 以桌面 Chromium 浏览器离线验收；SVG 使用标准矢量元素和系统字体回退，不保证不同工具像素一致。

## Migration Plan

不改写历史源码或数据库记录；先部署能够识别新增格式和 schemaVersion 的后端与桌面资源。验证旧格式及已有成果读取不回归。回退旧版本会无法识别新格式，因此回退前另存新成果，并保留受管数据供恢复升级后读取，不删除或降级转换文件。实施完成后同步主规格，将 Purpose 中的七种格式更新为九种，保留稳定需求 ID，并更新中英文 README。
