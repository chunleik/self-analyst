## Context

见 proposal.md 的动机。现有 `DesktopServer` 的 `/desktop-ui/{f}` 路由把所有资源转换为 UTF-8 字符串；标题栏引用的 `app-icon.png` 已存在，问题位于响应转换而非缺失资源。共享帮助菜单通过受当前窗口和后端 origin 校验的 Tauri `help_action` 执行原生操作。当前桌面壳没有版本检查服务，但已有 `ureq` 和 `serde_json` 依赖。

## Goals / Non-Goals

**Goals:** 保持图片传输完整性，在既有帮助交互中增加手动版本检测，维持窗口响应及现有原生权限边界。

**Non-Goals:** 自动升级、后台定时检查、安装包下载器、更新签名系统、托盘其他菜单重构及替换现有品牌图标。

## Decisions

1. 静态资源直接返回原始字节，按后缀设置内容类型（至少补齐 PNG），保留现有文本资源类型和缓存策略。相比换成 SVG 绕过问题，修复传输层可解决同路由上的二进制损坏。HTTP 回归测试验证 PNG 响应与 classpath 文件逐字节相等且可解码，并检查现有 CSS、JS、HTML、SVG 仍正常返回。
2. 桌面通过受管命令执行 HTTP 请求，复用现有客户端，在阻塞线程执行，设定整体超时及响应大小上限。目标固定为 `https://api.github.com/repos/chunleik/self-analyst/releases/latest`，带公开应用 User-Agent，不使用 GitHub token，不接收前端任意 URL。依据 [GitHub Releases API](https://docs.github.com/en/rest/releases/releases#get-the-latest-release) 读取最新公开稳定发布，防御性校验非草稿、非预发布及合法版本字段；禁用任意跨域重定向。
3. 当前版本取桌面构建版本，移除发布标签可选前导 `v` 后按 SemVer 比较，不按字符串顺序判断。优先复用依赖树中的成熟 SemVer 解析库；如需直接声明依赖，应更新 Cargo 清单和锁文件。非法或无法比较的版本报告检查失败。返回结构化结果和错误码，由共享页面渲染本地化对话框。
4. 帮助项顺序为使用指南、反馈问题、检查更新、分隔线、关于。检查中显示状态并去重，成功显示当前与最新版本；较新版本提供「前往下载」，用户点击后经原生受管命令打开固定项目发布路径，仅接受已校验的版本标签，不执行任意远端 HTML 或原始响应 URL。失败支持重试及手动查看发布页；取消或关闭对话框后，旧请求结果不得重新弹窗打断用户。
5. Web 版没有可信的桌面壳版本，检查更新入口显示说明并提供最新发布页按钮，不进行虚假比较。相比扩大后端 API 暴露桌面版本，这一方式保持 Web 与原生边界清晰。
6. 移除托盘 `about` 构造、菜单项和处理分支；保留帮助使用的关于展示函数。同步修改原规格中“托盘与帮助关于一致”的契约，避免归档后保留旧要求。

## Risks / Trade-offs

- GitHub 无法访问、限流或没有正式发布 → 限时失败、可重试和手动发布页入口；不将异常解释为无需更新。
- 版本标签不符合 SemVer → 明确失败，不猜测顺序；测试两位补丁号、预发布和构建元数据。
- 原生请求阻塞或对话框关闭后迟到 → 后台线程处理、请求状态去重及界面结果代次控制。
- 前端模拟服务器直接返回 PNG，可能掩盖 Java 路由问题 → 必须通过真实 Java HTTP 响应验证，并以真实后端完成图标视觉检查。
- 发布页仍需用户选择安装包类型 → 提示下载而非自动安装，覆盖安装版和便携版。

## Migration Plan

无需数据迁移。实现后运行 Java、Node 和 Rust 针对性测试，再运行跨模块验证，检查中文和英文帮助菜单、真实标题栏图标以及托盘菜单。同步两个主规格和两个 README，严格校验并归档。回滚时整体回退对应功能提交，不修改用户运行目录。
