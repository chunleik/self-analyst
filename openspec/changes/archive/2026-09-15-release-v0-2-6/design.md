## Context

动机见 proposal.md。当前工作区停留在已合并的功能分支，远端 main 已包含其它新增提交；发布必须基于最新 main。Maven、桌面与 Rust 工程分别保存项目版本。

## Goals / Non-Goals

确保发布来源、各模块版本和分发产物一致。保留无关本地输出和未完成的 add-python-release-assistant，不引入业务实现修改或新的依赖升级。

## Decisions

- 从最新 origin/main 创建 codex/release-v0.2.6，避免直接从当前较旧功能分支发布；执行前再次核实远端标签和版本未被其他任务占用。
- 精确修改本项目版本及锁文件对应条目，避免全局替换误改第三方依赖版本。
- 沿用现有 Windows Release 工作流；合并前等待 PR 最新提交全部必需检查，包括 Windows 全量验证，随后从已合并提交创建新标签。
- 无行为契约变化，跳过增量规格和主规格同步。发布说明保存在 docs/releases/v0.2.6.md，并在工作流完成后用于正式 Release 正文。

## Risks / Trade-offs

- 远端 main 或检查提交发生变化 → 同步后重新核对发布范围和最新提交检查，不能复用旧结果。
- 本地存在无关空 change → 独立、干净的发布工作区执行全量校验，保留原工作区文件。
- 构建或附件缺失 → 检查失败步骤并修复，不覆盖既有标签或绕过门禁。

## Migration Plan

更新并验证发布元数据，归档发布准备 change，推送功能分支并创建 PR；检查全部成功后合并，推送 v0.2.6 标签。等待 Windows Release 完成，确认正式版本、ZIP、0.2.6 安装包和两份 SHA-256 文件，校验下载文件摘要。发布失败时保留证据并修复原因，不将失败构建报告为发布成功。
