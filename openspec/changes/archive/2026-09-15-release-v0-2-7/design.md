## Context

动机见 proposal.md。已核实最新发布为 v0.2.6，远端 main 为 20f96258bc7883458946b3781b421252d8589916，包含 PR #47 和 #48；当前工作区仍处于已合并帮助菜单分支。

## Goals / Non-Goals

确保跨 Maven、Node、Rust 的项目版本和最终 Windows 分发产物一致。保留本地未跟踪分发目录及其他未完成 change，不补入与发布无关的实现修改。

## Decisions

- 基于重新获取的 origin/main 创建 codex/release-v0.2.7；不从当前较旧功能分支打标签，以包含已合并统计修复。
- 精确更新本项目版本和锁文件自身条目，不使用可能误改第三方依赖的全局版本替换。
- 沿用 Windows Release 工作流，不新增发布脚本。PR 最新提交必需检查全部成功后合并，再从已合并提交创建 v0.2.7 标签。
- 仅维护发布元数据，使用 skip_specs: true；主规格已由功能 change 维护，无需增量或同步。发布说明核实统计迁移、升级和回退限制。

## Risks / Trade-offs

- main 或标签在准备期间变化 → 执行前重新确认版本占用、提交范围与最新检查结果。
- 无关未完成 change 干扰全量规格校验 → 在干净发布工作区验证，并保留原工作区内容。
- 统计迁移影响旧数据或降级 → 对照 PR #47 的主规格、运行数据文档和验证记录编写升级说明，不能宣称无迁移。
- 构建或附件缺失 → 查明失败原因并修复，不覆盖已存在版本标签或绕过检查。

## Migration Plan

准备版本配置及发布说明，运行对应验证、严格校验并归档发布准备 change。推送功能分支并创建 PR；最新提交必需检查（含 Windows 全量验证）通过后合并，创建并推送新标签。等待 Windows Release 成功，再将已审阅发布说明写入 Release，核对安装包、ZIP 与对应校验和。失败时报告实际状态；不得将准备完成等同发布成功。
