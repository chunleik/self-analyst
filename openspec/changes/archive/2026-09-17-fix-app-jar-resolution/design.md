## Context

共用解析器通过文件名前缀收集候选；Shade 的中间文件也符合该前缀。动机见 proposal.md。

## Goals / Non-Goals

目标是正确区分正式产物与 Shade 中间产物；不改变构建命令、版本号、分发结构或用户数据。

## Decisions

在计数之前过滤 `*-shaded.jar`，保留已有 `original-*` 前缀排除与唯一候选检查。即使中间产物内容不同，仍以正式命名的 JAR 为候选；不读取大文件计算哈希，不按修改时间择优。只有中间产物时必须失败。

回归测试沿用桌面 Node 测试入口，在 Windows 上用 PowerShell 7 实际执行解析脚本；其他平台显式跳过此 Windows 构建脚本测试。测试创建独立临时目录并验证原文件未改变。

## Risks / Trade-offs

过滤不能解决多个正式版本残留的问题；继续明确拒绝多版本，要求清理或隔离构建目录，避免打错版本。
