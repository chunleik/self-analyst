## Context

动机和真实对照证据见 proposal.md。上一轮 .tmp/summary-eval 固定了 2026-09-19/20/21 的数据库快照、主分支及第一阶段源码、提示词和模型输出，可隔离预算与算法影响，不需要再采集或改写用户数据。

## Goals / Non-Goals

**Goals:** 同预算减少重复及结构开销，提高高耗时应用内多种标题的入选机会；支持 24000 默认预算并复验真实摘要。

**Non-Goals:** 不实现多次模型调用、主题 embedding、语义合并不同标题或历史自动重算；不更改普通文件及标题采集边界；不硬编码 Hop、Grafana 等实测主题。

## Decisions

- 跨来源处理在事实归组前完成：内容使用系统标题（上下文为空，或与系统标题完全相同且类型为 window/unknown）时，从内容观察中扣除同应用/标题有效窗口的交集，仅将剩余部分作为无活动确认的 content 观察。完整窗口事实保留；不同的上下文标题及显式 chat/article/document/page 语义仍按原规则关联有效窗口，即使字面标题相同也保留类型。这样不丢失未覆盖观察，也不为重复时长付出双倍模型输入。
- 本地 Fact 继续保存四个代表区间及每区间四个来源引用和省略数，不声称完整来源映射。模型行采用带短键的 JSON，区间为相对周期起点的秒偏移三元组（开始、结束、是否活动匹配），时长以毫秒精度显示；完整原始精度指标继续在本地保存。投影不发送数据库 ID 列表，fact ID 可对应同次本地结果。
- 窗口与新增语义上下文各保留一半预算，未用额度可复用；回退系统标题的未匹配观察不占独立上下文保留额度，而在余量阶段共同竞争。时间层以全部真实区间的交集而非仅最早时间确定。层内采用持续时间权重、已选同应用数量的渐进惩罚和标题词片相似度的渐进惩罚；相同应用的不同主题仍能在短辅助应用之前选中。标题词片按 Unicode 字母/数字分词，过滤同应用内过于常见词，不读取正文、不对不同标题做事实合并。观察候选给低而有界的权重，不以观察持续长度推断活跃。排序权重只在候选实际装入预算后更新。
- 默认预算升为 24000，但不修改用户 TOML；既有合法 12000 保持。事实和提示词版本升级，统计/日历版本与数据库保持兼容。
- 回归先验证跨来源完全/部分覆盖、同名异时、未知观察、应用内多主题、Unicode/超限和精确统计不变。复用冻结快照在 12000 与 24000 下做本地输入覆盖对照，真实模型至少生成新版 24000 三份，与上一轮主分支和第一阶段同日结果比较，单次模型随机性明确说明。

## Risks / Trade-offs

- 词片相似度不是语义理解 → 只影响采样排序，原始事实不合并，惩罚有界。
- 提高预算增加输入费用 → 先用同预算本地对照验证算法贡献，报告真实 token，保留用户配置。
- 紧凑时间不如完整日期易读 → 提示词说明基准起点与时区，区间保持分离，时间舍入只用于显示。
- 候选很多仍会省略 → 继续输出覆盖与省略统计，不声称完整复盘。

## Migration Plan

无数据迁移；新建摘要采用新版输入。上一轮产物和已有用户摘要保留，代码回退不会改变事件事实。
