## Context

见 proposal.md。当前 WikiTitleSampler 已提供局部事实 ID、时间和有界来源，WikiSummarizer 仍只解析自由文本 evidence；当前窗另用应用排名提示词。现行 GEN-020 限一次模型调用，因此本变更明确更新该契约以允许受限树形汇总。

## Goals / Non-Goals

**Goals:** 所有已识别的优化形成闭环：输入覆盖、证据支持、低延迟看板、长输入汇总、来源复用和质量验证。

**Non-Goals:** 不扩大采集隐私范围，不将标题推断当作成果证明，不自动付费重写历史，不引入独立 Python 服务。

## Decisions

- Fact/Selection 作为共用输入；中文使用字符 n-gram，英文保留词片。覆盖选择先按四位时间掩码寻找最小成本覆盖组合，再按边际主题/时长收益填充；仅16个掩码状态，避免通用背包指数复杂度。长标题首尾保留，代表区间兼顾首末、最长和时间覆盖。
- 覆盖选择同时保护全局与每来源独立预算内的可行时间层。有效活动用交集区间；纯观察仅以起点时间层参与覆盖排序，其完整观察区间仍保留但不借跨度取得多时段活动权重。
- TaskSegment 增加 evidenceFactIds、claimType，保留旧构造器与 JSON 缺省，历史 legacy 仅用于读取。新模型输出严格检查字段、长度、数量、引用、应用和观察属性，证据文案由已知标题生成或校验，拒绝明确无依据成果动词。验证不是语义证明，文案明确观察与推断。source 信息可保存为受限结构化派生元数据，不写原始正文。
- WikiSummarizer 提供单次生成/提示词/解析边界，另以编排器做按字符硬限制的自适应树形汇总；全请求预算包含固定提示词，输出预留与字符安全边界明确。短输入一次调用，长输入先规划全部块；默认最多6次调用，最多32000请求字符，沿用全局每日usage控制。超出总额度以可解释覆盖采样降级，不伪装全量。
- 中间缓存为有界本地派生缓存，key 包含输入摘要、模型身份、提示词、事实与统计版本。只缓存校验成功结果，失败不缓存；用户切模型即失效。缓存使用原子写入或有界内存，初版优先内存避免保存额外活动副本；重试同运行实例可复用。
- 上层子摘要携带日期、entryId、taskSegments、coverage，子引用写入现有sourceEntryIds。当前窗复用采样事实但保持单次低预算生成与5秒超时；历史周期读取职责保持。
- 当前窗文案缓存使用独立生成时间，不把每次 assembledAt 当作生成时间；语言进入缓存键，应用秒数按5分钟分档，避免频繁轮询延长陈旧文案寿命或额外耗费调用。
- 离线质量套件包含有期望的脱敏固定案例；显式模型评测不使用私人库，记录各案例覆盖/错误、调用数、tokens、延迟，保留人工真实性检查栏。模型身份和预算配置由运行上下文传递，不将凭据写入报告。

## Risks / Trade-offs

- 标题无法确认成果 → 引用校验、动作保守策略和反例评测共同限制，不宣称全自动事实判定。
- 多轮成本上升 → 单次优先、调用/时间/请求上限、全局预算与中间缓存。
- 更严格输出导致旧模拟/模型响应失败 → 只对新生成契约校验；旧数据库读取与兼容构造器保留。
- 当前窗长输入影响响应 → 单独小预算，不走后台树形路径，超时降级。

## Migration Plan

只增加兼容JSON字段和配置项，保留现有数据库结构及旧摘要。新提示词/事实版本标识新结果，旧数据不自动重算。完整测试、质量评测、双语文档与严格规格校验通过后同步主规格并归档。
