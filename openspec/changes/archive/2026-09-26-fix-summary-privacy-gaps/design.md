## Context

见 proposal.md。复查时在本机用 JDK 21 读取 Chrome 进程信息，`ProcessHandle.Info.commandLine()` 与 `arguments()` 都为空，因此上一版的命令行检测在 Windows 上恒为 false。事件里也没有 URL 字段，网站只能从标题识别。

## Goals / Non-Goals

**Goals:**

- 删掉不能工作的检测，文档和规格只描述真实生效的保护。
- 父级输入与小时输入使用同一套脱敏和排除。
- 被排除的应用不在提示词中出现。
- 上层摘要本地收敛为一句。

**Non-Goals:**

- 不引入新的无痕检测手段，例如读取浏览器 UI 树或调用 WMI。
- 不重算已有摘要，也不修改已保存的旧摘要文本。

## Decisions

### 1. 删除命令行检测

Chrome 的无痕窗口和普通窗口通常属于同一个进程，即使能读到命令行也无法按窗口判断。保留这段代码只会造成误导，所以窗口事件恢复为只记录应用和标题，标题采样也不再读取 `private_browsing`。

### 2. 子摘要按文本脱敏

原始窗口标题命中账号验证关键词时，整条替换为“账号验证页面”。子摘要的标题和描述是模型写的句子，整句替换会丢失其余内容，所以改为只替换命中的片段。内网 IP 与会议号两者都按片段替换。

### 3. 应用权重按排除列表过滤

提示词里的应用权重来自本地统计。排除应用的名称写入内部统计 `privacyExcludedApps`，只保存在本地；拼提示词时跳过这些应用。持久化的 `topApps` 与耗时保持不变。

### 4. 单句按中英文句末标点截取

以第一个“。！？!?”为界截取第一句；没有句末标点时保留原文并补“。”。截取后为空时，使用前三个保留主题组合成一句。

### 5. 删除无效参数

`parseSegments` 的覆盖不确定参数与各处计算它的辅助方法已不影响结果，直接删除。

## Risks / Trade-offs

- 标题里没有无痕标记的 Chrome 无痕窗口仍会被记录。README 会写明这一限制，并建议用户把敏感网站加入排除列表。
- 网站按标题关键词匹配，可能误伤标题里恰好含有该词的其他页面。
- 升级前已保存的小时摘要文本不会改写，只在进入上层时过滤。
