## Context

参见 proposal.md 的动机。`chat.js` 的会话列表点击委托直接调用 `confirm()`，确认后调用既有删除函数；项目帮助界面已使用 HTML `dialog` 和 `showModal()`。本变更需要明确异步确认后的目标绑定和焦点管理。

## Goals / Non-Goals

**Goals:** 使用现有前端能力实现居中、可键盘操作的删除确认，确保异步交互仍删除最初选中的会话。

**Non-Goals:** 不替换其他确认或错误弹窗，不改变后端删除协议和业务数据。

## Decisions

- 使用 HTML `dialog`、`showModal()`、居中样式和 `::backdrop`，沿用页面主题变量。相较继续使用原生 confirm，可控制位置和文案；相较手写遮罩容器，浏览器提供背景隔离和焦点约束，减少交互遗漏。
- 弹窗通过独立模块返回一次性的确认结果；调用者保存目标 session ID，确认后进入现有删除成功和失败流程。关闭时清理监听器及待确认状态，避免重复确认或下一次打开使用旧目标。
- 取消按钮默认聚焦，标题和描述关联无障碍属性。Esc 按取消处理，遮罩点击不确认也不关闭；确认后关闭弹窗，再执行删除，既有失败反馈保留。列表重新渲染导致触发按钮被替换时，将焦点恢复到相同会话的按钮，删除成功则使用当前会话入口或新建按钮。
- 静态文案使用现有 i18n 目录，提供中英文资源。弹窗采用受视口限制的宽高，长文案可换行，按钮始终可操作。

## Risks / Trade-offs

- [同步 confirm 改为异步后目标漂移或重复提交] → 打开时捕获 ID，结果只结算一次，以测试覆盖取消、连续打开和重复点击。
- [列表渲染替换 DOM 导致焦点丢失] → 检查触发元素是否仍连接到文档，并提供删除成功后的焦点回退。
- [Node 测试无法验证真实布局和浏览器焦点约束] → 自动测试验证事件和请求行为，浏览器视觉检查验证居中、键盘、缩放与遮罩。

## Migration Plan

随桌面 UI 资源发布，无数据迁移。回退本次前端变更即可恢复原确认交互。
