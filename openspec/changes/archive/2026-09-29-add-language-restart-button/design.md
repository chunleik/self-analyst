## Context

动机见 proposal.md。当前国际化契约规定语言在后端启动时确定。桌面壳 lib.rs 已提供 JavaBackend 的认证 shutdown、有界等待和子进程回收，run_return 处理退出请求，关闭窗口则隐藏到托盘；现有原生命令注册中没有重启入口。本次跨 UI 与 Rust 生命周期边界，需明确重启时序。

## Goals / Non-Goals

**Goals:** 用现有配置状态和原生桥接提供完整应用重启，保持数据根、单实例及认证启动边界；确保失败可解释、请求不会重入。

**Non-Goals:** 不添加语言热切换、普通浏览器进程管理、定时重启或通用配置自动重启；不把选择语言改为立即保存。

## Decisions

1. UI 以有效配置响应中的 app.language 待重启差异决定按钮，而非比较下拉框与当前有效语言字符串。auto 及系统语言解析不适合前端猜测，已有差异状态也能支持重新打开设置。
2. 按钮加入现有底部操作区，配合当前保存、草稿及请求状态；有草稿时要求先保存或放弃。避免把未保存内容静默丢弃，也不增加第二套保存路径。文案与错误进入现有双语目录。
3. 通过仅受管主页面可调用的 Tauri 命令设置原生重启意图，原生端同样实施单次调度。普通浏览器保持说明；不新增 Java HTTP 重启能力。实施时核对现有桥接权限与来源限制，保持同一信任边界。
4. 在原生退出流程统一协调重启：完成受管后端停止与子进程回收，释放单实例及相关资源后，从当前可执行路径以正常可见启动模式重新启动，保留安装/便携布局及同一数据根。不得在持有旧单实例锁时直接派生新主实例，也不得只 reload WebView。实现需核对 run_return 后资源析构时机，并以可测试的时序封装覆盖退出、释放和启动关系。
5. 重启请求失败且旧页面仍存在时恢复按钮并显示本地化错误；退出后重新启动失败使用原生诊断路径。手动触发重启不继承自启动隐藏窗口参数。

## Risks / Trade-offs

- [单实例锁或旧后端未释放导致新实例失败] → 在重启时序中显式处理资源释放，增加生命周期顺序测试并在打包桌面实测。
- [关闭窗口仅隐藏到托盘] → 重启必须走应用退出路径，不能模拟窗口关闭。
- [正在执行的工作会随重启中断] → 沿用正常退出行为，按钮附近说明将重启应用，只有用户显式点击后执行。
- [保存后新草稿被丢弃] → UI 同时检查所有设置草稿，未保存时禁用重启。
- [普通浏览器误判原生能力] → 使用现有原生桥接检测；能力不可用时保留手动说明。

## Migration Plan

无需数据迁移或配置格式升级。随桌面 UI 与原生壳一同交付；回退该变更后恢复原有手动重启流程，已保存 app.language 仍有效。
