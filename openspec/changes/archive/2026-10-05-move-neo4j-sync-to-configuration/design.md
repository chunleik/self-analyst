## Context

参见 proposal.md。原 Neo4j 面板随知识页常驻挂载；配置窗口会销毁并重新建立所选页签，已有异步状态检查及已确认发送需要适应此生命周期。

## Goals / Non-Goals

**Goals:** 用既有配置视图切换机制保留草稿保护，确保重新挂载后不接受旧响应且不会额外发送。

**Non-Goals:** 不改同步后端、密码环境变量、数据范围和默认关闭语义，不新增自动轮询。

## Decisions

- 独立 Neo4j 页签而非塞入高级原文编辑器，避免同步动作与尚未保存的草稿混淆；高级配置仍用原有定向定位入口。
- 离开页签递增视图代次并卸载显示状态。所有异步 UI 更新和发送前确认均核对代次，避免旧检查越过已关闭界面执行。
- 未完成的发送前 GET 在离开时释放界面锁，并用操作代次使其 finally 失效，避免旧请求解除新发送锁。
- 已确认 POST 不假装因关闭而取消。请求锁跨挂载保存，旧请求结束后只触发当前面板的最新只读状态查询，不把旧结果渲染到新目标。
- Neo4j 样式移入配置布局，滚动区域独立并允许按钮、地址在窄屏换行。

## Risks / Trade-offs

- 关闭时已发送的数据不能撤回 → 不中止已确认 POST 或自动重试，重新进入仍保持执行中状态和重复发送保护。
- 重新进入时目标已修改 → 清空旧目标并按需重读，后端指纹校验继续约束每次发送。
- 页签增多在窄窗口溢出 → 允许页签换行，并检查 390×700 与 800×600。
