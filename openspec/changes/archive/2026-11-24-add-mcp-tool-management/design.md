## Context

beta.19 已有 `McpManager`、`IntegrationStore`、`IntegrationCredentialStore`、受管桌面接口、按轮次的工具快照与多账号邮箱。新实现尽量复用一个权威目录和原有执行守卫。用户于 2026-11-24 明确选择新增本机外部接入、草稿和发信，并要求凭据继续加密。

## Decisions

1. **配置及凭据**：复用 `config/integrations.json` 和操作系统凭据适配器，单独原子保存本机发布规则及非秘密引用。IMAP、SMTP、MCP Bearer 独立目标绑定；持久化走 Windows Credential Manager，库不可用则拒绝。普通接口及日志不回显；本机 Bearer 只在显式生成或轮换时一次性提供。账户目标、凭据或范围变化清理旧发布授权；不建 ACL-only 明文文件。
2. **回环发布**：以现有 Javalin 回环监听器提供无会话、JSON 响应的 Streamable HTTP 工具子集。单账户和聚合路由分别为 `/mcp/{serverId}`、`/mcp/all`。仅显式发布的启用邮箱进入目录；无浏览器跨源接入，不转发第三方服务。独立 Bearer 校验和权限复核隔离桌面认证，外部读授权独立于会话模型授权。不同端点及代次的引用不互通。
3. **邮件读写**：抽出 `self-analyst-mail` 维护现有只读路径；固定提供 QQ、163、126、个人 Gmail 应用专用密码。草稿仅追加到唯一且可用的特殊用途 Drafts；SMTP 只用固定 SMTPS 独立凭据。先冻结确切收件人和完整内容并展示，再批准并在线路写入前检查。草稿与发信显式启用，默认关闭；不支持附件下载、任意 IMAP 命令或后台同步；无最终回复时要求核对，不重发。无需使用真实邮箱来验证协议。
4. **传输**：现状 Streamable HTTP 不变。旧版 SSE 在同一验证过的公网 HTTPS authority 下处理有界会话路由，不放宽普通 URL 检查；流失败或撤权关闭，绝不重放业务请求。stdio 只按本机绝对路径和参数数组启动，不经 shell 或继承秘密，导入/保存/启动应用不执行；保存并启用后用户另行发起测试或发现才启动。禁用、变更或失败后回收本程序可以观察到的进程树，这不是系统沙箱。
5. **Agent 发布**：按轮次使用现有工具定义快照和定义级批准，不在已运行的 Toolkit 中动态增加工具。实际调用复核实时代次、工具定义和精确参数；就绪或撤权无需重启。草稿及发信的请求正文不作为工具观测正文导出。脱离桌面审批无法写入。
6. **UI 和迁移**：顶栏 MCP 页复用连接、权限、测试和删除 UI，显示回环地址和账号发布状态；设置入口跳往该页。旧搜索键从活跃配置移到退役表，不迁移秘密，由默认关闭的 Parallel Search 模板替代。README 中英文同步。
7. **边界**：对外客户端是否支持本机地址由其实际连接路径决定。Cursor 文档提供本机 Streamable HTTP；未声称真实客户端互操作。Claude 声明云端发起的自定义连接器不能直达回环。Exchange Online、企业/任意主机及 stdio 秘密变量需要单独安全、认证和兼容性设计，未在此次发布中冒称支持。
