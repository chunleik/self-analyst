## Context

基线为 beta.18 main `e9838ca`。用户要求删除文件夹范围整组控件、固定全部，并不考虑旧版本兼容。此前选择器方案由本修订取代；历史验收事实不改写。

## Goals / Non-Goals

目标：简化邮箱设置，界面承诺和真实保存范围一致；保留授权及安全存储。
非目标：旧指定范围迁移、真实邮箱连接、后台收信同步、改变后端协议预算、发版。

## Decisions

### 1. 新 UI 固定 all

新建条目显式 `folderScope: all`、空 `allowedFolders`，只有账户元数据和正文许可可编辑。快照中的 selected 在 UI 明确拒绝，不能隐藏该字段继续按指定名单生效。缺失范围仍为非法，不自动转换或扩权。底层现有 selected 配置语义和管理接口保持独立，不为本次 UI 增加兼容转换。

### 2. 删除选择器与自动连接

删除范围下拉、搜索、操作按钮、目录列表与前端目录发现状态机，不以 disabled 控件或隐藏名单替代。打开设置、保存或启用不自动 LIST；目录读取留给用户明确发起的邮件工具及连接测试。保留后台目录发现接口的认证、预算和隔离，避免无关 Java 变更。

### 3. 授权语义不变

简短说明动态全部包含未来新增目录且非后台同步。正文默认关闭并独立授权。保存元数据不启用；加密保存启用确认仍展示范围、实际模型目标、正文、系统凭据存储与聊天留存。已有原子事务、回读验证、失败恢复、撤权和删除不变。

## Risks / Trade-offs

旧指定范围在新 UI 不受支持：明确报错而不迁移；原配置不改写。移除目录发现减少联网，但服务商可见目录和邮件预算仍受原规则约束。真实邮箱和 Windows/Tauri 人工验收不由 Node/合成浏览器替代。

## Validation

定向及全量 Node、合成中英文宽窄浏览器、OpenSpec 严格校验、主规格同步与差异检查。只改前端，不以未运行的 Java 全量或远端 CI 作为通过证据。
