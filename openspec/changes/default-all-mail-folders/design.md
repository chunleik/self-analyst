## Context

参见 proposal.md。本修订以未合并 PR #154 的 `4182c6c` 规划和实现为工作基线，对照已发布 beta.17/main `826e1c5`。main 仍是手填最多 32 项名单；PR 分支已有显式范围和安全启用，底层 LIST 使用递归匹配并返回完整名称，但设置页不显示目录。原先“不做文件夹选择器”和旧账户兼容设计被本修订取代。既有 verification.md 仅是此前实施历史，不证明本修订完成。

## Goals / Non-Goals

**Goals:** 新邮箱默认动态全部范围；用户无需猜测 IMAP 名称即可选择；连接配置完成后自动加载目录；安全持久化并以清晰确认默认启用；范围收窄即时生效。

**Non-Goals:** 不做旧邮箱兼容/迁移，不增加后台收信或全量同步，不改服务商历史可见范围，不提供发信/写入/附件下载，不绕过正文或模型目标授权，不改外部 MCP 凭据政策。本提案阶段不触达真实邮箱、不改代码、不发布。

## Decisions

### 1. 统一显式范围，不做迁移

沿用 `folderScope: all|selected`，新建表单显式赋 `all`；邮箱条目缺失/未知范围视为无效，不再按旧白名单自动规范化。配置顶层版本与外部 MCP 合同不随邮箱字段一起改写，保留完整配置校验失败时原文件不被覆写的边界。不设计旧格式升级、旧账户重建或会话凭据导入流程；不为兼容需求引入第二套逻辑。

`allowedFolders` 在 selected 模式为 1–256 个唯一完整名称；all 模式允许为空并保留用户切换前的选择。星号不作通配权限，空列表不表示全部。模式与名单均进入权限 revision；范围或正文改变先停用，新确认后再启用，旧引用/游标失效。导入新格式仍清除启用与凭据，不携带授权。

### 2. 动态全部与当前全选分开

all 表示当前及以后新增的可读目录，不把某次发现结果固化成白名单。selected 是固定精确名单，包括当前全选操作生成的名单；未来目录不会自动加入。all 模式展示当前完整目录的选中状态，取消某项时转成 selected，使用当前完整发现快照减去该项，提示含义变化。若尚无完整快照，不能通过取消某项产生不完整授权名单。

从 all 切到 selected 时保留此前明确名单；没有名单且已有完整快照时可选中当前目录作为草稿。清空在 selected 下显示校验提示，不能保存为宽权限。未保存就离开采用现有放弃确认。

### 3. 独立管理端发现，不使用 Agent 工具绕过权限

增加受管理桌面认证保护的 `POST /desktop/integrations/mail/folders`，请求绑定已保存账户 ID、expectedRevision，可带本次临时授权码；不接受任意 host/port。只连接该账户固定 QQ/163 TLS 目标，执行有界目录列举。未启用账户也可发现，返回所有服务商可见可容纳邮件的目录，不受当前 selected 名单过滤；这仅用于本机用户设置。

响应包含账户 ID、revision、目录完整名称、服务端分隔符/可选择属性以及完整性标识，目录名称不作为权限凭证。底层新增必要目录元数据时继续保留完整名称原文，禁止前端猜分隔符或改写路径。纯容器目录可以作为层级展示节点，但不能授权为邮件目录。响应在目录数（256）、名称长度（256 字符）和现有请求/网络期限内有界；控制字符或超额返回分类错误，不静默截断成“全部”。无目录与失败分开。

发现入口不启用账户、不读邮件信封或正文、不打开邮件进行抓取、不写远端状态，也不把名称发给 Agent/LLM、开发者观测或持久日志。现有 Agent listFolders 继续只返回当前已启用且授权的范围。连接测试保留其独立协议检查语义，不能把一次 LIST 成功等同全套测试成功。

### 4. 凭据与自动加载时机

界面明确告知配置后会连接所选服务商列举文件夹。元数据保存成功且匹配账户凭据可用后，自动发起一次发现；账户身份、凭据改变后仅在用户完成保存/连接操作时重新发现，不在逐字输入时发送秘密或反复认证。打开已有已配置账户时自动加载一次，并提供主动刷新。

新账户先保存公共配置，输入授权码后“连接并加载文件夹”将秘密仅供本次发现使用，服务端清理临时字符数组并关闭连接，不自动写系统库。加载后用户选择范围，再走保存启用确认。若尚无可用凭据，显示等待输入状态，不发送失败请求循环。可复用的持久凭据必须匹配当前账户身份；不接受凭据引用跨账户挪用。没有目录快照时仍可明确确认 all 范围，但 selected 需要有效非空名单；发现失败不代表授予或撤回权限。

### 5. 无额外开关的安全启用

邮箱不显示 enabled、persist 及原处理授权勾选项；独立正文选择仍保留。用户点击“加密保存并启用邮箱”，确认账户、当前/未来目录范围、正文是否允许、模型目标、聊天留存、系统安全存储与断开边界。确认取消不提交；服务端核对 revision、披露版本与目标。确认并成功保存后即启用，无需第二个启用开关。

凭据复用现有 Windows Credential Manager，写入后回读核验，原子提交新引用与授权后再清理旧引用。其他平台不假装可加密保存，失败不降级。发现临时凭据不属于长期 session 账户；不迁移旧 session 邮箱。外部 MCP 的 session 存储保持不变。

配置写入与发现网络请求分离：启用成功后自动发现失败，界面明确显示“已保存并启用，文件夹加载失败”，不得回滚已确认配置、重复启用或谎称保存失败。提交结果无法确认时维持既有不确定状态与主动刷新恢复，不盲删可能有效凭据。后续正文读取和实际模型接收目标确认保持独立。

### 6. 可取消、抗迟到的目录选择器

用搜索框和分层复选列表替换手填框，展示完整路径、已选数量、范围模式、刷新和“选中当前全部/清空”。使用标准可聚焦控件、明确标签与加载/错误状态，名称只经 textContent 渲染，采用共享主题令牌，补齐中英文。搜索只筛显示，不改变已选集合；刷新成功不擅自清除已选但暂未发现项，为其显示“当前不可用”，由用户决定是否移除。

每次发现绑定账户、配置 revision 与 generation。关闭设置、切换账户、修改身份、断开或删除会取消并使结果失效；同账户正在加载时合并/拒绝重复请求。远端返回后再次核对账户存在、revision 和凭据世代；过期结果不能污染新账户或复活已删除连接。失败保留草稿，旧列表标明过期，允许主动重试，不无限轮询。

## Risks / Trade-offs

- [默认全部误解为自动下载] → 明确是按需读取许可，正文、模型目标和账户确认独立，不做自动遍历搜索。
- [发现所有目录泄露未授权范围] → 仅本机管理端可见，不进入 Agent 工具或观测载荷，接口受认证且响应 no-store。
- [认证失败或列表巨大] → 沿用固定目标、TLS、取消/限时，超额明确失败，不声称全部成功。
- [发现刷新丢失选择] → 保留草稿及不可用项，完整性和 generation 检查先于更新。
- [PR 分支落后于 main] → 实施时先整合，不覆盖已发布删除/工具弹窗/观测；所有验证针对最终提交重跑。
- [不兼容旧邮箱格式] → 用户明确不需要迁移；非法条目报错而不猜测宽权限、不删除原文件。此任务不访问或修改任何真实配置。

## Migration Plan

不安排旧邮箱迁移。后续获准实施后，先把本 change 与最新 main 整合，执行未完成任务、同步两份主规格及文档，运行定向和全量验证。新 UI 通过合成账户的浅/深色、窄窗口和键盘验收，真实邮箱测试需单独具备可用账户授权，不把合成测试当作实机验收。PR、合并、归档和发版需按后续授权，仍不本地打包。
