## Context

参见 proposal.md。现有 schemaVersion=1 严格 JSON 解析和独立的运行时 MailAccount 均只支持白名单，目录工具过滤并截断为 32 条。底层 IMAP LIST 已使用 `*` 递归匹配并保留完整名称，限制 256 项；权限 revision 已绑定引用、游标和调用前后复核。

## Goals / Non-Goals

**Goals:** 明确区分范围语义，让新账户便捷选择全部，保证旧范围不扩大，保留动态目录与权限撤回；移除用户指定的三个邮箱勾选项，以清晰操作确认完成系统安全存储与启用。

**Non-Goals:** 不改变邮箱认证、协议只读、正文读取、模型发送、历史覆盖或全文留存边界；不增加自动读取、服务商设置修改、外部 MCP 服务或文件夹选择器；不触达真实邮箱。

## Decisions

1. 增加 `folderScope: all|selected`。缺省只在读取旧配置时规范化为 `selected`，新表单显式写 `all`。不使用 `*` 哨兵或空列表推断权限，避免迁移误授权。保持 schemaVersion=1 的可选增量字段，旧版本严格解析会拒绝未知字段，不能默默扩大范围。
2. `allowedFolders` 继续表示指定模式白名单并保留切换前的内容，全部模式允许为空；指定模式仍要求 1–32 个有效且不重复的完整名称。新表单保留 INBOX 作为切回指定模式的起点，运行时依据模式判定而不凭列表是否为空推测。
3. 所有配置复制、凭据更新、断开、导出/导入和运行时映射携带模式。模式及列表均属于现有 revision 权限快照，收窄立即影响运行检查并使旧引用失效。账户工具向模型返回模式以免 `allowedFolders` 造成歧义。
4. 全部模式列举实际可读目录，保留嵌套完整路径并支持新建目录；继续沿用底层 256 目录及协议输入/时长预算，服务层也验证目录响应并安全拒绝超额，不再静默取 32 条。指定模式保持精确匹配。搜索仍每次指定单个目录，不为“全部”隐式循环搜索整个邮箱。
5. UI 增加范围选择与随模式更新的说明，全部时禁用白名单输入但保留草稿。保留正文选择，移除邮箱的 disclosureVersion、enabled、persist 三个勾选项，不用同类开关替代。外部 MCP 保持既有控件。所有外部名称继续使用安全文本渲染。
6. 保留先保存公共元数据的现有流程，再提供“加密保存并启用邮箱”操作。确认内容包含账户、完整范围/未来目录、正文是否允许、当前模型目标、聊天留存、系统持久化及断开边界。取消不发送启用请求；确认后向受管桌面专用接口提交预期 revision、披露版本和已展示的模型目标。服务端拒绝缺失确认、目标变化或过期配置。保存/启用不发出 IMAP 网络请求，不将启用成功描述成已测试连通。
7. 专用启用操作只使用 Windows Credential Manager。新授权码先写入且回读核验系统库，再原子提交凭据引用、enabled=true 和 disclosureVersion=1，最后清理旧引用。确认尚未提交的失败保留此前有效状态并处理孤立项；原子替换后若清理或关闭抛错，先重读持久配置确认是否已提交，不能把异常当成未执行而盲删新凭据。能确认已提交时按实际成功状态返回，无法判断时保留可能被引用的凭据并明确报告结果不确定、不自动重试，之后核对真实引用再安全清理。无新授权码时仅允许复用当前账户匹配且可读取的持久凭据。不可用平台、无可复用凭据或保险库失败不能回退 session/明文。底层会话存储保留用于旧账户读取及外部 MCP，但邮箱新凭据写入不能借旧入口绕过持久化要求。
8. 元数据保存不允许直接伪造新 enabled/disclosure 状态。邮箱服务商、地址、目录范围或正文权限变化后先保存为未启用、披露待确认；仅显示名等无关编辑不强制停用。新建/导入仍关闭。断开继续先持久撤权再清理凭据，保留可重新启用路径；仅会话旧凭据需用户重新输入后才能使用新持久化启用流程。实际会话模型目标授权保持独立，首次发送或目标变化仍确认。

## Risks / Trade-offs

- [用户将范围误解为自动全量读取] → 设置和文档说明仍按需读取，历史受服务商限制，正文、模型发送独立授权。
- [旧配置被默认值扩大] → 在配置边界和 UI 都按缺省 selected 处理并测试保存/导入往返；只有新建表单明确默认 all。
- [目录数量或名称恶意超限] → 保留并测试 256 项、256 字符、控制字符、网络/时间预算，超额明确失败。
- [回退到旧版本无法解析新字段] → 不自动重写用户配置；文档提示备份与旧版不支持新范围字段，不能静默降级成更宽权限。
- [移除授权勾选项后产生隐式授权] → 将授权集中到明确启用确认，后端复核 revision/模型目标，权限变更先停用；普通元数据保存不能启用。
- [系统库不可用或误称加密] → 使用现有真实 CredWriteW/CredReadW 及回读核验，非 Windows 明确不可用；不自制加密、不在配置旁保存解密密钥、不回退会话或明文。系统库不隔离同一登录用户下的恶意程序。

## Migration Plan

读取旧文件不触发写入或联网，旧账户规范化为指定模式；旧启用/披露/存储状态继续可读，不自动迁移会话授权码。用户主动保存后序列化显式范围，权限改变则停用并等待新操作确认。导入仍禁用所有账户和授权。本地测试与规范同步完成后创建功能 PR，并等待最新提交的远端 CI，尤其是 Windows 全量验证。Windows 桌面视觉及真实 QQ/163 尚未验证，保留在验证报告中。合并后才进入独立版本变更及远端发版流程，不自行合并、不本地打包或归档。
