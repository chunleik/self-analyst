## Why

邮箱当前需要手填允许读取的文件夹，默认只有 INBOX，用户难以知道自定义和嵌套目录的准确 IMAP 名称。用户要求默认全部读取范围、可自行调整，并在配置完成后自动加载目录供选择；移除“后续轮次启用”和“保存到本机系统凭据库”选项，凭据必须安全持久保存。

本次继续现有 `default-all-mail-folders`，不建立重复 change。2026-11-14 核查时 PR #154 尚未合并，beta.17/main 不包含它；原分支已有默认全部与安全启用实现，但没有目录选择器。用户明确“目前没人使用，不用考虑旧邮箱”，本次统一新配置设计，不实施旧邮箱兼容、迁移或自动重建。以下是修订提案，不是已发布能力。

## What Changes

- 邮箱配置显式使用 `folderScope: all|selected`；新建默认全部，覆盖当前和以后新增的服务商可见可读目录，包括嵌套目录。指定模式通过完整目录名精确匹配。
- 保存连接配置且有可用凭据后自动加载一次目录；新账户可先用本次输入的授权码连接并加载，之后选择范围。目录发现不等于启用、正文读取或模型发送授权。
- 用可搜索、有层级和完整路径的复选列表取代手填白名单。提供刷新、选中当前全部和清空；取消全部模式中的单项后转为指定模式，并明确未来新增目录不自动加入。
- 指定模式支持最多 256 个目录，与发现预算一致；超额明确失败，不把截断清单称为全部。保留暂时不可见的已选目录并标识状态。
- 去掉邮箱的“后续轮次启用”“保存到本机系统凭据库”及原处理授权勾选项，以带完整告知的“加密保存并启用邮箱”确认承载授权；保留独立正文许可及断开/删除入口。确认成功后默认启用，不要求额外开关。
- 新邮箱凭据只使用当前用户系统安全存储，写入后回读核验；失败不降级明文、配置旁自存密钥或仅会话。目录发现可使用仅供本次连接的临时授权码，不持久保存。
- 不考虑历史邮箱格式兼容或会话凭据迁移，缺少明确范围的邮箱条目拒绝为无效，不猜测权限，也不静默清空配置；不改变外部 MCP 的配置及会话凭据行为。
- 新增管理端目录发现及前端异步状态测试，更新两份增量规格、相关文档和验收清单。当前只写提案，不实施、提交、推送、合并或发版。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `mail-integration`: 明确全部/指定范围、管理端完整目录发现、凭据与启用边界、目录预算和撤权复核。
- `user-configuration`: 统一新邮箱默认值，可视化目录选择、自动加载与失败状态，并以明确启用操作取代邮箱开关。

## Impact

影响邮箱配置解析和运行时映射、受管桌面管理接口、IMAP 目录发现、连接设置 UI、中英文文案、Java/Node/协议测试及邮箱用户文档。不引入依赖，不扩大 Agent 的管理权限，不做后台同步。实施前须整合最新 main，保留 beta.17 的连接删除、工具弹窗和开发者观测功能；PR #154 原有测试结论不能覆盖此次改动。主规格同步、代码实施及 PR 交付均留待后续授权。
