## Why

目前邮箱仅接受逐项填写的文件夹白名单，新账户默认只有 INBOX，用户无法直接授权全部目录。增加明确的全部文件夹模式，以满足默认读取所有可用文件夹的需求，同时避免升级后扩大已有账户的授权。

用户进一步要求移除邮箱表单的处理授权、后续轮次启用和本机凭据库三个勾选项，并将凭据加密保存。用明确的保存/启用操作承载必要知情确认，避免隐藏开关造成静默启用或外发。

## What Changes

- 新建邮箱账户默认选择“全部文件夹”，但仍默认关闭账户、正文权限与模型处理同意。
- 用明确的 `folderScope` 区分 `all` 与 `selected`，不把 `*`、空白名单或旧配置解释为全部。
- 缺少新字段的旧账户保持既有精确白名单；现有账户只能通过用户主动保存切换到全部模式。
- 全部模式按调用时服务商可见目录工作，支持嵌套目录和之后新增的目录；不自动下载、同步或解除协议预算。
- 界面披露当前/未来目录范围、独立正文权限、模型接收方与会话留存；补充迁移、撤权、目录和 UI 回归验证及文档。
- 邮箱不再显示处理授权、启用或凭据持久化三个勾选项，改为带完整披露与明确确认的“加密保存并启用邮箱”操作，保留独立正文选择和断开撤权。
- 新邮箱凭据只通过系统安全存储持久化，Windows 复用当前用户 Credential Manager；不可用或写入失败明确报错，不降级明文或仅会话。不自动迁移既有会话凭据。
- 邮箱权限范围、正文或目标变化先停用并要求重新确认启用；会话级实际模型接收目标确认继续独立执行。外部 MCP 的现有选项和默认会话凭据规则不变。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `mail-integration`: 明确文件夹范围模式、新账户默认、动态目录、权限复核和安全持久化启用边界。
- `user-configuration`: 兼容旧配置，新增文件夹范围设置，并以显式启用确认取代三个邮箱勾选项。

## Impact

影响邮箱配置的 JSON 解析、运行时账户映射和文件夹授权、凭据与启用事务、受管桌面管理接口、Agent 账户/目录工具结果、连接设置 UI、相关 Java/Node 测试及邮箱文档。不引入依赖，不改变实际模型接收方确认、独立正文权限、远端只读和数据保留边界。本地实施完成后，按后续授权提交功能分支、推送并创建 PR，等待最新提交的必需远端检查。本次不自行合并、不归档；只有实际合并后才进入独立版本变更及远端发版流程，不在本地打包。
