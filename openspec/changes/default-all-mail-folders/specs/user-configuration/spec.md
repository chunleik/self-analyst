## ADDED Requirements

### Requirement: SPEC-CFG-MAIL-FOLDERS-001 统一默认与显式范围
新建邮箱表单 SHALL 固定使用全部文件夹，包含未来新增目录；正文默认关闭，账户明确确认前保持未启用。新 UI MUST 只接受、保存和启用 `folderScope: all`，不自动迁移或隐藏旧指定范围。不支持的范围 MUST 明确拒绝，不得显示全部但实际保存指定名单。底层独立配置校验与导入安全不变。

#### Scenario: 创建新账户
- **WHEN** 用户添加邮箱
- **THEN** 使用动态全部范围，无目录选择控件；正文关闭且未启用

#### Scenario: 不支持的旧范围
- **WHEN** 新 UI 加载指定或缺失范围的邮箱配置
- **THEN** 明确拒绝该配置，不迁移为全部、不修改原配置

### Requirement: SPEC-CFG-MAIL-PICKER-001 固定全部范围的简洁设置
邮箱配置页 MUST NOT 展示范围选择、目录搜索、加载、刷新、全选、清空和复选列表；SHALL 以简短说明告知读取全部文件夹，包括以后新增目录。打开、保存或启用配置 MUST NOT 自动发起目录发现。按需邮件工具读取及独立连接测试保持原权限和安全预算。

#### Scenario: 配置邮箱
- **WHEN** 用户打开邮箱设置、保存或确认启用
- **THEN** 固定全部范围，无目录选择器，也不因这些操作自动列举目录；正文与模型授权仍独立

### Requirement: SPEC-CFG-MAIL-ACTIVATION-001 明确操作替代三个邮箱开关
邮箱表单 MUST NOT 显示“读取范围及模型处理授权”“后续轮次启用”“保存到本机系统凭据库”三个勾选项或同类开关。系统 SHALL 用明确的保存/启用按钮和一次操作确认承载知情授权，确认内容包含账户、当前/未来目录范围、正文许可、实际配置的模型目标、系统安全持久化和会话留存。普通保存 SHALL 只修改元数据，不能借提交隐藏启用/披露字段绕过确认；只有专用确认操作可赋予新启用状态。正文选择 SHALL 保留，外部 MCP 的控件和默认存储规则 SHALL 不受此邮箱 UI 改动影响。

#### Scenario: 保存元数据与确认启用
- **WHEN** 用户保存邮箱元数据后输入授权码并点击加密保存启用
- **THEN** 显示完整确认；取消不提交秘密或启用请求，确认后系统安全持久化成功才启用；成功后默认启用而无需额外开关，结果不冒称已完成服务商连接测试；不自动触发目录发现

#### Scenario: 复用匹配的系统凭据
- **WHEN** 用户重新启用未改变账户目标的邮箱且没有输入新授权码
- **THEN** 只允许复用匹配且可读取的已持久化安全凭据；没有匹配凭据时要求输入，不降级到仅会话存储

#### Scenario: 重复点击、保存失败与关闭
- **WHEN** 用户重复点击、取消确认、关闭表单或请求返回错误/迟到结果
- **THEN** 不重复保存凭据或启用，失败不覆盖用户草稿且不声称已保存，晚到结果不能改写另一账户或重开已关闭界面

#### Scenario: 撤销权限仍可见
- **WHEN** 用户查看已启用邮箱的设置
- **THEN** 保留清晰的启用状态及断开操作，断开停止读取并清理凭据，同时说明不会撤回已发送内容或删除已存聊天
