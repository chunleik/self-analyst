# Design

## Context

动机见 proposal.md。核对基线 `773536b`：增强消息面由 `deep-chat-adapter.js` 配置 Deep Chat 自有输入区，fallback 使用 `index.html` 的 textarea；后者已有 72px 最小高度的样式测试。`chat-images.js` 当前在两者之外独立渲染原生 file input、常驻限制、缩略图及第二个发送图片按钮；已有选择、粘贴、图片预算和会话草稿隔离。没有发现拖放事件绑定。

发送路径依赖请求来源：增强路径通过适配器传入流事件和取消信号，`sendChatTabMessage` 先上传图片与追加权威 user/pending，再执行模型。不能只把增强输入框移除、调用 fallback 发送就宣称保持流式能力。当前截图说明的是增强输入体验，不能把 fallback 的多行样式当成已解决问题。

## Goals / Non-Goals

**Goals:** 两种消息面表现一致、图文输入集中、维持原轮次身份与失败恢复，防止重绘和切换会话造成草稿丢失。

**Non-Goals:** 不更换 Deep Chat、不升级依赖、不新增通用文件上传、录音、模型选择、草稿跨重启持久化、后台截图或采集；不改变后端图片端点、限额、权限、预算和重试协议。不调整 legacy drawer 的交互。

## Decisions

### 1. 共享外置输入区，增强组件只显示消息

实施核对后经用户确认调整：vendored Deep Chat 有 `inputAreaStyle` 可隐藏原生输入区域，但附件与文本原本处在不同 DOM 所有权下。改用一个外置原生 textarea composer，增强和 fallback 仅负责消息展示，不再把附件插入 shadow DOM。这样只有一个草稿、主动作和事件绑定，避免组件反应式重建造成输入丢失。保留 adapter 的消息渲染、canonical 更新与降级机制。

外置 composer 调用现有 `sendChatTabMessage` 并显式传入流式选项、signal、onExecutionStart 和 onDelta；增量仅更新原 session 的 pending，结束后仍由现有服务端 canonical 路径替换。停止使用绑定原 session/user 的取消端点和本地 AbortController，不把默认 fallback 的非流式调用当成等价替代。预填与修复会话草稿读写改为同一 textarea。

备选双适配器方案会使图文操作依赖私有 shadow DOM 布局，并保留两套键盘/状态处理，本次经确认不采用。消息展示仍保持增强/fallback 两条通路，不更换组件。

### 2. 弹性布局而非视口悬浮覆盖

主会话区域使用有界 flex/grid；消息区可收缩并独立滚动，输入容器不随消息滚动，也不使用覆盖消息的 position: fixed。文本初始目标 72px、上限目标 200px，在支持的短窗口下结合可用高度限制，附件区独立有界；调整时需保留可阅读的消息空间。

输入、粘贴、预填草稿、切换会话、清空、宽度变化时重新计算高度；不要在每次流 delta 都重建 textarea/contenteditable。保持选区、光标、IME composition 与焦点。颜色、边框和阴影使用现有主题变量，中文英文长提示均可换行。

### 3. 操作状态按真实阶段呈现

- 空草稿：发送禁用；有效纯图片视为可发送内容。
- 校验/上传/追加：显示“正在准备…”并禁用重复发送和附件修改；不宣称已开始模型生成，不提供无法真正取消上传的假停止按钮。
- 模型生成：主动作显示“停止生成”，关联正在执行的 session/turn，而非读取后来选中的会话；复用取消请求及本地 AbortController。
- 未配置模型、正文未加载或 reconciliation-required：给出原因并禁用新发送，不影响已有流的停止。
- 持久化前失败：保留图文草稿；持久化后失败：使用原 pending 重试，不把已发图片重新塞回草稿。

主按钮和 Enter 共用一次性发送守卫；不能仅依靠 CSS disabled。保持输入法组合保护，覆盖 `isComposing` 及组合结束附近 Enter 事件的回归测试。

### 4. 附件复用一条本地校验通路

添加按钮打开隐藏的原生文件选择器；粘贴与输入区 drop 传入同一个图片加入函数，不自动上传或发送。保留 4 张、每张 5 MiB、总计 20 MiB、每张 2000 万像素和 PNG/JPEG 边界。只接受浏览器提供的 File，不将路径字符串、目录或远程 URL 转换成图片。

本地预览完成前冻结发送；用会话键及草稿 generation 校验异步回调，清理或移除时撤销 object URL，不把旧结果加入新会话。批量输入可保留已加入的合法图片，但必须说明实际数量与拒绝项，不能因一个非法文件清空既有内容。取消选择不改变草稿。

dragover/drop 仅处理输入容器内的文件拖放，阻止浏览器导航；纯文本编辑和其他页面拖放不受影响。Windows Tauri 主窗口显式调用 `disable_drag_drop_handler()`，关闭原生文件拖放拦截，交由 WebView 的 DOM File 通路；不增加文件系统权限、路径读取命令或新后端接口。其他窗口保持不变。Windows OS 文件拖放仍需实机验收，浏览器成功不等于 Windows 验收通过。

### 5. 就近反馈与键盘可用性

“＋”和停止图标都提供当前语言的 aria-label/title；隐藏 file input 不保留额外可见原生控件。限制说明通过添加入口旁的帮助或展开提示访问，错误在容器内显示，重要状态通过 aria-live 呈现但不逐 token 播报。缩略图移除含可辨识的图片序号，取消选择返回合理焦点，删除当前焦点项后转至相邻项或添加按钮。文案全部进入两套 locale。

## Risks / Trade-offs

- 外置输入区切换可能改变流处理 → 显式复用 canonical 发送协议，补流式、停止、fallback、连续发送测试。
- 高度自适应挤占消息区域 → 最大高度和附件预览有界，验证最小支持窗口及缩放。
- 切换会话与图片解码竞态 → 会话键和 generation 双校验，回收废弃 object URL。
- 关闭主窗口原生拖放处理后需确认 WebView 文件行为 → 真实 Tauri 验证；阻塞如实报告，不放宽文件读取权限。
- Node DOM 替身无法证明 IME/布局可用 → 补实际中文输入法与浅深色截图，不以字符串样式断言代替人工验收。

## Migration Plan

无需数据迁移。已获批准后按任务实施、测试与同步两个主规格；提交、推送及创建 PR 等待用户后续指示，不归档。回滚撤销前端和主窗口拖放配置变更，已持久消息和图片不改写。
