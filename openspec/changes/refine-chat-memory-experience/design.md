## Context

动机见 proposal.md。当前 MemoryExtractionService 在允许提炼的 assistant sent 后调用模型；入库分级主要检查 sensitive、confidence 和 approvalPolicy，未核验用户原文来源与长期价值。主规格已有“不能只依赖模型分级”的要求，实施需补足这一差距。当前 memorySnapshot 仅选择 active/pending，LongTermMemoryService 的正文规范化去重无法覆盖跨语言同义表达。

前端 chat.js 在会话上下文区域直接渲染策略、输入框和记忆列表。计数来自全局 pending；新的入口须明确使用同一口径。语言由后端 Lang 和 Messages 提供，遵守现有配置生效和历史数据保留契约。工作区同时有文档生成变更，实施须增量修改共享会话文件。

## Goals / Non-Goals

**Goals:** 在保持异步提炼和现有管理接口的基础上，提供不打断聊天的审核入口、可验证的候选来源和一致的生成语言。

**Non-Goals:** 不改变采集边界，不读取原始事件流来构建用户画像，不引入向量数据库、翻译服务或独立语言配置，不批量删除、翻译已有记忆；不要求每一条低风险明确偏好都人工批准。

## Decisions

### 1. 显示状态与记忆数据分开

在 chat.js 维护当前会话面板展开状态，页面初始化和会话切换归为关闭；每个会话的手动输入及按记忆 ID 保存的编辑草稿独立保留。入口设置 aria-expanded/aria-controls，关闭后恢复入口焦点。CSS 在关闭状态移除记忆专属列宽；本轮业务上下文独立保留，窄窗口允许面板重排。

复用现有记忆 API 获取全局 pending 计数，展开后提供相同集合及来源会话信息。异步刷新沿用当前会话和请求代次保护；后台新增只更新数据，不重置焦点或编辑控件。折叠详细 evidence，保留来源摘要和本地化用途提示。相较弹窗逐条确认，这能让用户自行决定何时审核。

### 2. 先判定资格，再分级入库

沿用 sent 后一次异步提炼调度，不另加同步聊天分类请求。此处“活动查询不生成记忆”约束的是入库结果，不承诺所有自然语言活动查询都零模型调用。双语提炼指令要求纯活动查询返回空候选；混合请求仅提取用户明确陈述的长期内容，保留 remember/forget 和 off 的既有语义。

扩展仅内部使用的 Candidate 结构，提供候选来源类别、用户消息 ID、原文片段和长期价值类别；服务端验证来源角色、ID、片段包含关系、允许的长期类别，缺失字段及仅 assistant 来源一律丢弃。原文片段必须来自当前有界用户消息，不能引用全文库或工具活动总结。模型将纯疑问或活动片段误标为长期陈述的情况纳入中英文回归用例；仍无法判定长期价值的候选丢弃，不能以 pending 兜底。

有效候选再走敏感过滤、去重及 smart/confirm_all 分级。来源校验不能替代语义判断，提示词与确定性校验共同收紧入口；仅改提示词无法验证模型伪造的来源，仅用关键词又会漏掉混合表达，因此保留结构化模型判断并验证证据。

### 3. 同义去重受预算约束

保留现有确定性正文去重。在有界记忆摘要中加入少量 rejected/disabled 抑制项，与 active/pending 共用总长度上限；明确标记用途仅为去重，不得当作真实个人事实进入对话。模型可返回 duplicateOf 指向摘要中出现的 ID；服务端校验 ID 在本次摘要中、类型及状态兼容，复用已有记忆，不接受模型任意更新其它条目。不确定同义时不修改旧内容，物理删除不留下抑制项。

摘要优先覆盖近期、与本轮相关的条目，同时为拒绝项留出配额；同义抑制承诺限于本次有界上下文，完整存储继续做规范化正文去重。选择有界模型去重以覆盖中英文表述，不引入 embedding 或全库语义检索。

### 4. 生成语言与历史原文区分

memory.prompt 的 zh/en 指令显式要求 content 和生成 evidence 说明使用有效语言，原始引用保持原样；前端用途、状态和按钮来自 locales 消息目录。用固定响应测试生成指令和传递的 Lang，并以中英文实际输出验收补充，不把单纯字符集检测当成语言正确性的证明。

沿用既有语言生效时机。切换语言后，新候选使用新语言，历史候选仍显示保存时正文；这项兼容边界需写入用户文档。不得因刷新或切换面板发起翻译调用，不将显示语言变更写回已批准事实。

## Risks / Trade-offs

- [严格资格校验漏掉潜在有用信息] → 保留手动添加，允许用户明确陈述长期背景或提出记住请求；不凭一次活动猜测偏好。
- [模型错误识别长期价值或同义关系] → 核验用户证据、保守丢弃、限制 duplicateOf 范围、不覆盖旧内容，添加反例测试。
- [有界摘要未包含旧拒绝项] → 规范化正文去重仍覆盖存储；不承诺无限历史跨语言去重。
- [旧候选语言不同] → 明确只影响后续生成，保留手动编辑途径。
- [轮询重绘丢失焦点或草稿] → 增量更新计数、按 ID 保留草稿、覆盖乱序和编辑中刷新用例。
- [共享文件与文档生成功能冲突] → 实施前重新读取最新变更，回归文档附件与增强/fallback 消息面。

## Migration Plan

本次仅增加规划文件。实施无需迁移 memory.json 或更换 API 状态值；候选验证字段作为内部模型响应协议，不要求旧存储回填。上线前运行针对性 Java/Node 测试、页面中英文视觉检查及 OpenSpec 严格校验，然后同步主规格和用户文档、归档 change。交付遵循功能分支和 PR 必需检查流程，未获合并授权不合并。

回滚仅撤回本次实现，不清理或改写用户记忆；重新运行中的旧模型响应若不符合新候选结构应安全丢弃，不影响聊天。
